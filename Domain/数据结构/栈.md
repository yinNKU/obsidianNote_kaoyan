## 一句话定位
栈是仅允许在一端（栈顶）进行插入和删除操作的线性表，操作特性为后进先出（LIFO）；顺序栈通过数组与栈顶指针实现，链栈通过单链表表头操作实现，共享栈利用两个栈底相向延伸提高空间利用率。

## 它解决什么问题？
解决需要"后进先出"顺序的数据管理问题——如函数调用、递归、括号匹配、表达式求值等场景。栈是操作受限的线性表，限制本身使其行为可预测、实现简单高效。

## 主要概念
栈，栈顶，栈底，空栈，后进先出（LIFO），顺序栈，栈顶指针，共享栈，链栈，卡特兰数

> **缩写对照**
> - **LIFO**：Last In First Out，后进先出
> - **SqStack**：Sequential Stack，顺序栈类型

## 概念解析
#### 栈的定义与特点
- **栈（Stack）**：仅允许在一端进行插入和删除操作的线性表。
	- 栈顶（Top）：允许插入和删除的一端。
	- 栈底（Bottom）：固定不变、不允许操作的另一端。
	- 空栈：不含任何元素的栈。
- **操作特性**：后进先出（LIFO），入栈和出栈只能在栈顶进行。若 n 个元素按顺序入栈，出栈顺序为逆序。
- **数学性质**：n 个不同元素按固定次序入栈时，可能的出栈序列总数为 $\frac{1}{n+1}C_{2n}^n$（卡特兰数）。

#### 栈的基本操作
- **InitStack(&S)**：初始化空栈 S。
- **StackEmpty(S)**：判栈空，空则返回 true。
- **Push(&S, x)**：入栈，x 成为新栈顶元素（栈未满时）。
- **Pop(&S, &x)**：出栈，弹出栈顶元素并通过 x 返回（栈非空时）。
- **GetTop(S, &x)**：读取栈顶元素但不出栈，通过 x 返回。
- **DestroyStack(&S)**：销毁栈并释放存储空间。
- 解答算法题时，若未特殊限制，可直接使用上述基本操作函数。

#### 顺序栈的实现
```c
#define MaxSize 50
typedef struct {
    ElemType data[MaxSize];
    int top;          // 栈顶指针
} SqStack;
```
- **存储方式**：利用一组地址连续的存储单元存放从栈底到栈顶的数据元素，附设整型指针 top 指示当前栈顶元素位置。
- **初始化**：`S.top = -1`（指向栈顶元素本身）。
- **栈空条件**：`S.top == -1`。
- **栈满条件**：`S.top == MaxSize - 1`。
- **栈长**：`S.top + 1`。
- **入栈操作**：栈未满时，栈顶指针先加 1，再存入元素。`S.data[++S.top] = x`。
- **出栈操作**：栈非空时，先取出栈顶元素，栈顶指针再减 1。`x = S.data[S.top--]`。
- **读栈顶**：`x = S.data[S.top]`，不改变栈状态。
- **另一种初始化方式**：`S.top = 0`（指向栈顶元素下一个位置），此时入栈 `S.data[S.top++] = x`，出栈 `x = S.data[--S.top]`，判空 `S.top == 0`，判满 `S.top == MaxSize`。做题时务必根据题目设定灵活应对。
- 栈上溢：对最大使用空间估计不足时发生，应及时报错处理。

#### 顺序栈基本操作代码
- **初始化**：
	```c
	void InitStack(SqStack &S) {
	    S.top = -1;
	}
	```
- **判栈空**：
	```c
	bool StackEmpty(SqStack S) {
	    return S.top == -1;
	}
	```
- **入栈**：
	```c
	bool Push(SqStack &S, ElemType x) {
	    if (S.top == MaxSize - 1) return false;
	    S.data[++S.top] = x;
	    return true;
	}
	```
- **出栈**：
	```c
	bool Pop(SqStack &S, ElemType &x) {
	    if (S.top == -1) return false;
	    x = S.data[S.top--];
	    return true;
	}
	```
- **读栈顶元素**：
	```c
	bool GetTop(SqStack S, ElemType &x) {
	    if (S.top == -1) return false;
	    x = S.data[S.top];
	    return true;
	}
	```
- 以上代码基于 top 初始化为 -1。入栈指针先加再赋值，出栈先取值再减。top 标识栈中有效元素的边界。

#### 共享栈
- **共享栈**：两个顺序栈共享同一段一维数组空间，栈底分别置于数组两端（0 号栈底在低地址端，1 号栈底在高地址端），栈顶向中间延伸。
	- top0 初始为 -1（0 号栈空），top1 初始为 MaxSize（1 号栈空）。
	- 栈满条件：`top1 - top0 == 1`（两栈顶相邻）。
	- 0 号栈入栈：top0 先加 1 再赋值；1 号栈入栈：top1 先减 1 再赋值。出栈顺序相反。
- **优点**：更高效利用存储空间，两栈空间动态调节，仅当整个数组占满时才发生溢出。存取数据时间复杂度仍为 $O(1)$。

#### 链栈
```c
typedef struct LinkNode {
    ElemType data;
    struct LinkNode *next;
} LiStack;  // 链栈类型定义
```
- **链栈**：采用链式存储的栈，通常用单链表实现，所有操作在链表表头进行。便于动态分配存储空间，不存在栈满溢出问题，多栈共存场景更灵活。
- **无头结点约定**：栈顶指针 Lhead 直接指向栈顶元素。入栈和出栈均在表头进行（类比单链表头插法和头删法）。对于带头结点的链栈，初始化、判空及操作细节有所不同，应根据实际需求调整。
- **入栈**：创建新结点插入表头（头插法），$O(1)$。
- **出栈**：删除表头结点并释放，$O(1)$。

#### 栈在括号匹配中的应用
- **问题**：检查表达式中的圆括号和方括号是否合法配对，嵌套顺序任意。
- **算法思想**：
	1. 初始化空栈，顺序扫描括号序列。
	2. 遇到**左括号**：压入栈中，表示新增一个待匹配期待（优先级最高）。
	3. 遇到**右括号**：若栈非空且栈顶左括号与当前右括号**匹配**，则弹出栈顶；否则序列非法。
	4. 扫描结束后，**栈为空**则合法，否则存在未匹配左括号，序列非法。
- **匹配判定**：当前右括号与栈顶左括号同类（`[` 对 `]`，`(` 对 `)`）即为匹配。
- 时间复杂度 $O(n)$，空间复杂度 $O(n)$。

#### 栈在表达式求值中的应用

**算术表达式**
- **中缀表达式**：运算符在操作数之间（如 $3+4$），需括号明确运算次序，符合人类习惯但不便于计算机直接求值。
- **后缀表达式（逆波兰式）**：运算符在操作数之后（如 $3\;4\;+$），无需括号，运算次序隐含于结构，适合计算机求值。
- **前缀表达式**：运算符在操作数之前（如 $+\;3\;4$）。
- **表达式树**：中缀表达式对应的表达式树经**后序遍历**所得序列即为后缀表达式。（2025考点）

**中缀转后缀（手算方法）**
1. 按运算优先级对整个表达式逐层加括号。
2. 将每个运算符移到其所在括号的右括号之后。
3. 删除所有括号，即得后缀表达式。

**中缀转后缀（机算方法，运算符栈）**
- 原理是：运算符必须等到"它后面不会再出现比它优先级更高、需要先计算的运算符"，才能进入后缀表达式。栈里存的是"现在还不能输出"的运算符。其实是比较优先级，操作数优先级最低因此直接放入后缀，遇到运算符不知道后面会不会有更优先的运算符因此放进去等待，如果运算符低于栈顶优先级说明栈顶之后没有遇到比他更优先的因此栈顶弹出，直到这个运算符比栈顶高。

| 扫描项 | 处理方式 |
| --- | --- |
| 操作数 | 直接加入后缀表达式 |
| `(` | 直接入栈 |
| `)` | 不断弹出栈顶运算符加入后缀表达式，直到遇到 `(`，将其弹出并丢弃 |
| 运算符 | 优先级高于栈顶或栈顶为 `(` 则入栈；否则依次弹出栈顶直到满足条件再入栈 |

- 扫描结束后，将栈中剩余运算符依次弹出加入后缀表达式。
- 栈中暂存的是**尚未确定输出时机**的运算符。栈深度的最大值即所需栈容量。

**后缀表达式求值**
- 从左至右扫描后缀表达式：
	- **操作数**：压入栈中。
	- **操作符**：弹出两个操作数（先出的是**右操作数** Y，后出的是**左操作数** X），计算 $X <op> Y$，结果压回栈中。
- 全部处理完毕，栈顶元素即为最终结果。
- **栈深度分析（2009、2012、2025考点）**：栈中元素的最大个数即为栈所需的最大容量。通过手工模拟转换或求值过程可有效求解。

#### 栈在递归中的应用
- **递归**：函数、过程或数据结构在其定义中直接或间接引用自身。
- **两个条件**：
	- **递归表达式（递归体）**：描述如何将问题分解为规模更小的同类子问题。
	- **边界条件（递归出口）**：确保递归在有限步内终止。
- **递归工作栈**：系统为每层调用的返回地址、局部变量、形参分配空间并保存在递归工作栈中。递归深度过大会导致**栈溢出**。
- **递归主要缺陷**：存在大量重复计算，效率不高。
- **递归转非递归**：任何递归算法均可转换为非递归算法，通常需借助显式栈模拟递归调用过程。
