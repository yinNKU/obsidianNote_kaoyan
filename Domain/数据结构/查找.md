## 一句话定位
查找是在数据集合中寻找满足条件的数据元素的过程，核心指标是平均查找长度（ASL）。

## 它解决什么问题？
从大量数据中快速定位目标元素，衡量标准是比较次数（ASL）。

## 主要概念
查找表、关键字、ASL、静态/动态查找、顺序/折半/分块/树形/散列查找

> **缩写对照**
> - **ASL**：Average Search Length，平均查找长度
> - **BST**：Binary Search Tree，二叉排序树
> - **AVL**：Adelson-Velsky and Landis tree，平衡二叉树

## 概念解析

#### 基本概念
- **查找**：在数据集合中寻找满足条件的数据元素的过程。结果分查找成功和查找失败。
- **查找表**：用于查找的数据集合，常见操作有查询和插入/删除。
- **静态查找表**：仅涉及查询，无需动态修改；反之称动态查找表。
- **关键字**：数据元素中唯一标识该元素的某个数据项的值。
- **ASL**：所有查找操作中关键字比较次数的加权平均值，$ASL = \sum_{i=1}^n P_i C_i$，是衡量查找算法效率的核心指标。[^1]

#### 顺序查找
- **定义**：从线性表一端开始，逐个检查元素关键字是否满足给定条件。
	- 适用于顺序表和链表，不要求关键字有序。
	- 可设 **哨兵**（$ST.elem[0] = key$）避免循环中判断下标越界。
- **代码实现**：
	```c
	typedef struct {
	    ElemType *elem;   // 动态数组基址
	    int TableLen;     // 表的长度
	} SSTable;

	int Search_Seq(SSTable ST, ElemType key) {
	    ST.elem[0] = key;                 // 哨兵
	    for (int i = ST.TableLen; ST.elem[i] != key; --i);
	    return i;                         // 成功返回下标，失败返回0
	}
	```
- **ASL（成功，等概率）**：$(n+1)/2$
- **ASL（失败）**：$n+1$（无序表）；有序表可提前终止，失败 ASL 约 $n/2 + n/(n+1)$。
- **优化**：若已知查找概率，按概率由大到小排列元素。

#### 折半查找
- **定义**：每次与表中间位置元素比较，缩小一半查找范围，仅适用于关键字有序的顺序表。
	- 时间复杂度 $O(\log_2 n)$。
- **判定树**：描述折半查找过程的二叉树。圆形结点表示表中存在的记录，方形结点为失败结点（共 $n+1$ 个）。
	- 性质：任一结点值 > 左子树所有结点值，< 右子树所有结点值。
	- $n$ 个圆形非叶结点 + $n+1$ 个方形叶结点，是一棵平衡二叉树。
	- 树高 $h = \lceil \log_2(n+1) \rceil$，比较次数最多不超过树高。
	- 查找成功长度 = 根到目的结点的路径上的结点数；查找失败长度 = 根到失败结点父结点的路径上的结点数。
	- 不适用于链式存储结构（需随机访问）。
- **代码实现**：
	```c
	int Binary_Search(SSTable L, ElemType key) {
	    int low = 0, high = L.TableLen - 1, mid;
	    while (low <= high) {
	        mid = (low + high) / 2;         // 取中间位置
	        if (L.elem[mid] == key)
	            return mid;                 // 查找成功
	        else if (L.elem[mid] > key)
	            high = mid - 1;             // 前半部分
	        else
	            low = mid + 1;              // 后半部分
	    }
	    return -1;                          // 查找失败
	}
	```
- **ASL（成功，等概率）**：$\frac{n+1}{n}\log_2(n+1)-1 \approx \log_2(n+1)-1$。
- **ASL（失败）**：等于从根结点到失败结点父结点的路径上的结点数。

#### 分块查找
- **定义**：将表划分为若干子块，块内无序、块间有序；建立索引表（每块最大关键字 + 起始地址）。
	- 两步：索引表中确定块（顺序/折半），块内顺序查找。
	- 又称 **索引顺序查找**。
- **ASL**：$L_I + L_S$（索引查找 ASL + 块内查找 ASL）。当 $n$ 均匀分 $b$ 块、每块 $s$ 个记录且均为顺序查找时，$ASL = \frac{b+1}{2} + \frac{s+1}{2}$；$s=\sqrt{n}$ 时 $ASL$ 最小为 $\sqrt{n}+1$。

#### 树形查找

##### 二叉排序树（BST）
- **定义**：左子树所有结点值 < 根结点值 < 右子树所有结点值，左右子树也是 BST。
	- 中序遍历 BST 得到递增有序序列。
- **查找**：从根开始，key 小于根则入左子树，大于则入右子树，相等则成功；直至 NULL 则失败。
	```c
	BSTNode *BST_Search(BiTree T, ElemType key) {
	    while (T != NULL && key != T->data) {
	        if (key < T->data) T = T->lchild;
	        else T = T->rchild;
	    }
	    return T;
	}
	```
- **插入**：查找失败的位置即为插入位置，新结点一定为叶结点。
	```c
	int BST_Insert(BiTree &T, KeyType k) {
	    if (T == NULL) {
	        T = (BiTree)malloc(sizeof(BSTNode));
	        T->data = k;
	        T->lchild = T->rchild = NULL;
	        return 1;
	    } else if (k == T->data) return 0;
	    else if (k < T->data) return BST_Insert(T->lchild, k);
	    else return BST_Insert(T->rchild, k);
	}
	```
- **构造**：从空树开始依次插入各关键字（重复关键字忽略）。
	```c
	void Creat_BST(BiTree &T, KeyType str[], int n) {
	    T = NULL;
	    for (int i = 0; i < n; i++) BST_Insert(T, str[i]);
	}
	```
- **删除**：分三种情形。
	- 叶结点：直接删除。
	- 单支结点：将唯一子树上移顶替。
	- 双支结点：用中序直接前驱（左子树最右）或直接后继（右子树最左）替换，转化为删除该前驱/后继（至多有一个子树）。
- **查找效率**：取决于树高。平衡时 $O(\log_2 n)$（ASL 约 $2.9$）；最坏退化为单支树 $O(n)$（ASL 约 $5.5$）。
	- 相同关键字集合，插入顺序不同可生成不同形态的 BST。
	- 静态查找宜用二分查找（有序顺序表），动态查找宜用 BST。

##### 平衡二叉树（AVL）
- **定义**：任意结点左右子树高度差（**平衡因子**）绝对值不超过 1 的 BST，平衡因子取值 -1、0、1。
- **插入**：按 BST 规则插入后，沿查找路径向上检查最小不平衡子树，通过 **旋转** 调整。
	- **LL（右单旋）**：在 $A$ 的左孩子的左子树插入，$A$ 的平衡因子由 1 增至 2。将 $A$ 左孩子 $B$ 右上旋为根，$A$ 成为 $B$ 的右孩子，$B$ 的原右子树成为 $A$ 的左子树。
	- **RR（左单旋）**：在 $A$ 的右孩子的右子树插入，$A$ 的平衡因子由 -1 减至 -2。将 $A$ 右孩子 $B$ 左上旋为根，$A$ 成为 $B$ 的左孩子，$B$ 的原左子树成为 $A$ 的右子树。
	- **LR（先左后右双旋）**：在 $A$ 的左孩子的右子树插入。先对 $A$ 的左孩子 $B$ 左旋（RR），再对 $A$ 右旋（LL）。
	- **RL（先右后左双旋）**：在 $A$ 的右孩子的左子树插入。先对 $A$ 的右孩子 $B$ 右旋（LL），再对 $A$ 左旋（RR）。
- **删除**：与插入类似，用 BST 方法删除后，从被删结点向上回溯找第一个不平衡结点 $z$，设 $y$ 为 $z$ 的较高子树根，$x$ 为 $y$ 的较高子树根，按 LL/RR/LR/RL 调整。插入只需一次调整，删除可能需要多次回溯至根。
- **查找**：含 $n$ 个结点的 AVL 树最大深度 $O(\log_2 n)$，ASL 为 $O(\log_2 n)$。
	- 深度 $h$ 的 AVL 树最少结点数：$n_0=0,\ n_1=1,\ n_2=2,\ n_h=n_{h-2}+n_{h-1}+1$。
	- 该递推式可用于求给定结点数下查找的最多比较次数（树的最大深度）。

##### 红黑树
- **定义**：弱平衡的 BST，每个结点有红/黑颜色，通过颜色约束保证最长路径不超过最短路径的 2 倍。
- **5 条性质**：
	1. 每个结点或是红色，或是黑色。
	2. 根结点是黑色。
	3. 叶结点（虚构的外部 NULL 结点）都是黑色。
	4. 红结点的父结点和孩子结点均为黑色（无连续红结点）。
	5. 任一结点到每个叶结点的简单路径上黑结点数相同（**黑高**相同）。
- **黑高（bh）**：从某结点出发（不含该结点）到叶结点的任意路径上黑结点总数。根的黑高即红黑树的黑高。
	- 结论1：最长路径 $\leqslant$ 2 倍最短路径（全黑路径最短，红黑交替路径最长）。
	- 结论2：$n$ 个内部结点的红黑树高度 $h \leqslant 2\log_2(n+1)$。
- **与 AVL 对比**：红黑树"适度平衡"（允许左右子树高度差达 2 倍），插入/删除调整频率低于 AVL；查找略慢于 AVL（常数级）。查找远多于插入/删除用 AVL，插入/删除频繁用红黑树。C++ map/set、Java TreeMap/TreeSet 均基于红黑树。
- **插入**：新结点初始着为 **红色**（避免破坏性质 5）。插入后若父结点为黑则结束；若父结点为红则破坏性质 4，分三种情形调整（设 $z$ 为当前结点，$z.p.p$ 为爷结点且必为黑）：
	- **情形1（LR 型）**：叔结点 $y$ 为黑，$z$ 为父的右孩子。先对 $z.p$ 左旋，转为情形2。
	- **情形2（LL 型）**：叔结点 $y$ 为黑，$z$ 为父的左孩子。对 $z.p.p$ 右旋，父染黑、爷染红。
	- **情形3**：叔结点 $y$ 为红。父和叔染黑，爷染红，将爷作为新 $z$ 继续回溯（可能多次，直至 $z$ 为根则染黑结束；或进入情形1/2 旋转后结束）。
	- 对称情形（父为右孩子时对应 RL/RR 型）。
- **删除**：按 BST 规则删除，若被删结点为黑则破坏性质 5。引入 **双黑** 概念，分四种情形（$x$ 为替换结点，$w$ 为 $x$ 的兄弟）：
	- **情形1**：$w$ 为红。交换 $w$ 与 $x.p$ 颜色，对 $x.p$ 左旋，转为情形2/3/4。
	- **情形2（RR 型）**：$w$ 为黑，$w$ 的右孩子为红。交换 $w$ 与 $x.p$ 颜色，$w$ 右孩子染黑，对 $x.p$ 左旋，结束。
	- **情形3（RL 型）**：$w$ 为黑，$w$ 左红右黑。交换 $w$ 与其左孩子颜色，对 $w$ 右旋，转为情形2。
	- **情形4**：$w$ 为黑，$w$ 左右孩子均为黑。从 $x$ 和 $w$ 中各提取一重黑色（$x$ 变普通黑，$w$ 变红），将 $x.p$ 作为新 $x$ 向上回溯。

#### B树 & B+树
##### B树
- **定义**：$m$ 阶 B 树是一种自平衡的 $m$ 路查找树，所有叶结点位于同一层次。满足以下 5 条性质：
	1. 每个结点至多 $m$ 棵子树（至多 $m-1$ 个关键字）。
	2. 根结点非叶时至少 2 棵子树（至少 1 个关键字）。
	3. 非叶根以外至少 $\lceil m/2 \rceil$ 棵子树（至少 $\lceil m/2 \rceil-1$ 个关键字）。
	4. 结点结构：$n,\ P_0,\ K_1,\ P_1,\ K_2,\ P_2,\ \cdots,\ P_n$，其中 $K_1<K_2<\cdots<K_n$，$P_{i-1}$ 所指子树关键字均小于 $K_i$，$P_i$ 所指子树关键字均介于 $K_i$ 与 $K_{i+1}$ 之间。
	5. 所有叶结点（外部结点）在同一层，不存数据，对应指针为空，相当于查找失败。
- **查找**：两个基本操作。
	- 在 B 树中定位目标结点（磁盘 I/O，决定效率的关键）。
	- 在结点内查找关键字（读入内存后用顺序/折半查找）。
	- 多路分支决策，与 BST 相似但每结点含多关键字。
- **高度（磁盘存取次数）**：对于 $n$ 个关键字、$h$ 高、$m$ 阶 B 树（高度不含外部叶结点层）：
	- 最小高度：$h \geqslant \log_m(n+1)$（每个结点关键字达最大值 $m-1$）。
	- 最大高度：$h \leqslant \log_{\lceil m/2 \rceil}((n+1)/2) + 1$（每个结点关键字达最小值）。
- **插入**：
	- **定位**：沿查找路径到最底层终端结点（外部叶结点的父结点）。
	- **插入与分裂**：插入后关键字数 $\leqslant m-1$ 则直接插入；若 $> m-1$（达 $m$ 个），则从中间位置 $\lceil m/2 \rceil$ 分裂，左半保留原结点，右半移入新结点，中间关键字提升至父结点。可能递归向上传播，根结点分裂则树高 +1。
- **删除**：需保证各结点关键字数 $\geqslant \lceil m/2 \rceil-1$。
	- 若 $k$ 不在终端结点：用前驱（左子树最右下）或后继（右子树最左下）替换，转化为删除终端结点中的情形。
	- **直接删除**：删除前关键字数 $\geqslant \lceil m/2 \rceil$，直接删。
	- **兄弟够借**：删除前关键字数 $= \lceil m/2 \rceil-1$，且相邻兄弟关键字数 $\geqslant \lceil m/2 \rceil$。父结点关键字下移，兄弟关键字上移（父子换位法）。
	- **兄弟不够借**：左右兄弟关键字数均为 $\lceil m/2 \rceil-1$。将该结点、一个兄弟及父结点中分隔它们的关键字合并为一个新结点。合并后父结点关键字数减 1，若根变空则删除根，否则可能向上递归。

##### B+树
- **定义**：$m$ 阶 B+ 树是为数据库高效检索设计的 B 树变体，满足以下条件：
	1. 每个分支结点至多 $m$ 棵子树。
	2. 非叶根至少 2 棵子树；其余分支结点至少 $\lceil m/2 \rceil$ 棵子树。
	3. 分支结点的关键字个数等于其子树个数。
	4. 所有关键字及其记录指针均存储在叶结点中，叶结点内关键字升序，相邻叶结点通过指针按顺序链接（支持顺序查找）。
	5. 分支结点仅包含引导查找的关键字（对应子树的最大值副本）及指向子结点的指针。
- **与 B 树的 5 点差异**：
	1. **子树与关键字关系**：B+ 树 $n$ 个关键字对应 $n$ 棵子树；B 树 $n$ 个关键字对应 $n+1$ 棵子树。
	2. **关键字数量范围**：B+ 树非根内部结点 $\lceil m/2 \rceil \leqslant n \leqslant m$（根 $2 \leqslant n \leqslant m$）；B 树非根内部结点 $\lceil m/2 \rceil-1 \leqslant n \leqslant m-1$（根 $1 \leqslant n \leqslant m-1$）。
	3. **关键字存储**：B+ 树所有关键字存储在叶结点，非叶结点关键字是副本（可重复出现）；B 树每个关键字仅出现一次。
	4. **结点功能**：B+ 树叶结点存完整数据，非叶结点仅索引（更紧凑，减少磁盘 I/O）；B 树所有结点均存储数据。
	5. **顺序查找**：B+ 树叶结点通过指针链接成有序链表，支持顺序遍历；B 树不支持。
- **查找特点**：通常有两个头指针（一个指向根，一个指向最小关键字叶结点）。支持从根的多路查找和从最小叶结点的顺序查找。查找过程中，即使在非叶结点遇到相等关键字也不终止，继续向下直至叶结点。无论成功与否，每次查找均对应一条从根到叶结点的路径。

#### 散列（Hash）表
- **定义**：根据关键字直接进行访问的数据结构，建立关键字到存储地址的直接映射。通过 **散列函数** $Hash(key) = Addr$ 实现，理想情况下查找时间复杂度 $O(1)$。
	- **冲突**：两个或以上不同关键字映射到同一地址，这些关键字称为 **同义词**。
- **散列函数构造要点**：定义域包含全部关键字，值域取决于表大小；地址应均匀分布；计算简单快速。
- **常见散列函数**：
	- **直接定址法**：$H(key) = a \times key + b$，计算最简单，不会产生冲突，适用于关键字分布基本连续的情形。分布稀疏则浪费空间。
	- **除留余数法**：$H(key) = key \% p$，$p$ 为不超过表长 $m$ 且尽可能接近 $m$ 的质数。最常用，$p$ 的选择是关键。
	- **数字分析法**：选取关键字数码分布均匀的数位组合成地址。适用于已知且固定的关键字集合。
	- **平方取中法**：取关键字平方值的中间几位作为地址，分布较均匀。适用于关键字各位分布不均或位数较少的情形。
- **冲突处理方法**：
	- **开放定址法**：所有空闲地址均可用于存放任意关键字。递推公式 $H_i = (H(key) + d_i) \% m$。
		- **线性探测法**：$d_i = 1, 2, \cdots, m-1$。顺序查看下一单元，表尾回绕至表首。易引发 **聚集（堆积）** 现象，大量元素在相邻地址堆积，降低查找效率。
		- **平方探测法（二次探测法）**：$d_i = 1^2, -1^2, 2^2, -2^2, \cdots, k^2, -k^2$（$k \leqslant m/2$）。$m$ 须为 $4k+3$ 的素数。能有效避免堆积，但无法探测所有位置（至少覆盖一半地址空间）。
		- **双散列法**：$d_i = i \times H_2(key)$。需两个散列函数，$H_i = (H(key) + i \times H_2(key)) \% m$。
		- **伪随机序列法**：$d_i$ 为第 $i$ 个伪随机数。
		- **注意**：采用开放定址法时不能直接物理删除元素（会截断同义词查找路径），应设置删除标记实现逻辑删除。
	- **拉链法（链接法）**：将散列到同一地址的所有同义词组织成一个链表，头指针存放在散列表对应单元中。特别适用于频繁插入和删除的场景。
- **散列查找过程**：计算初始地址 Addr = H(key)；检查 Addr 处是否有记录，无则失败，有则比较关键字，相等则成功，否则按冲突处理方法计算下一探测地址，重复直至成功或失败。
- **ASL**：依赖于 **装填因子** $\alpha = n/m$（$n$ 记录数，$m$ 表长），$\alpha$ 越大冲突概率越高。散列表的查找效率取决于三个因素：散列函数、冲突处理方法和装填因子。同一关键字集合和相同散列函数，不同冲突处理方法会导致不同 ASL。
	- 如何计算线性探测法查找失败的ASL：对于除留余数法，除数对应着可能查找的位置，因此每个位置的概率是除数的倒数。由于要查到空才能判断查找失败，因此和空的比较也应该算在查找次数内，因此公式为：$$ASL_{失败}=\frac{每个位置查找失败的总和}{除数}$$
	- 如何计算线性探测法查找成功的ASL：$$ASL_{成功}=\frac{每个元素查找次数}{已插入元素总数}$$
	- 如何计算链地址法查找成功的ASL：同线性探测法
	- 如何计算链地址法查找失败的ASL：同样需要计算和空的比较。
