## 一句话定位
计算机系统是由硬件与软件构成的多级层次结构，通过逐层抽象隔离底层实现与上层应用。

## 它解决什么问题？
理解计算机从物理器件到用户应用之间的分层组织逻辑，明确软/硬件边界及各层职责，为体系结构设计提供框架。

## 主要概念
冯·诺依曼机、CPU（Central Processing Unit，中央处理器）、存储器、总线、系统软件/应用软件、软硬件逻辑等价性、ISA（Instruction Set Architecture，指令集体系结构）、微体系结构、存储程序、翻译程序、可执行文件生成

> **缩写对照**
> - **CPU**：Central Processing Unit，中央处理器
> - **ALU**：Arithmetic Logic Unit，算术逻辑单元
> - **I/O**：Input/Output，输入/输出
> - **ISA**：Instruction Set Architecture，指令集体系结构
> - **OS**：Operating System，操作系统
> - **DBMS**：Database Management System，数据库管理系统
> - **PC**：Program Counter，程序计数器
> - **SIMD**：Single Instruction Multiple Data，单指令多数据流
> - **GCC**：GNU Compiler Collection，GNU 编译器套件
> - **EDVAC**：Electronic Discrete Variable Automatic Computer，电子离散变量自动计算机
> - **IEEE**：Institute of Electrical and Electronics Engineers，电气与电子工程师协会

## 概念解析
#### 计算机系统组成
- **硬件**：有形的物理装置，包括 CPU、存储器、输入输出设备等。[^1]
- **软件**：在硬件上运行的程序及其相关数据与文档。
- **设计原则**：使用频繁且硬件实现成本较低的功能宜由硬件实现，以提升整体效率。

#### 冯·诺依曼机
- **"存储程序"思想**：将程序和数据预先存入主存，启动后自动逐条取指执行，无须人工干预。[^2]
- **五大部件**：运算器、控制器、存储器、输入设备、输出设备。
- **核心特点**：
  - 指令和数据以相同形式（二进制）存放，仅凭内容无法区分
  - 指令由操作码和地址码组成
  - 采用二进制编码表示

#### 计算机功能部件
- **CPU**：运算器 + 控制器，现代架构组织为**数据通路**与**控制单元**。[^3]
  - **数据通路**：含 ALU（算术逻辑运算）和通用寄存器组（提供操作数、暂存结果），以及多路选择器、内部互连通路。
  - **控制单元**：取指、译码，生成控制信号指挥数据通路各部件协同工作。
- **存储器**：
  - **内存**：主存（存放待执行程序和数据）+ 高速缓存（Cache，后期引入）
  - **外存**：磁盘、固态硬盘（可与主存交换数据），磁带、光盘（长期备份）
- **外部设备与控制器**：
  - 外设 = 物理功能部件 + 设备控制器，二者在功能/物理上通常分离
  - 设备控制器（I/O 接口）：如键盘接口、显卡、网卡，负责与主机通信并控制外设
- **总线**：CPU、主存和 I/O 接口之间的公共传输通路。按功能划分：ALU 属数据处理部件，主存和磁盘属存储部件，总线、桥接器、接口及控制器共同构成互连结构。[^4]

#### 计算机软件
- **系统软件**：保障系统高效运行的基础软件，用于管理和调度系统资源。[^5]典型：操作系统（OS）、数据库管理系统（DBMS）、语言处理程序、网络与分布式软件系统、标准库程序、服务性程序。
- **应用软件**：面向特定应用领域的专用程序，如科学计算、工程设计、数据统计等。
- **软/硬件逻辑功能等价性**：同一功能既可用硬件实现又可用软件实现，在相同规范下逻辑功能等价，但硬件效率通常远高于软件。[^6]

#### 计算机系统层次结构
- **算法与编程层**：
  - **机器语言**：由 0/1 组成的指令序列，计算机唯一能直接识别执行的语言。
  - **汇编语言**：用助记符代替二进制指令，需经汇编程序翻译为机器语言。
  - **高级语言**：如 C、C++、Java，接近自然语言，需经编译程序处理。
  - **翻译程序三类**[^7]：
    - 汇编程序（汇编器）：汇编语言 → 机器语言
    - 解释程序（解释器）：逐条翻译并立即执行高级语言语句，不生成独立目标程序
    - 编译程序（编译器）：高级语言一次性翻译为汇编语言或机器语言目标程序
- **操作系统层**：抽象硬件及底层结构，构建供程序员使用的虚拟机，所有语言处理系统在 OS 提供的运行环境中执行。
- **ISA（指令集体系结构）**：软/硬件之间的关键接口，定义软件可直接使用的硬件功能[^8]，包括指令格式、操作类型、寻址方式、可访问寄存器等。ISA 构成软件能"感知"到的计算机功能视图（软件可见部分）。
- **微体系结构（微架构）**：处理器内部的硬件组织方式，决定"怎么做"。[^9]包括数据通路组织、控制单元实现、流水线级数、缓存层次、分支预测等。相同 ISA 可对应多种微架构（如 Intel Core → Skylake → Alder Lake 均遵循同一 x86 ISA）。

#### 计算机系统的不同用户
- **最终用户**：直接操作应用程序完成任务，工作在最上层。
- **系统管理员**：配置、管理、维护系统，工作在 OS 层面。
- **应用程序员**：用高级语言开发应用软件，工作在高级语言层面。
- **系统程序员**：开发 OS、编译器、DBMS 等系统软件，工作在机器语言层面，直接面向 ISA。
- **透明性**：下层机器的结构特性对上层用户通常是"透明"的，无须了解即可开发。

#### 计算机工作原理
- **"存储程序"工作方式**：程序执行前将指令和数据加载至主存，启动后自动逐条取指执行。每条指令：取指（PC 提供地址）→ 译码 → 取操作数 → 执行 → 写回。[^10]
- **PC 更新规则**：
  - 顺序指令：下一条地址 = 当前 PC + 指令长度
  - 跳转指令：下一条地址 = 指令指定的目标地址
- **源程序到可执行文件四阶段**[^11]：
  1. **预处理**：处理 #开头的指令（如 #include 替换为头文件内容），生成 .i 文件
  2. **编译**：将 .i 翻译为汇编程序 .s
  3. **汇编**：将 .s 转换为机器语言，生成可重定位目标文件 .o
  4. **链接**：将 .o 与所需库函数链接，解析外部符号引用，生成可执行文件
- **指令执行抽象模型**：取指—译码—执行三阶段循环，具体硬件实现细节在第5章"中央处理器"展开。

[^1]: 硬件为"躯体"，软件为"灵魂"——硬件提供能力，软件决定如何利用这些能力。

[^2]: EDVAC 机首次提出，冯·诺依曼因此被称为"现代计算机之父"。

[^3]: 传统上运算器和控制器分立，现代处理器中二者被系统组织为数据通路与控制单元。

[^4]: 图1.1 展示了一个典型多总线结构：CPU 通过处理器总线经 I/O 桥接器与主存和 I/O 设备通信。

[^5]: 系统软件不直接解决具体应用问题，而是为应用软件提供运行平台和资源管理。

[^6]: 例如浮点运算：硬件浮点运算器 vs 软件子程序模拟，在 IEEE 754 规范下结果一致，但硬件快得多。这是体系结构设计的核心问题之一。

[^7]: 汇编程序、解释程序、编译程序统称翻译程序，翻译后生成的目标程序才能被硬件执行。解释器不生成独立目标程序。

[^8]: ISA 是软/硬件的分界线——ISA 以下为硬件层（CPU、主存、I/O），ISA 以上为软件层（系统软件与应用软件）。

[^9]: ISA 定义"做什么"，微架构决定"怎么做"。例如加法可用串行进位、超前进位或 SIMD 单元实现，均属微架构范畴。

[^10]: 程序开始前，第一条指令地址存入 PC；执行过程中 PC 自动更新，实现指令流的连续执行。

[^11]: 以 UNIX 系统 GCC 为例：hello.c → (cpp) → hello.i → (cc1) → hello.s → (as) → hello.o → (ld) → hello。
