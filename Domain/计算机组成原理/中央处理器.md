## 一句话定位
中央处理器（CPU）是计算机的运算与控制核心，负责取指令、译码、执行，由数据通路（ALU+寄存器）和控制部件两大部分组成；其性能核心指标包括时钟频率、CPI 和指令吞吐率，可通过单周期、多周期、流水线等不同模型实现指令执行。

## 它解决什么问题？
CPU 解决如何从主存取出指令并执行运算的问题——在精确的时序控制下，通过数据通路完成数据的传输与运算，通过控制部件生成微操作控制信号，协调各部件按指令要求有序工作；同时具备检测与响应异常/中断的能力。

## 概念解析

#### CPU的功能
- **取指令并译码**：从主存取出指令，解析操作码，生成相应控制信号。
- **更新 PC**：确定下一条指令地址，支持顺序执行或程序转移。
- **执行算术与逻辑运算**：通过 ALU 对操作数进行运算。
- **取操作数或写结果**：访问主存或 I/O 接口，读取操作数或将运算结果写回。
- **处理异常或中断**：检测异常或中断请求，在必要时转入相应处理程序。
- **时序控制**：通过时钟信号协调各操作的执行顺序和持续时间，确保指令按序执行。

#### CPU的基本结构
- **程序计数器（PC）**：存放即将执行指令的地址，顺序执行时自动递增（增量为当前指令字节数），转移时更新为目标地址，位数由地址总线宽度决定。
- **指令寄存器（IR）**：暂存当前正在执行的指令，供指令译码器使用，位数等于指令字长。
- **通用寄存器组（GPRs）**：供用户程序灵活使用，暂存操作数、中间结果或地址指针，减少对主存的频繁访问。
- **标志寄存器（FR/PSWR）**：保存 ALU 运算产生的状态信息（零标志、进位等），用于条件判断与转移控制。
- **存储器地址寄存器（MAR）**：存放当前要访问的主存地址，位数由地址总线宽度决定。
- **存储器数据寄存器（MDR）**：暂存从主存读出的数据或将要写入主存的数据，起缓冲与同步作用。
- **指令译码器（ID）**：对 IR 中的操作码进行分析，识别指令类型，输出译码信号。
- **算术逻辑单元（ALU）**：执行数据运算的核心部件，完成算术与逻辑运算。
- **时序信号产生部件**：以系统时钟为基础，生成指令执行所需的周期、节拍和工作脉冲。
- **操作控制信号形成部件**：综合译码信号、时序信号和状态标志，生成微操作控制信号。
- **总线控制逻辑**：实现总线传输的控制，包括数据和地址信息的缓冲与控制。
- **中断机构**：实现对异常情况和外部中断请求的处理。
- 考点：CPU 中各种寄存器的作用与特点（2013、2016、2021）。

#### CPU中的寄存器
- **用户可见寄存器**：可被用户程序直接读取或修改，包括 GPRs、专用地址寄存器（基址、变址、SP）、PC，以及只读型标志寄存器（FR）。
	- 考点：用户可见寄存器（2010、2015、2021）。
- **用户不可见寄存器**：对用户程序透明，仅由 CPU 硬件或操作系统内核使用，包括 IR、MAR、MDR、页表基址寄存器等。

#### 指令执行流程
- **基本循环**：取指令 → 执行指令 → 中断/异常检测，循环往复。
	1. 以 PC 为地址从主存取出指令；同时 PC 自动更新为下一条指令地址。
	2. 译码识别指令类型，区分分支指令与非分支指令。
	3. 分支指令：判断分支条件，满足时更新 PC 为目标地址。
	4. 非分支指令：依次取操作数、执行运算、写回结果。
	5. 执行完成后检测中断/异常：未检测到则继续取指；检测到则保存返回地址，转入中断服务程序。
- 考点：指令执行的过程（2011）。

#### 时序控制与指令周期
- **时钟信号**：时序控制的基础，由晶振经整形分频后形成，时钟周期长度由数据通路中组合逻辑的最大传播延迟决定。
- **指令周期**：一条指令从主存读出到执行完成所经历的全部时间，典型划分为五个阶段：
	- **IF（取指）**：以 PC 为地址从主存/指令 Cache 读取指令送入 IR，PC 更新为下一条地址。
	- **ID（译码/读寄存器）**：译码操作码和寻址方式，从寄存器堆读取操作数，提取立即数。
	- **EX（执行/计算地址）**：ALU 运算（算术/逻辑）、计算访存有效地址、计算分支目标地址并判断转移。
	- **MEM（访存）**：LOAD/STORE 指令访问数据 Cache 或主存完成读写；寄存器-寄存器类指令不涉及。
	- **WB（写回）**：将 ALU 运算结果或存储器读出的数据写回寄存器堆。
- **定长 vs 变长指令周期**：定长所有指令周期相同；变长不同指令占用不同时钟周期数，现代计算机普遍采用变长指令周期以提高效率。

#### 处理器指令执行模型
- **单周期处理器**（CPI = 1）：每条指令在一个时钟周期内完成，指令之间严格串行，时钟周期由最慢指令决定，资源利用率低。
	- **注意**：单周期处理器不能采用单总线结构的数据通路，因为单总线一个时钟周期内只允许一次操作，无法完成一条指令的所有操作。
- **多周期处理器**（平均 CPI > 1）：不同指令占用不同数量的时钟周期，提高了时钟频率和资源利用率，但指令间仍串行。
- **流水线处理器**（理想 CPI = 1）：每个时钟周期启动一条新指令，多条指令在流水线中重叠执行，显著提高吞吐率。
- 考点：单周期和多周期 CPU 的 CPI（2016、2020、2025）。

#### 数据通路的功能与组成
- **数据通路（DataPath）**：数据在指令执行过程中所经过的路径及涉及的硬件部件，包括 ALU、通用寄存器、状态寄存器等，由控制部件生成控制信号驱动。
- **组合逻辑元件（操作元件）**：输出仅由当前输入决定，不依赖历史状态，不受时钟控制，包括加法器、ALU、译码器、多路选择器（MUX）、三态门等。
	- **译码器**：$n$ 位输入产生 $2^n$ 个互斥输出。
	- **MUX**：根据控制信号 Select 从 $N$ 路输入中选择一路，需 $\lceil \log_2 N \rceil$ 位控制信号。
	- **三态门**：由 EN 控制通断，EN=1 时输出等于输入，EN=0 时高阻态（隔断）。
	- 考点：三态门、多路选择器的应用（2015、2023、2024）。
- **时序逻辑元件（状态元件）**：输出依赖当前输入和历史状态，须在时钟同步下工作，包括各类寄存器（GPRs、PC、状态寄存器）和存储器。
- **时钟周期约束**：最小时钟周期 $\geqslant T_{\mathrm{clk\_to\_q}} + T_{\mathrm{max}} + T_{\mathrm{setup}}$，其中组合逻辑延迟 $T_{\mathrm{max}}$ 是关键因素。
	- 考点：数据通路的组成部件（2017、2021、2025）。

#### 数据通路的组织与分类
- **按部件连接方式**：
	- **总线式数据通路**：主要部件通过 CPU 内部总线连接，单总线结构简单但同一时刻仅一组数据传输，多总线支持更高并行度，优点是扩展灵活成本低，缺点是有总线竞争。
	- **专用数据通路**：点对点专用连线连接各部件，可并行传输延迟低，缺点是布线复杂成本高。

| 对比维度 | 总线式数据通路 | 专用数据通路 |
| --- | --- | --- |
| 结构复杂度 | 简单，连线少 | 复杂，需大量点对点连线 |
| 扩展灵活性 | 强，新增部件只需挂接总线 | 弱，新增需重新布线 |
| 数据传输效率 | 低，同一时刻仅一组传输 | 高，多组可并行传输 |
| 硬件成本 | 低 | 高 |
| 性能瓶颈 | 总线带宽受限 | 无总线瓶颈 |
| 典型应用 | 教学模型、嵌入式微控制器 | 高性能处理器（如 RISC）|

- **按时序组织方式**：
	- **单周期数据通路**：所有操作在一个时钟周期内完成，控制简单但资源利用率低。
	- **多周期数据通路**：指令划分为多个阶段，每个阶段在一个时钟周期内完成，提高了硬件复用率。
	- **流水线数据通路**：不同阶段由专用功能部件完成，通过流水段寄存器隔离中间结果，理想每周期完成一条指令。

#### 单总线数据通路
- **结构特点**：所有数据传输共享同一条内部总线，同一时刻仅允许一个部件向总线输出数据，各部件通过三态门与总线相连，控制信号命名格式为"部件名+in/out"。
- **关键部件**：GPRs（通用寄存器组）、Y/Z 暂存寄存器（暂存 ALU 输入/输出）、FR（标志寄存器）、ALU。
- **加法指令示例**（add rd, rs）：
	- 取指阶段：PC→MAR（1周期）→MEM→MDR（5周期）→MDR→IR（1周期）
	- 执行阶段：rs→Y（1周期）→rs+rd→Z（1周期）→Z→rd（1周期）
- **LOAD 指令示例**（lw rd, rs）：
	- 取指阶段同上
	- 执行阶段：rs→MAR（1周期）→MEM→MDR（5周期）→MDR→rd（1周期）
- **注意**：ALU 是无存储能力的组合逻辑电路，需先将一个操作数暂存到 Y；ALU 输出不能直接连到总线，需暂存到 Z 以避免反馈干扰。
- 考点：数据通路中的部件及连接方式（2013、2015、2022）；指令执行阶段的操作控制分析（2009、2015、2019）。

#### 专用数据通路
- **取指令部件**：指令存储器仅支持读，PC 提供地址，下地址逻辑区分顺序执行（PC+4）和转移执行。
- **R 型指令数据通路**：操作数全部来自寄存器，结果写回寄存器，Rs/Rt 为源寄存器编号、Rd 为目的寄存器编号，控制信号 RegWr 使能写回、ALUctr 决定运算类型。
- **I 型指令数据通路**：在 R 型基础上增加立即数扩展器和多路选择器，RegDst 选择 Rd（R 型）或 Rt（I 型）为目的寄存器，ExtOp 决定符号扩展或零扩展，ALUSrc 选择第二操作数为 Rt（R 型）或扩展后立即数（I 型）。
- **访存指令数据通路**：在 I 型基础上增加数据存储器和写回选择，MemtoReg 选择写回数据为 ALU 结果（运算类）或存储器读出数据（LOAD），LOAD/STORE 地址计算为立即数符号扩展加 Rs 经 ALU 不判溢出加法。
- **单周期处理器特点**：指令存储器和数据存储器分离（取指与访存可并行），无 IR（取指后各字段直接用于生成控制信号），时钟周期由最慢指令决定，关键功能单元需多个独立实例（硬件无法复用），所有控制信号在一个时钟周期内保持有效。

#### 控制器的功能与工作原理
- **控制器**：计算机的指挥中心，负责取出待执行的指令并计算下一条指令的位置（更新 PC），对指令的操作码进行解码产生对应的时序信号和控制信号，管理 CPU、主存和 I/O 设备间的数据流向及时序。
- **硬件连接关系**：执行部件通过数据总线与主存及 I/O 设备交换数据，I/O 设备通过接口电路接入系统总线，主存及 I/O 设备根据地址总线信号判断是否被选中并依据控制总线信号完成数据传输，控制器通过地址总线发送指令地址（PC 值）访问主存并将获取的指令通过数据总线送入 IR。
- 依据微操作控制信号的生成方式不同，控制器可分为**硬布线控制器**和**微程序控制器**。

**硬布线控制器**
- **定义**：由复杂的组合逻辑电路和触发器构成（也称组合逻辑控制器），根据指令需求、当前时序和内部状态按时间顺序生成微操作控制信号。
- **指令译码**：IR 中的 $n$ 位操作码通过译码电路转换为 $2^n$ 个输出信号，每种操作码唯一地激活一条输出信号线。
- **CU 输入**：包括三类信号——操作译码器输出的指令信息（与节拍信号共同生成微操作控制信号）、时钟脉冲（划分节拍确保控制信号按时发出）、执行单元反馈的状态标志（使 CU 能根据 CPU 当前状态动态调整控制逻辑）。
- **特点**：性能主要受限于电路延迟（响应速度快），灵活性差（修改或新增指令需重新设计电路），随着指令系统功能增强微操作控制信号数量急剧增加导致电路规模庞大调试困难。
- **应用**：RISC CPU。
**微程序控制器**
- **定义**：采用存储逻辑实现，将控制器所需的微操作控制信号组织为微指令并将执行每条机器指令所需的微指令序列（微程序）预先存入专用的高速存储器（控制存储器）中，运行时依次读取微指令生成相应的微操作控制信号。

**基本概念**
- **微命令**：控制部件向执行部件发出的最基本控制信号，是构成控制序列的最小单位（如使能寄存器写入信号、打开数据通路中的控制门）。
- **微操作**：执行部件接收到微命令后所执行的具体动作，二者一一对应。
- **相容性微命令**：可同时有效、协同完成某一功能的微命令。
- **互斥性微命令**：在同一时刻不允许同时有效的微命令。
- **微指令**：若干微命令的集合，包含操作控制字段（微操作码字段，生成当前步骤所需的微操作控制信号）和顺序控制字段（下址字段，确定下一条微指令的地址）。
- **微周期**：执行一条微指令所需的基本时间单位，通常为一个时钟周期。
- **层次关系**：机器指令 → 微程序（微指令的有序集合）→ 微指令 → 微命令/微操作。
- **主存储器**：存放程序和数据，位于 CPU 外部，通常用 RAM 实现。
- **控制存储器（CM）**：存放微程序，位于 CPU 内部，通常用 ROM 实现，每个存储单元的地址称为微地址。
	- 考点：主存储器和控制存储器的区别（2017）。
- **程序**：指令的有序集合，由软件开发者编写，存放于主存或辅存。
- **微程序**：微指令的有序集合，由体系结构设计者编写，用于解释和执行机器指令，固化于控制存储器中，对程序员完全透明。
- **关键寄存器**：MAR（存放主存读/写地址），$\mu$PC 或 CMAR（存放待执行微指令在 CM 中的微地址），IR（存放从主存读出的当前机器指令），$\mu$IR 或 CMDR（存放从 CM 读出的当前微指令）。

**微程序控制器的组成与工作过程**
- **基本组成**：微地址形成部件（根据机器指令操作码生成对应微程序的入口地址并依据当前微指令的顺序控制字段及状态条件产生后续微地址），微指令地址寄存器（$\mu$PC，接收微地址形成部件提供的微地址作为 CM 的读地址），控制存储器（CM，存放所有机器指令对应的微程序），微指令寄存器（$\mu$IR，暂存从 CM 读出的微指令并将其操作控制字段和顺序控制字段分别送至执行单元和微地址形成部件）。
- **工作过程**：
	1. 执行取指令公共操作：将取指微程序的入口地址送入 $\mu$PC，从 CM 读取首条取指微指令送入 $\mu$IR，完成后机器指令存入 IR。
	2. 生成当前指令的微程序入口地址：根据 IR 中操作码经微地址形成部件产生对应微程序的起始微地址送入 $\mu$PC。
	3. 顺序执行微程序：从 CM 逐条读取微指令送入 $\mu$IR 并执行。
	4. 返回循环：当前微程序执行结束后自动转移回取指微程序入口，处理下一条机器指令。
- **微程序数量**：控制存储器中微程序总数等于机器指令条数加上公共微程序数（取指、间址、中断等）。

**微指令的编码方式**
- **直接编码（直接控制）方式**：操作控制字段中每一位直接对应一个微命令，置 1 有效置 0 无效，结构简单直观且微命令可并行发出执行速度快，但微指令字长过长（$n$ 个微命令需要 $n$ 位）导致控制存储器容量急剧膨胀。
- **字段直接编码方式**：将操作控制字段划分为若干互斥段，互斥性微命令归入同一字段、相容性微命令分配到不同字段，每个字段独立编码经译码后激活一个微命令，显著缩短微指令字长但需译码导致执行速度略低于直接编码。
	- 分段原则：互斥性微命令在同一字段相容性微命令在不同字段，每个字段位数不宜过多，每个字段预留一个编码表示"无操作"（如 3 位字段用 000 表示无操作）。
	- 考点：字段直接控制的编码方式（2012）。
- **字段间接编码方式**：某个微命令字段的实际含义由另一个字段的编码共同决定，进一步压缩微指令长度，但译码线路更复杂时间开销更大，仅适用于特定场合。

**微指令的地址形成方式**
- **增量方式（计数器方式）**：下条微地址由 $\mu$PC 自动加 1 生成，适用于顺序执行段。
- **断定方式（下址字段方式）**：在当前微指令中显式指定下条微地址。
- **三种典型情形**：
	1. 微程序入口地址：机器指令操作码经微地址形成部件生成对应微程序首条微指令地址送入 $\mu$PC。
	2. 顺序执行：采用增量方式（$\mu$PC + 1）或断定方式在下址字段填入顺序地址。
	3. 条件分支：微地址形成部件结合当前微指令的下址字段指定的转移目标地址与条件信号来确定下条微地址。

**微指令的格式**
- **水平型微指令**：操作控制字段中每一位（或每一字段）直接对应一个微命令，可同时定义并执行多个并行的微操作，并行能力强执行效率高微程序短，但微指令字长长编写微程序困难。
![[5.18.png]]
- **垂直型微指令**：类似机器指令结构（设置微操作码字段通过译码产生控制信号），一条垂直型微指令通常显式定义一个基本微操作，格式示例为` | 微操作码 | 目的地址 | 源地址 |`，微指令短格式规整编写微程序简单，但微程序长执行速度慢效率低。
- **水平型 vs 垂直型对比**：水平型并行能力强灵活性强效率高而垂直型较差，单条水平型完成更多工作而垂直型需多条微指令完成同等任务，水平型字长长但微程序短而垂直型字长短但微程序长，水平型编写难度大而垂直型类似机器指令更易理解。
- 考点：微指令后继地址字段位数与微指令条数的关系（2014）。

**硬布线控制器 vs 微程序控制器**

| 对比项 | 微程序控制器 | 硬布线控制器 |
| --- | --- | --- |
| 工作原理 | 微操作控制信号以微程序形式存放在 CM 中，执行指令时读出 | 微操作控制信号由组合逻辑电路根据指令码、状态和时序即时产生 |
| 执行速度 | 慢 | 快 |
| 规整性 | 较规整 | 烦琐、不规整 |
| 应用场合 | CISC CPU | RISC CPU |
| 易扩充性 | 易扩充修改 | 扩充修改困难 |

- 考点：硬布线控制器和微程序控制器的特点（2009）。

#### 并行处理体系结构分类（Flynn分类法）
- **Flynn分类法**：根据指令流和数据流的数量，将计算机体系结构分为四类——SISD、SIMD、MISD、MIMD。
- **SISD（单指令流单数据流）**：传统串行计算机结构，包含一个处理器和一个存储器，任一时刻仅执行一条指令。部分SISD采用指令流水线和多模块交叉方式组织存储器以提升性能。
- **SIMD（单指令流多数据流）**：由一个指令控制单元和多个处理单元组成，所有处理单元同时执行同一条指令，但各自拥有独立的地址寄存器，可操作不同的数据。适用于数据级并行（如数组for循环），但在条件分支场景下效率显著降低。向量处理器是SIMD的典型实现。
- **MISD（多指令流单数据流）**：多个指令流同时处理同一数据流，理论上存在但无实际应用。
- **MIMD（多指令流多数据流）**：同时执行多条指令，分别处理多个不同的数据流，是当前主流的并行计算模型。分为两类：
  - **多计算机系统（消息传递型MIMD）**：每个节点拥有私有存储器和独立地址空间，通过消息传递进行通信。
  - **多处理器系统（共享存储型MIMD）**：具有统一全局地址空间，所有处理器可通过普通访存指令访问任意存储单元。
- **总结**：SIMD属于数据级并行，适用于规则同构的数据处理；MIMD支持线程级或任务级并行，适用范围更广。

#### 硬件多线程
- **硬件多线程**：为减少线程切换开销，处理器为每个线程配备独立的通用寄存器组、PC等关键状态部件。线程切换时只需激活对应寄存器组，无须将上下文写入或读出内存，大幅降低切换延迟。
- **细粒度多线程**：每个时钟周期切换线程，交替执行不同线程的指令。各线程指令交错执行，有效提升功能部件利用率。
- **粗粒度多线程**：连续执行同一线程的指令序列，仅当因高延迟事件（如Cache缺失）导致流水线阻塞时才切换至另一线程。切换需清空流水线并重新填充，开销大于细粒度多线程。
- **同时多线程（SMT）**：在单个时钟周期内同时发射并执行来自多个不同线程的多条指令，既利用指令级并行又实现线程级并行。通常构建于超标量和乱序执行微架构之上，共享执行单元与缓存等资源。
- **超线程（Hyper-Threading）**：Intel处理器的SMT实现，在一个物理核心中维护两套完整的线程状态部件（寄存器组、PC等），高速缓存和ALU等执行资源由两个逻辑核心共享，实际性能提升10%~30%。

#### 多核处理器
- **多核处理器（Multi-core）**：将多个独立的处理单元（核）集成到单个CPU芯片中，也称片上多处理器。每个核通常配备私有的L1 Cache（有时包括L2），多个核共享更高层级的Cache（如L3），所有核通过互连网络共享主存储器。
- **并行性对比**：串行处理器逐一执行任务；双核处理器相当于两名工人并行工作；向量处理器如同用一根长木板同时推动多块石头（对所有数据施加完全相同操作）。
- **与单核多线程的区别**：多核架构支持多线程在物理上同时执行（每个核独立运行一个线程），而单核细粒度/粗粒度多线程以时间交错方式执行，任一瞬间仅有一个线程在运行。

#### 共享内存多处理器（SMP）
- **SMP（共享内存多处理器）**：具有共享单一物理地址空间的多处理器系统，所有CPU可通过常规访存指令访问内存中任意位置，通过读/写共享变量进行通信。操作系统负责将各CPU的独立虚拟地址映射到统一的物理地址空间。
- **UMA（统一存储访问）**：所有CPU访问任意内存单元的延迟基本相同，与发起请求的CPU及目标地址无关。
- **NUMA（非统一存储访问）**：内存访问延迟取决于请求CPU与目标内存的物理位置关系。内存控制器集成到各CPU内部，每个CPU直接连接一部分物理内存（本地内存），各CPU通过高速互连总线（如Intel QPI）相互连接并可访问远程内存。访问本地内存延迟显著低于远程内存，程序性能对数据布局敏感。
- **同步机制**：多个CPU可能同时访问同一共享变量，需引入互斥锁等同步机制确保操作原子性与数据一致性。
- **Cache一致性**：SMP系统中多个CPU的Cache可能同时缓存同一物理地址的副本，要求任意时刻所有CPU对该地址的Cache副本保持一致。通常由硬件一致性协议保障（通过传播写操作或无效化其他CPU中的副本）。
- 考点：Cache一致性与内存一致性的区别与联系（2021、2023）。
