## 一句话定位
指令系统是计算机软件与硬件之间的接口，由操作码和地址码组成，定义机器级程序的格式与行为；通过定长/扩展操作码、不同地址数指令格式平衡指令表达能力与指令字长。

## 它解决什么问题？
解决如何用二进制编码表示机器操作与操作数地址的问题——在有限字长内既要支持丰富的指令种类，又要兼顾译码效率与硬件复杂度。ISA 为汇编/机器语言程序员提供编程接口，深入理解 ISA 才能写出充分利用硬件特性的高性能程序。

## 主要概念
指令集体系结构（ISA），操作码，地址码，零/一/二/三地址指令，定长操作码，扩展操作码，寻址方式（指令寻址/数据寻址），数据传送指令，算术逻辑运算指令，移位指令，顺序控制指令（JMP/BRANCH/CALL/RET），输入输出指令，CPU控制指令，CISC，RISC，复杂指令系统计算机，精简指令系统计算机，微程序控制，硬布线控制，LOAD/STORE，指令流水线

> **缩写对照**
> - **ISA**：Instruction Set Architecture，指令集体系结构
> - **OP**：Operation Code，操作码
> - **PC**：Program Counter，程序计数器

> - **SP**：Stack Pointer，堆栈指针
> - **BR**：Base Register，基址寄存器
> - **IX**：Index Register，变址寄存器

> - **RET**：Return，返回指令

> - **RISC**：Reduced Instruction Set Computer，精简指令系统计算机

## 概念解析
#### 指令集体系结构（ISA）
- **ISA**：完整定义软件与硬件之间的接口，是机器语言/汇编语言程序员必须掌握的基础。
- **规定内容**：
	- 指令格式、寻址方式、操作类型，以及各操作所需操作数的个数、类型和寻址约束
	- 操作数的数据类型，以及按大端还是小端方式存放
	- 程序可访问的寄存器编号、数量和位数，存储空间的大小及编址方式
	- 程序员可见的控制状态，如程序计数器（PC）、条件码的定义与行为
- **与高级语言的关系**：高级语言（C/C++/Java）抽象层高、隐藏机器细节，开发效率高但难以利用硬件特性优化；理解 ISA 才能开发性能更优的程序。

#### 指令的基本格式
- **指令格式**：`[操作码字段 | 地址码字段]`
- **操作码（OP）**：指明操作及功能，是识别指令、理解地址码含义的关键
- **地址码**：给出被操作信息的地址——源操作数地址、目的操作数地址、转移目标地址或子程序入口地址
- **定长指令字结构**：所有指令字长相等，取指和译码简单，利于流水线
- **变长指令字结构**：字长随功能而异，通常为字节整数倍
- 格式：`[OP]`
- 格式：`[OP | A1]`
	- **单操作数指令**：按 A1 地址取数，执行 OP 后结果存回 A1。含义：OP(A1) → A1。如加1、减1、求反、求补、移位
	- **累加器型双操作数指令**：A1 为源操作数地址，另一操作数隐含在 ACC，结果存入 ACC。含义：(ACC) OP (A1) → ACC
	- 地址码为主存地址时需 **3次访存**（取指1次 + 取数1次 + 存结果1次）
- 格式：`[OP | A1 | A2]`
	- **含义**：(A1) OP (A2) → A1，A1 为目的兼结果地址，A2 为源操作数地址
	- 地址码均为主存地址时需 **4次访存**（取指1次 + 取两数2次 + 存结果1次）
- 格式：`[OP | A1 | A2 | A3]`
	- **含义**：(A1) OP (A2) → A3，A1、A2 为源操作数地址，A3 为结果地址
	- 地址码均为主存地址时需 **4次访存**（取指1次 + 取两数2次 + 存结果1次）

#### 定长操作码
- **定长操作码**：在指令字最高位分配固定位数的操作码字段，n 位操作码最多表示 $2^n$ 条指令
- 优点：简化硬件设计，提高译码速度
- 在字长为32位或更长的系统中是常规用法

#### 扩展操作码
- **扩展操作码**：操作码长度随地址码减少而增加，不同地址数的指令有不同长度的操作码，从而在有限字长内支持更多指令种类
- **核心规则**：
	- 短操作码不能成为长操作码的前缀（即短操作码不能与长操作码的前面部分相同）
	- 各指令的操作码一定不能重复
- **设计原则**：高频指令分配短操作码，低频指令分配长操作码，减少指令译码和分析时间
- **典型扩展方案**（16位字长，4位基本OP，三个4位地址段）：三地址15条（1111扩展）→ 二地址15条（11111111扩展）→ 一地址15条（111111111111扩展）→ 零地址16条，共61条
- **其他扩展方案**：如15条三地址 + 12条二地址 + 63条一地址 + 16条零地址，共106条

#### 指令的类型
- **数据传送指令**：MOV（寄存器间传送）、LOAD（内存→CPU寄存器）、STORE（CPU寄存器→内存）、PUSH（进栈）、POP（出栈）
- **算术和逻辑运算指令**：ADD、SUB、MUL、DIV、INC、DEC、AND、OR、NOT、XOR
- **移位操作指令**：算术移位、逻辑移位、循环移位
- **顺序控制指令**：
	- **JMP（无条件转移）**：任何情况下都执行转移，不保存返回地址
	- **BRANCH（条件转移）**：仅在特定条件满足时转移，条件通常为标志位或其组合
	- **CALL（调用）**：保存下一条指令地址（返回地址），子程序结束后能返回主程序
	- **RET（返回）**：从子程序返回主程序
	- **TRAP（陷阱）**：陷入特殊处理程序
- **输入输出指令**：CPU 与外部设备交换数据或传送控制命令及状态信息
- **CPU 控制指令**：停机、开中断、关中断、系统模式切换等，仅操作系统内核代码可用

#### 寻址方式
- **寻址方式**：确定指令或操作数有效地址的方法，分为指令寻址和数据寻址两大类。
- **指令寻址**：确定下一条将要执行的指令地址。
	- **顺序寻址**：通过 PC 加上当前指令的字节长度，自动形成下一条指令地址。PC 自增大小与编址方式和指令字长有关——按字节编址时，16位指令 PC 自增2，32位指令 PC 自增4（2013、2014、2019、2023考点）
	- **跳跃寻址**：通过转移类指令实现。目标地址由指令给出，分为绝对转移（地址码直接给出目标地址）和相对转移（地址码给出相对于当前 PC 的偏移量）。转移指令的执行结果都是修改 PC 的值。
- **数据寻址**：确定本条指令操作数地址。指令字中通常设有寻址特征字段，其位数决定了可支持的寻址方式种类（2020、2023考点）。
	- **形式地址（A）**：指令地址码字段中所包含的地址，不代表操作数的真实地址
	- **有效地址（EA）**：通过寻址方式由形式地址计算得出的真实地址
	- 不同寻址方式中形式地址位数的意义不同：立即寻址时决定操作数取值范围；直接寻址时决定可寻址存储空间大小；寄存器寻址时决定通用寄存器最大数量；寄存器间接寻址时寄存器的位数决定可寻址空间大小

| 寻址方式      | 有效地址           | 访存次数 |
| --------- | -------------- | :--: |
| 立即寻址      | A 即是操作数        |  0   |
| 直接寻址      | EA = A         |  1   |
| 一次间接寻址    | EA = (A)       |  2   |
| 寄存器寻址[^3] | EA = Ri（寄存器编号） |  0   |
| 寄存器间接一次寻址 | EA = (Ri)      |  1   |
| 相对寻址[^2]  | EA = (PC) + A  |  1   |
| 基址寻址      | EA = (BR) + A  |  1   |
| 变址寻址      | EA = (IX) + A  |  1   |
| 隐含寻址 [^1] | 由特定寄存器隐含给出     |  0   |
| 堆栈寻址      | 由 SP 隐含给出      |  0   |

#### CISC 与 RISC
- **基本概念**：指令系统朝两个相反方向发展——**CISC（复杂指令系统计算机）** 通过增强原有指令功能、加入更复杂指令将部分软件功能固化到硬件（如 x86）；**RISC（精简指令系统计算机）** 通过精简指令集、简化指令功能以提升执行效率（如 ARM、MIPS）。
- **CISC 特点**（考点：2017）：
	1. 指令系统庞大复杂，指令数量通常超过 200 条
	2. 指令长度不固定，指令格式和寻址方式种类繁多
	3. 多数指令均可直接访问内存
	4. 各类指令使用频率差异显著——约 80% 程序执行仅依赖 20% 简单指令，这一 20/80 定律催生了 RISC
	5. 指令执行时间相差较大，大多数需多个时钟周期才能完成
	6. 控制器多采用微程序控制，部分复杂指令难以用硬连线逻辑实现
	7. 难以通过优化编译生成高效目标代码
- **RISC 特点**（考点：2009、2025）：
	1. 仅选取使用频率最高的简单指令，复杂功能由多条简单指令组合实现
	2. 指令长度固定，指令格式和寻址方式种类较少
	3. 仅 LOAD/STORE（取数/存数）指令可访问内存，其余运算均在寄存器之间进行
	4. CPU 中配备大量通用寄存器
	5. 普遍采用指令流水线技术，绝大多数指令在一个时钟周期内完成
	6. 以硬布线控制为主，极少或不使用微程序控制
	7. 高度依赖编译器优化，以缩短程序执行时间
- **兼容性差异**：CISC 通常支持向后兼容，新机型包含旧机型全部指令并加以扩展；RISC 因大幅简化指令集、改变指令格式，通常无法与老机型兼容。
- **RISC 优势**：
	- **芯片利用率**：CISC 微程序控制 ROM 占 CPU 芯片面积 50% 以上，RISC 硬布线逻辑电路仅约 10%
	- **运算速度**：指令少、格式统一、寻址方式简单，配合大量通用寄存器和流水线，多数指令单周期完成
	- **设计维护**：结构简单，设计周期短，逻辑清晰易调试，可靠性高
	- **编译优化**：指令类型和寻址方式有限，编译器更易选择最优指令序列
- **现实格局**：x86 凭借庞大软件生态占据主流，纯 RISC 系统难以满足兼容性需求；现代 CISC 处理器已融合大量 RISC 思想，性能差距缩小；CISC 的丰富指令功能也为许多程序设计所需。
- **对比表**：

| 对比项目 | CISC | RISC |
| --------- | ---- | ---- |
| 指令系统 | 复杂，庞大 | 简单，精简 |
| 指令数目 | 一般大于 200 条 | 一般小于 100 条 |
| 指令字长 | 不固定 | 定长 |
| 可访存指令 | 不加限制 | 只有 LOAD/STORE 指令 |
| 各种指令执行时间 | 相差较大 | 绝大多数在一个周期内完成 |
| 各种指令使用频度 | 相差很大 | 都比较常用 |
| 通用寄存器数量 | 较少 | 多 |
| 目标代码 | 难以用优化编译生成高效的目标代码程序 | 采用优化的编译程序，生成代码较为高效 |
| 控制方式 | 绝大多数为微程序控制 | 绝大多数为组合逻辑控制 |
| 指令流水线 | 可以通过一定方式实现 | 必须实现 |
