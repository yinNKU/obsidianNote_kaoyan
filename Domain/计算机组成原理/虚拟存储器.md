## 一句话定位
虚拟存储器是由硬件与系统软件协同实现的存储管理机制，利用主存和辅存（磁盘）构建逻辑上连续且容量巨大的地址空间；对应用程序员透明——程序按虚拟地址编写，无须关心实际主存容量或物理位置；虚地址空间远大于实地址空间。

## 它解决什么问题？
主存容量有限，无法同时容纳大型程序的所有代码和数据。虚拟存储器将程序的虚拟地址空间与主存的物理地址空间分离，仅将活跃部分调入主存，其余留在辅存，实现"小主存跑大程序"；同时通过地址映射和页表管理，为每个进程提供独立的虚拟地址空间，支持多道程序并发执行和内存保护。

## 主要概念
虚拟地址空间，物理地址空间，虚地址（逻辑地址），实地址（物理地址），缺页异常，页表，有效位，脏位，引用位，快表（TLB），慢表（Page），页式虚拟存储器，段式虚拟存储器，段页式虚拟存储器，地址转换，内部碎片，外部碎片

> **缩写对照**
> - **TLB**：Translation Lookaside Buffer，页表缓存/快表
> - MMU：Memory Management Unit，内存管理单元（就是将虚拟地址转换为物理地址的硬件）

## 概念解析
#### 虚拟存储器的基本概念
- **虚拟存储器**：将程序地址空间（虚拟地址空间）与主存物理地址空间分离的存储管理机制。
	- CPU 使用虚地址访存 → 系统判断数据是否在主存中 → 若在，通过地址变换转为实地址后访问；若不在，触发缺页（缺段）异常，由 OS 将包含该地址的页（段）从辅存调入主存。
	- 主存已满时，根据替换算法选择一个页面置换。
	- 借鉴 Cache 思想，将辅存中频繁访问的数据缓存在主存中。
- **回写策略**：虚拟存储器只能采用回写法——页面被修改时标记为脏页，仅在被置换出主存时才写回辅存。辅存访问延迟极高，每次写都同步更新辅存不可行。
	- 考点：虚拟存储器只能采用回写法的原因（2016）。
- **全相联映射**：分页机制允许任一虚页装入主存中任意可用物理页框（类似全相联），提高主存利用率，支持高效地址重定位。

#### 页式虚拟存储器
- **页式虚拟存储器**：以页为基本单位，主存空间和虚拟地址空间均划分为大小相同的页。
	- 物理页（实页/页框）：主存中的页。
	- 虚拟页（虚页）：虚拟地址空间中的页。
	- **页表**：记录每个虚页在主存中映射位置的数据结构，常驻内存。

##### 页表
- **页表项字段**：
	- **有效位（装入位）**：=1 表示虚页已调入主存，页表项存放物理页号；=0 表示未调入，存放外存地址。
	- **脏位（修改位）**：表示页面是否被修改过，置换时决定是否写回磁盘。
	- **引用位（使用位）**：记录页面是否被访问过，用于 Clock/LRU 等替换算法。
- **缺页处理流程**：CPU 访问虚页 → 有效位=0 → 缺页异常 → OS 缺页处理程序根据外存地址将页调入空闲物理页框 → 主存满则选择页面置换（回写策略下根据脏位决定是否写回） → 更新页表。
	- 考点：数组的分页存放、缺页分析与处理过程（2014、2019、2023、2025）。
- **优缺点**：页面大小固定，页表结构简单，调入方便；但最后一页可能产生内部碎片，页缺乏逻辑意义，模块化/保护/共享不如段式灵活。

##### 地址转换
- **虚拟地址结构**：高位=虚页号，低位=页内偏移。物理地址同样：高位=物理页号，低位=页内偏移。页大小相同 → 页内偏移一致。
	- 考点：虚拟地址结构的分析（2011、2019、2021、2024）。
- **地址转换过程**：页表基址寄存器 → 查当前进程页表起始地址 → 从虚拟地址提取虚页号作为索引 → 查页表项 → 有效位=1，取物理页号 → 与页内偏移拼接 → 物理地址。有效位=0 → 缺页异常。
	- 考点：虚拟地址与物理地址的转换（2011、2013、2018、2022）。

##### 快表（TLB）
- **TLB**：由高速 SRAM 构成的页表项缓存，缓存近期频繁访问的页表项，避免每次地址转换都访问主存中的页表（慢表）。
	- 依据：程序访问的局部性原理——CPU 在一段时间内往往集中访问少数页面。
	- 考点：TLB 的硬件实现（2018），TLB 和 Cache 的比较（2020）。
- **TLB 映射方式**：通常采用全相联或组相联映射。全相联下 TLB 标记=完整虚拟页号；组相联下虚页号高位=标记，低位=组索引。TLB 表项包含虚页号（标记）、物理页号、控制位（有效位、脏位等）。
	- 考点：TLB 映射方式、地址划分与标记字段的分析（2016、2021）。

##### 具有 TLB 和 Cache 的多级存储系统
- **访问过程**：CPU 给出虚地址 → TLB 并行比较虚页号与所有 TLB 项标记 → TLB 命中则获取实页号完成地址转换；TLB 未命中则访问主存页表（慢表），完成后装入 TLB（TLB 满则替换） → 获得物理地址 → Cache 按映射方式划分为标记+组号+块内地址 → 定位 Cache 组，比较标记 → 命中则取数据送 CPU。
	- 考点：具有 TLB 的虚拟存储系统的地址变换过程（2024）。
- **三种缺失情况**：
	- TLB 缺失：虚页号不在 TLB 中。
	- Cache 缺失：主存块不在 Cache 中。
	- Page 缺失：页面不在主存中。
	- 关系：Page 缺失 → TLB 必然缺失；Page 缺失 → Cache 中不可能有对应数据。Cache 缺失由硬件处理；缺页由 OS 处理；TLB 缺失可由硬件或软件处理。
	- 考点：TLB、Cache 和 Page 缺失组合的分析（2010）。
- **五种组合及访存次数**：

| 序号 | TLB | Page | Cache | 说明 | 访存次数 |
|------|-----|------|-------|------|----------|
| 1 | 命中 | 命中 | 命中 | 最佳情况 | 0 次访主存 |
| 2 | 命中 | 命中 | 缺失 | Cache 可能不命中 | 1 次访主存 |
| 3 | 缺失 | 命中 | 命中 | TLB 缺失但 Page 可能命中 | 1 次访主存 |
| 4 | 缺失 | 命中 | 缺失 | 最差不含缺页 | 2 次访主存 |
| 5 | 缺失 | 缺失 | 缺失 | 缺页异常，需访问磁盘 | 至少 2 次访主存+磁盘 |

#### 段式虚拟存储器
- **段式虚拟存储器**：按程序的逻辑结构划分段，各段长度因程序而异。虚拟地址分为段号+段内地址。
	- **段表**：记录段的段号、有效位、段起点、段长等信息。因段长度可变，必须给出起始地址与段长。
- **地址变换**：提取段号 → 查段表基地址 → 找到段表项 → 有效位=1，取段起始地址 → +段内地址 → 物理地址。
- **特点**：分段对程序员不透明（段是程序逻辑结构的独立部分）；分页对程序员透明。
- **优缺点**：段边界与程序逻辑边界一致，便于编译/管理/修改/保护/段共享；但段长度可变导致主存分配困难，易产生外部碎片。

#### 段页式虚拟存储器
- **段页式虚拟存储器**：程序先按逻辑结构分段，每段再划分为固定大小的页。主存空间也划分为大小相等的页，调入调出以页为基本交换单位。
	- 每个程序一个段表，每段一个页表。虚拟地址=段号+段内页号+页内地址。
- **地址变换**：段号查段表 → 获得页表起始地址 → 段内页号查页表 → 取出实页号 → +页内地址 → 物理地址。
- **优缺点**：兼具页式和段式优点——按段共享保护，避免段式外部碎片；但需两次查表，系统开销大。

#### 虚拟存储器与 Cache 的比较
- **相同点**：
	- 最终目标都是提高性能，体现容量/速度/价格梯度。
	- 都把数据划分为小信息块作为交换单位（虚拟存储器的页通常远大于 Cache 块）。
	- 都涉及地址映射、替换算法、更新策略。
	- 都基于局部性原理，采用"快速缓存"思想，将活跃数据放在高速部件中。
- **不同点**：
	- Cache 解决 CPU 与主存速度差异；虚拟存储器解决主存容量不足。
	- Cache 完全由硬件实现，对所有程序员透明；虚拟存储器由 OS+硬件实现，对应用程序员透明，对 OS 开发者不透明。
	- 不命中性能影响：Cache 不命中访问主存，延迟增数十倍；缺页访问磁盘，延迟增可达十万倍。
	- CPU 可直接访问 Cache 和主存，Cache 不命中时硬件自动从主存取数据装入 Cache；辅存与 CPU 无直接通路，缺页须先将数据从辅存调入主存再访问。
	- 考点：虚拟存储器与 Cache 的比较（2024），Cache 缺失和缺页的处理开销对比（2016）。
