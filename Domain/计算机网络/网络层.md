## 一句话定位

网络层提供主机到主机的通信服务，通过路由选择与分组转发将分组从源主机经多个网络和多段链路传输到目的主机，屏蔽底层异构网络细节，向上提供统一的 IP 网络服务。

## 它解决什么问题？

物理层和数据链路层仅解决相邻节点的通信，无法将分组跨越多个异构网络传输到远端主机。网络层通过统一的 IP 协议屏蔽底层差异，实现异构网络互连；通过路由选择算法计算最优路径，通过分组转发将数据沿路径逐跳传送；同时提供虚电路或数据报两种服务模型，并处理网络拥塞问题。

## 概念解析

#### 异构网络互连

- **定义**：将两个以上的计算机网络通过一定方法用中继系统相互连接，构成更大的网络系统。网络互连通常指用路由器进行网络连接和路由选择。
- **四种中继系统**（按所在层次）：
	- **物理层**：转发器（中继器）、集线器——只是把网络扩大，从网络层看仍是同一个网络，不称为网络互连。
	- **数据链路层**：网桥或交换机——同样只是扩展网络，不改变网络层视角。
	- **网络层**：路由器——实现真正意义上的网络互连和路由选择。
	- **网络层以上**：网关。
- **IP 网络（虚拟互连网络）**：参与互连的计算机网络都使用相同的网际协议 IP，通过 IP 协议使性能各异的网络在网络层上看起来像是一个统一的网络。主机通信时感觉就像在单个网络上通信，看不见底层异构细节。

#### 路由与转发

- **定义**：路由器的两大核心功能。
	- **路由选择**：运行路由协议，定期与相邻路由器交换信息，动态生成并维护路由表，计算到达目的网络的最优路径。
	- **分组转发**：根据转发表将到达的分组从合适的输出端口转发出去。
- **路由表 vs 转发表**：路由表由路由选择算法生成，侧重于拓扑计算；转发表由路由表导出，结构上优化查找效率。讨论原理时通常不严格区分两者。

#### 网络层提供的两种服务

- **虚电路服务**（面向连接）：通信前必须先建立逻辑连接——虚电路（VC），路径固定后传输数据，结束后释放连接。
	- **工作原理**：发送"呼叫请求"分组经中间节点转发至目的 → 目的返回"呼叫应答"确认 → 数据传输 → 发送"释放请求"拆除连接。
	- **特点**：
		- 建立与释放开销大，适合长时间大量数据交换，不适合少量数据或交互应用。
		- 路由选择在连接建立阶段完成，后续分组只用短虚电路号（VCID）而非完整地址。
		- 提供可靠、有序的分组交付，支持端到端流量控制。
		- 对节点/链路故障敏感——任一故障中断所有经过的虚电路。
		- 分组首部开销小（仅携带 VCID）。
		- "虚"的含义：链路并非专用，可被多条虚电路共享。

- **数据报服务**（无连接）：发送分组前无须建立连接。每个分组携带完整源和目的地址，独立选路转发。
	- **工作原理**：主机将报文分割封装为分组 → 节点缓存分组 → 查询转发表独立选路转发 → 后续节点同样处理直至到达目的。
	- **特点**：
		- 无须建立连接，随时发送随时接收。
		- 尽最大努力交付，不保证可靠性——分组可能丢失、重复、失序、出错。
		- 每个分组携带完整源和目的地址，支持独立路由。
		- 存在排队时延，拥塞时可能被丢弃。
		- 故障适应能力强——可动态更新转发表绕行。
		- 资源利用率高——链路共享，多会话同时通信。

数据报服务与虚电路服务对比：

| 对比项 | 数据报服务 | 虚电路服务 |
| --- | --- | --- |
| 连接的建立 | 不需要 | 必须有 |
| 目的地址 | 每个分组有完整目的地址 | 仅建立阶段使用，之后用 VCID |
| 路由选择 | 每个分组独立选路 | 同一条虚电路按同一路由转发 |
| 分组顺序 | 不保证有序到达 | 保证有序到达 |
| 可靠性 | 不保证，由用户保证 | 由网络自身保证 |
| 故障适应性 | 强，可绕行 | 差，故障中断所有虚电路 |
| 差错处理/流量控制 | 由用户主机负责 | 可由网络或用户负责 |

#### SDN 的基本概念

- **定义**：软件定义网络，核心是控制平面与数据平面的解耦——控制平面集中化，数据平面分布式部署。
	- **传统网络**：每台路由器同时承担控制与转发功能。
	- **SDN 架构**：路由器仅保留数据平面（接收分组、匹配流表、执行转发），不再运行路由协议。控制功能由逻辑集中式的远程控制器统一承担。
- **三类接口**：
	- **北向接口**：面向上层应用提供标准化 API，开发者可构建定制化网络应用，无须关注底层转发设备细节。
	- **南向接口**：实现控制器与转发设备的双向通信（如 OpenFlow 协议），控制器统一管理异构硬件，将上层应用逻辑下发至数据平面。
	- **东西向接口**：用于控制器集群内部通信，提升控制平面的可靠性和可拓展性。
- **优势**：
	- 集中控制与分布转发——控制平面具备全局视图便于统一优化，数据平面分布式高速转发保障性能。
	- 灵活可编程性——通过标准化接口以软件方式动态定义网络行为。
	- 降低成本——控制与转发分离使硬件设备简化。
- **挑战**：
	- 安全风险——集中化控制器易受攻击，一旦崩溃影响整个网络。
	- 性能瓶颈——网络规模扩大后控制器可能成为瓶颈。

#### 拥塞控制

- **定义**：网络中出现过量分组超过其处理能力时引发的性能下降现象称为拥塞。拥塞控制的核心是及时感知拥塞并采取措施，避免因缓冲区溢出导致分组丢失。
- **判断依据**（吞吐量与网络负载的关系）：
	- 负载增大但吞吐量增长甚微 → 轻度拥塞。
	- 负载增大但吞吐量反而下降 → 严重拥塞。
- **拥塞控制 vs 流量控制**：
	- **流量控制**：管理发送方与接收方之间的点对点通信，抑制发送速率确保接收方能及时处理。
	- **拥塞控制**：全局性过程，确保网络能有效承载当前流量，涉及所有主机、路由器及各类因素。仅靠增加资源无法根本解决。
- **两种方法**：
	- **开环控制**：系统设计时预先考虑可能导致拥塞的因素，通过静态策略防止拥塞发生。不依赖当前网络状态。典型手段包括确定何时接收新流量、何时丢弃分组、采用何种调度策略等。
	- **闭环控制**：监测网络运行状态，动态检测拥塞的位置与程度，反馈至控制节点调整网络运行。基于反馈的动态方法。

#### IP多播

- **定义**：让源主机一次发送的单个分组抵达用一个组地址标识的若干目的主机（一对多通信）。多播数据报的源地址是源主机 IP，目的地址是 D 类 IP 地址。
	- 在一对多通信中显著节省网络资源——单播需发送 90 份，多播仅发送 1 份，在分岔节点复制转发。
	- 多播数据报也是"尽最大努力交付"；多播地址只能用于目的地址，不能用于源地址；对多播数据报不产生 ICMP 差错报文。
	- 多播仅适用于 UDP（TCP 是面向连接的一对一协议）。

- **IP 多播地址（D 类地址）**：前四位 1110，范围 224.0.0.0 ~ 239.255.255.255，每个地址标志一个多播组。

- **硬件多播（以太网）**：IANA 保留以太网多播地址范围 01-00-5E-00-00-00 ~ 01-00-5E-7F-FF-FF。D 类 IP 地址的低 23 位映射到以太网多播地址的后 23 位，高 5 位无法映射 → 32 个不同的 IP 多播地址映射到同一 MAC 地址（多对一映射）。主机收到后须在 IP 层根据目的 IP 地址过滤。

- **IGMP（网际组管理协议）**：使本地多播路由器获知本局域网上主机加入/退出多播组的信息。仅作用于本地子网。报文封装在 IP 数据报中（协议字段 2）。
	- **第一阶段**：主机加入多播组时，向该组多播地址发送 IGMP 报文声明成为成员。
	- **第二阶段**：路由器周期性地查询本地局域网主机，若某组连续多次无响应则判定已无成员。

- **多播路由协议**：构造以源主机为根的多播转发树，使分组在每条链路上仅传送一次。不同的多播组对应不同的转发树；同一多播组若源不同则转发树也不同。

#### 移动 IP

- **定义**：允许移动主机在切换网络接入点时仍保持其永久 IP 地址不变的网络协议机制，对上层的 TCP 连接完全透明。
	- 若移动后通过 DHCP 获取新 IP 重新接入，则不属于移动 IP（因为 IP 已改变，TCP 连接会中断）。

- **三种功能实体**：
	- **移动节点**：拥有永久 IP 地址、可在不同网络间移动的主机。
	- **归属代理（本地代理）**：连接在归属网络上的路由器，负责截获并转发发往移动节点的数据。
	- **外地代理**：连接在被访网络上的路由器，协助移动节点接收数据。

- **关键概念**：
	- **永久地址（归属地址）**：移动站的初始 IP 地址。
	- **归属网络**：移动站初始所在的网络。
	- **转交地址**：外地代理为移动站分配的临时地址，属于被访网络。

- **基本通信流程**：
	1. **本地通信**：移动站位于归属网络时，按传统 TCP/IP 方式直接通信。
	2. **漫游与注册**：移动站漫游到被访网络 → 向外地代理登记并获取转交地址 → 外地代理将转交地址注册至归属代理。
	3. **接收数据（B→A）**：归属代理截获发往移动站的 IP 分组 → 构建 IP 隧道封装转发至外地代理 → 外地代理解封后交付给移动站。
	4. **发送数据（A→B）**：移动站直接通过被访网络的外地代理转发，使用永久地址作为源地址，无须经过归属代理。
	5. **移动与返回**：移动站再次漫游时新外地代理更新转交地址；返回归属网络后注销转交地址，恢复本地直连。

#### 冲突域和广播域

- **冲突域**：连接到同一物理介质上的所有节点集合，节点间存在介质争用。属于物理层概念。第 1 层设备（集线器/中继器）不能划分冲突域；第 2 层（网桥/交换机）和第 3 层（路由器）可划分冲突域。
- **广播域**：能接收同一广播帧的所有节点集合。属于数据链路层概念。第 1 层和第 2 层设备所连节点通常在同一广播域；第 3 层设备（路由器）可划分广播域。

| 设备 | 冲突域 | 广播域 |
| --- | --- | --- |
| 集线器 | 不划分（同一冲突域） | 不划分（同一广播域） |
| 交换机 | 划分（每端口一冲突域） | 不划分（同一广播域） |
| 路由器 | 划分 | 划分 |

#### 路由器的组成和功能

- **功能**：互连不同的网络（异构网络）并转发分组。可用于连接不同的 LAN、VLAN、WAN 或实现 LAN 与 WAN 互连。转发决策基于 IP 地址，端口同时具备物理层和数据链路层处理能力。

- **结构组成**：
	- **路由选择部分（控制平面）**：路由选择处理机，根据路由协议（RIP/OSPF）构建并维护路由表。
	- **分组转发部分（数据平面）**：
		- **交换结构**：路由器内部连接输入与输出端口的高速通路，负责根据转发表将分组快速转发至合适输出端口。
		- **输入端口**：物理层接收比特流 → 数据链路层提取帧并剥离帧头帧尾 → 网络层根据目的 IP 查找转发表 → 送至交换结构。若为路由协议分组则交由路由选择处理机。
		- **输出端口**：从交换结构接收分组，封装后发送。
	- 每个端口设有缓冲区用于暂存分组和差错检测。

#### 路由表与分组转发

- **路由表表项**（标准格式）：目的网络 IP 地址、子网掩码、下一跳 IP 地址、接口。可配置默认路由（0.0.0.0/0）。
- **路由表 vs 转发表**：路由表由路由算法生成，侧重路由计算优化；转发表由路由表导出，侧重高速查找优化。
- **转发 vs 路由选择**：转发是单个路由器根据转发表将分组从合适端口送出的过程（数据平面）；路由选择是多个路由器通过路由协议协同工作，动态生成路由表的过程（控制平面）。

- **主机间跨网络发送 IP 数据报流程**（H1 → H2，不同子网）：
	1. H1 判断 H2 不在同一子网（子网掩码与 H2 的 IP"与"的结果不等于本网络地址），无法直接交付。
	2. H1 通过 ARP 获得默认网关（路由器 R1）的 MAC 地址，封装帧发送至 R1。
	3. R1 收到帧后剥离帧头帧尾得到 IP 数据报，根据目的 IP 查找路由表，得到下一跳。
	4. R1 通过 ARP 获得 H2 的 MAC 地址，封装帧发送到目的子网。
	5. H2 收到帧后剥离帧头帧尾得到 IP 数据报。
