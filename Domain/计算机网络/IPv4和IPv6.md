## 一句话定位

IPv4 是互联网核心的网络层协议，定义数据传送的基本单元——IP 分组及其格式，规定分组处理与路由选择规则，通过 IP 地址实现全球统一的寻址体系。IPv6 通过 128 位地址空间从根本上解决地址耗尽问题，并优化首部格式、增强安全性和即插即用能力。

## 它解决什么问题？

数据链路层仅在同一物理网络内通信，无法跨网络寻址。IPv4 提供全球唯一的 32 位 IP 地址，通过分组封装、分片重组、路由转发、地址解析（ARP）、动态配置（DHCP）和差错报告（ICMP）等机制，实现主机到主机的跨网络通信，并利用 CIDR 和 NAT 缓解地址短缺问题。IPv6 以 128 位地址从根本上解决地址耗尽问题，同时简化首部、引入流标签和任播等新特性。

## 概念解析

#### IPv4 分组

- **IP 分组格式**：由首部和数据部分组成。首部固定部分 20B，可选字段 1~40B。
	- **版本**（4位）：IPv4 值为 4。
	- **首部长度**（4位）：以 4B 为单位，最常用 20B（值为 5）。首部长度必须为 4B 整数倍。
	- **总长度**（16位）：首部+数据总长度，以 1B 为单位，最大 65535B。受链路 MTU 限制。
	- **标识**（16位）：源主机为每个数据报设置递增标识。分片时所有分片复制该标识，用于重组。
	- **标志**（3位）：DF=1 禁止分片；MF=1 表示还有后续分片，MF=0 表示最后一个分片。
	- **片偏移**（13位）：以 8B 为单位，指出该分片数据在原始数据报中的偏移量。其偏移量不计算首部的字节。
	- **TTL**（8位）：生存时间，每经一个路由器先将TTL减 1，之后判断是否为 0，为0 时丢弃。防止无限循环。
	- **协议**（8位）：指示上层协议（6=TCP，17=UDP）。
	- **首部检验和**（16位）：只检验首部，不含数据。每经一个路由器重新计算。
		- 清零校验和字段，将整个IP首部（通常是20字节）按**16位（2字节）** 为一组进行划分，然后将所有组的值相加。如果首部长度不是16位的整数倍，需要在末尾填充0。
		- 得到的和可能会超过16位（产生进位）。此时需要将**高位的进位不断加到低16位**上，直到最终结果是一个16位的数。
		- 最终结果按位取反，得到校验值
		- 接收方的验证方法与计算过程完全一致，但包含了校验和字段本身。如果最后全1，那么无错
	- **源地址**（4B）、**目的地址**（4B）。

- **IP 数据报分片**：当 IP 数据报总长度超过链路 MTU 时，将其数据部分分割为多个较小的 IP 数据报（分片）。分片可在源主机或中间路由器进行，重组仅在目的主机进行。
	- 分片依据：标识（同属原数据报）、标志（MF 判断是否最后分片）、片偏移（重组顺序）。
	- 除最后一个分片外，其余分片的数据长度必须是 8B 的整数倍（因片偏移以 8B 为单位）。
	- 若分组长度超过MTU，则当 $\mathrm { D F } = 1$ 时，丢弃该分组，并且要用ICMP（终点不可达报文）向源主机报告差错；当 $\mathrm { D F } = 0$ 时，进行分片， $\mathrm { M F } = 1$ 表示后面还有分片。

#### IPv4 地址

- **定义**：32 位全球唯一标识符，为每台主机（或路由器）的每个接口分配。用点分十进制表示（如 192.168.1.1）。
- **分类的 IP 地址**：由网络号和主机号两部分组成。
	- 其中A类地址网络号全0或全1被保留

| 类别  | 前几位 | 最大网络数                         | 默认子网掩码        | 私有地址段                             |
| --- | --- | ----------------------------- | ------------- | --------------------------------- |
| A   | 0   | $2^7-2$（1~126）                | 255.0.0.0     | `10.0.0.0` ~ `10.255.255.255`     |
| B   | 10  | $2^{14}$（128.0~191.255）       | 255.255.0.0   | `172.16.0.0` ~ `172.31.255.255`   |
| C   | 110 | $2^{21}$（192.0.0~223.255.255） | 255.255.255.0 | `192.168.0.0` ~ `192.168.255.255` |

- **特殊 IP 地址**：
	- 主机号全 0：网络地址（标识本网络）。
	- 主机号全 1：直接广播地址（向本网络广播）。
	- 127.x.x.x：环回测试地址，用于本机进程间通信，不发送到物理网络。
	- 0.0.0.0：本网络上的本主机（常用于 DHCP）。
	- 255.255.255.255：受限广播地址，仅在本网络内广播，路由器丢弃该报文。

- **IP 地址特点**：
	- 分等级结构（网络号 + 主机号），便于地址管理和路由聚合。
	- 标识网络接口而非主机——多接口主机需多个 IP 地址。
	- 同一逻辑网络内的主机网络号相同，主机号唯一。
	- 逻辑地址，与底层硬件地址无关。

#### 划分子网

- **定义**：从主机号借用若干位作为子网号，形成三层结构：IP 地址 = {网络号，子网号，主机号}。
	- 对外透明：外部路由器不知内部子网，仍按网络号转发。
	- 内部灵活划分：各子网独立分配地址范围。
	- 划分子网不改变原网络号，无法从 IP 地址本身判断是否划分了子网。
- **子网掩码**：32 位二进制串，1 对应网络号和子网号，0 对应主机号。IP 地址与子网掩码按位与得子网地址。
	- 同一子网内所有主机及路由器接口必须配置相同的子网掩码。
- **网关**：本子网所连路由器接口的 IP 地址，用于跨网络转发。
	- **默认网关**：到当前主机最近路由器的接口IP地址
	- **直接交付**：目的 IP 与子网掩码按位与结果等于本网络前缀 → 同一子网，直接发往目的主机。
	- **间接交付**：否则发往默认网关，由路由器转发。

#### 无分类编址 CIDR

- **定义**：消除传统 A、B、C 类限制，使用灵活的网络前缀（可变长度）。IP 地址 = {网络前缀，主机号}。
- **斜线记法**：IP 地址/前缀长度，如 128.14.32.5/20。前缀长度等价于子网掩码中连续 1 的个数。
- **CIDR 地址块**：网络前缀相同的连续 IP 地址组成地址块。地址总数必为 2 的整数次幂。
	- 由任意一个地址和前缀长度可确定最小地址、最大地址和地址总数。
	- 主机号全 0 和全 1 的地址一般不分配给主机。

- **路由聚合**：将一个大的 CIDR 地址块替代路由表中多个较小的地址块，压缩路由表规模。
	- 示例：206.1.0.0/17 和 206.1.128.0/17 可聚合为 206.1.0.0/16。

- **最长前缀匹配**：目的地址匹配多条路由时，选择网络前缀最长（最具体）的那条路由。
	- 实现时通常将转发表按前缀长度降序排列。

#### 子网划分应用举例

- **定长子网掩码**：每个子网使用相同子网掩码，各子网 IP 地址数量相同，易造成浪费。
	- 例：208.115.21.0/24 划分 4 个 /26 子网，各子网 62 个可用地址。
- **变长子网掩码**：各子网可用不同掩码，地址数量按需分配，减少浪费。
	- 建议从最大子网开始划分，避免地址碎片。
	- 点对点链路传统用 /30（2 个可用地址），最新标准允许用 /31（2 个地址全用，零浪费）。

#### 网络地址转换 NAT

- **定义**：将专用网络中的私有 IP 地址转换为公网 IP 地址，实现与互联网通信。
- **三个私有 IP 地址块**：
	- 10.0.0.0/8（一个 A 类网络）
	- 172.16.0.0/12（16 个连续的 B 类网络）
	- 192.168.0.0/16（256 个连续的 C 类网络）
	- 互联网路由器对目的地址为私有地址的数据报一律不予转发。
- **NAT 工作原理**：NAT 路由器维护 NAT 转换表，映射 {私有 IP:端口} ↔ {全球 IP:端口}。
	- 出站分组：替换源 IP 和源端口。
	- 入站分组：还原目的 IP 和目的端口。
	- 可手工配置静态映射，使内网服务器对外可见。
	- 普通路由器不改变 IP 地址；NAT 路由器会修改源/目的 IP 地址，且涉及传输层端口号。


#### 网络层转发分组的过程

- **核心原则**：基于目的主机所在网络转发，而非基于目的主机（网络数远少于主机数）。
- **转发表项**：（目的网络地址，下一跳地址）。
- **特殊路由**：
	- **特定主机路由**：a.b.c.d/32，为单个主机单独设路由，优先级最高。
	- **默认路由**：0.0.0.0/0，匹配所有未被其他路由覆盖的目的地址，优先级最低。
- **分组转发算法**：
	1. 提取目的 IP 地址 D。
	2. 若存在特定主机路由 D/32，按下一跳转发。
	3. 将路由项的子网掩码与 D 按位与，若结果等于网络前缀则匹配成功，按下一跳转发。
	4. 否则继续检查下一项；遍历完未匹配则使用默认路由；若无默认路由则报告目的不可达。
- **注意**：转发表仅指明下一跳路由器。分组每经一个路由器，重新查表决定下一步，逐跳转发。下一跳的 MAC 地址由 ARP 解析获得。

#### 地址解析协议 ARP

- **IP 地址与硬件地址**：IP 地址是网络层逻辑地址，MAC 地址是数据链路层物理地址。IP 数据报每经一次路由器转发，都被重新封装，MAC 帧源/目的地址随之改变。
- **ARP 工作原理**：每台主机和路由器维护 ARP 高速缓存（ARP 表），存放 IP 地址到 MAC 地址的映射。表项设生存时间，超时自动删除。
	- 同一局域网内：主机 A 查 ARP 缓存找主机 B 的 MAC 地址。未找到则广播 ARP 请求（目的 MAC=FF-FF-FF-FF-FF-FF），主机 B 单播 ARP 响应。双方更新 ARP 缓存。
	- **ARP 仅作用于同一局域网**：跨网通信时，ARP 解析的是下一跳路由器接口的 MAC 地址。
- **4 种典型情况**：
	1. 主机发往本网络另一主机：ARP 解析目的主机 MAC。
	2. 主机发往其他网络主机：ARP 解析默认网关 MAC。
	3. 路由器转发至直连网络主机：ARP 解析目的主机 MAC。
	4. 路由器转发至非直连网络：ARP 解析下一跳路由器 MAC。

#### 动态主机配置协议 DHCP

- **定义**：动态分配 IP 地址的应用层协议，基于 UDP，提供即插即用机制。
- **DHCP 客户需配置的四项**：IP 地址、子网掩码、默认网关、DNS 服务器地址。
- **DHCP 四步交换过程**：
	1. **DHCP Discover**：客户广播（源 0.0.0.0，目的 255.255.255.255），寻找 DHCP 服务器。
	2. **DHCP Offer**：服务器广播，提供 IP 地址等配置信息。可能有多台服务器响应。
	3. **DHCP Request**：客户广播（源 0.0.0.0，目的 255.255.255.255），选择接受某服务器的提供，同时通知其他服务器释放预留地址。
	4. **DHCP ACK**：被选中的服务器广播确认，客户配置生效。
- **租用期**：IP 地址使用时限。过 50% 时客户单播请求续租；过 87.5% 时客户广播请求续租；到期未续则停止使用并重新申请。客户可随时主动释放。
- **采用 UDP 原因**：客户初始无 IP 地址且不知服务器地址，无法建立 TCP；UDP 无连接、支持广播。

#### 网际控制报文协议 ICMP

- **定义**：网络层协议，封装在 IP 数据报中传送。使主机或路由器向源点报告网络中的差错或异常情况。
- **ICMP 差错报告报文**（5 种）：
	- **终点不可达**：路由器或主机无法交付数据报。
	- **时间超过**：TTL 减为 0 被丢弃；或分片重组超时。
	- **参数问题**：数据报首部字段值不正确。
	- **改变路由（重定向）**：通知源点改用更优路径。
	- **源点抑制**：拥塞时路由器丢弃数据报，请求源点降低发送速率（新ICMP已不使用）。
	- **不应发送的情形**：对 ICMP 差错报文本身；对第一个分片后的后续分片；对多播/广播地址；对特殊地址（127.0.0.0 或 0.0.0.0）。
- **ICMP 询问报文**（2 种）：
	- **回送请求和回答**：测试目的主机是否可达。
	- **时间戳请求和回答**：估算往返时延。
- **典型应用**：
	- **PING**：利用 ICMP 回送请求/回答报文，测试两台主机间的连通性。
	- **Traceroute/Tracert**：逐步增大 TTL 值，触发沿途路由器返回 ICMP 时间超过报文，追踪分组经过的路由路径。
#### IPv6

- **IPv6 设计动机**：IPv4 地址已于 2011 年耗尽。CIDR 和 NAT 仅延缓了 IPv4 寿命，IPv6 的 128 位地址空间从根本上解决问题。
- **主要特点**：
	- **更大的地址空间**：128 位，地址空间是 IPv4 的 $2^{96}$ 倍。
	- **扩展的地址层次结构**：可划分更多层次，便于路由聚合。
	- **灵活的首部格式**：基本首部固定为 40B，功能通过扩展首部灵活实现，路由器通常不处理扩展首部，提高转发效率。
	- **改进的选项**：选项放在有效载荷中可灵活配置，不像 IPv4 固定在首部可变部分。
	- **允许协议继续扩充**：IPv6 可不断扩展功能，IPv4 功能固定不变。
	- **支持即插即用**：通常无须 DHCP，自动配置 IPv6 地址。
	- **支持资源预分配**：通过流标号支持实时音视频等 QoS 应用。
	- **仅源主机分片**：不允许中间路由器分片，只支持端到端分片，如果对于某链路太大，直接丢弃并发送ICMP报文。
	- **基本首部固定 40B**：IPv4 首部可变（20~60B）。
	- **增强安全性**：身份鉴别和保密由扩展首部提供。

- **IPv6 基本首部格式**：40B 固定，仅含 8 个字段。
	- **版本**（4位）：IPv6 值为 6。
	- **通信量类**（8位）：区分数据报类别或优先级。
	- **流标号**（20位）：标识从特定源到特定终点的一系列数据报，路由器据此提供 QoS 保证。同属一个流的数据报具有相同流标号。
	- **有效载荷长度**（16位）：基本首部之后的字节数（含扩展首部和上层数据），最大 65535B。
	- **下一个首部**（8位）：功能同 IPv4 的协议字段。无扩展首部时标识上层协议；有扩展首部时标识第一个扩展首部的类型。
	- **跳数限制**（8位）：同 IPv4 的 TTL，每经一个路由器减 1，减至 0 丢弃。
	- **源地址**（128位）、**目的地址**（128位）。
- **与 IPv4 首部的对比**：

| IPv4 字段 | IPv6 变化 |
| --- | --- |
| 首部长度 | 取消，基本首部固定 40B |
| 服务类型 | 取消，由优先级和流标号替代 |
| 总长度 | 取消，改用有效载荷长度 |
| 标识/标志/片偏移 | 取消，移至分片扩展首部 |
| TTL | 更名为跳数限制，作用不变 |
| 协议 | 取消，改用下一个首部 |
| 首部检验和 | 取消（传输层已有差错检测） |
| 选项 | 取消，由扩展首部替代 |

- **IPv6 地址**：128 位，采用冒号十六进制记法（8 组 16 位，冒号分隔）。
	- **缩写规则**：
		- **省略前导零**：每组中前面的零可省略，如 000A → A。
		- **双冒号替换连续全零组**：`::` 可替代连续全零组，但一个地址中只能使用一次，如 4BF5:0:0:0:BA5F:39A:A:2176 → 4BF5::BA5F:39A:A:2176。
	- **三种基本目的地址**：
		- **单播**：传统的点对点通信，发送给唯一指定接收方。
		- **多播**：一点对多点，发送给所有加入该多播组的接口（同 IPv4 多播）。
		- **任播**（IPv6 新增）：标识一组接口，数据报仅交付给其中路由距离最近的一个（"一址多用、就近交付"）。
	- **地址分类**：

| 地址类型 | 前缀 | 说明 |
| --- | --- | --- |
| 未指明地址 | ::/128 | 仅用作源地址，表示尚未配置 IP 的主机 |
| 环回地址 | ::1/128 | 同 IPv4 的 127.0.0.1 |
| 多播地址 | FF00::/8 | 占 IPv6 地址空间的 1/256 |
| 本地链路单播地址 | FE80::/10 | 仅用于本地链路内，路由器不转发 |
| 全球单播地址 | 可变 | 使用最多的地址 |
	- **全球单播地址划分**：可用 $n$ 位作为子网前缀 + $(128-n)$ 位接口标识符；也可分三级——全球路由选择前缀 + 子网前缀 + 接口标识符。

- **IPv4 向 IPv6 过渡策略**：
	- **双协议栈**：主机同时安装 IPv4 和 IPv6 两个协议栈，分别配置两类地址。通过 DNS 获知目的地址类型，选择对应协议通信。
	- **隧道技术**：IPv6 数据报进入 IPv4 网络时，整个封装为 IPv4 数据报的数据部分；离开 IPv4 网络后解封装，交由 IPv6 处理。
