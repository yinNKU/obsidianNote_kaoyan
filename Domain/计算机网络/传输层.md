## 一句话定位

传输层为运行在不同主机上的应用进程提供端到端的逻辑通信，通过 UDP 和 TCP 分别提供无连接不可靠服务和面向连接可靠服务，向上层屏蔽底层网络的复杂性。

## 它解决什么问题？

网络层仅提供主机之间的通信（IP 数据报交付到主机），但通信的实质是主机中的进程之间的通信。传输层解决：① 将数据交付给正确的应用进程（端口与复用/分用）；② 为应用层提供可靠或不可靠的端到端传输服务；③ 对整条报文进行差错检测；④ 通过流量控制和拥塞控制管理数据传输速率。

## 概念解析

#### 传输层功能与服务

- **传输层功能**：
	- **进程间逻辑通信**：通信的真正端点是主机中的进程，而非主机本身。传输层向上层屏蔽底层网络细节。
	- **复用与分用**：复用——发送方多个应用进程使用同一传输层协议传送数据；分用——接收方传输层根据端口将数据交付给对应应用进程。
	- **差错检测**：对整条报文（首部+数据）进行检验。TCP 发现错误要求重传，UDP 发现错误直接丢弃。
	- **提供面向连接（TCP）和无连接（UDP）服务**。

- **端口**：传输层与应用层的交互接口，长 16 位。
	- **熟知端口（0~1023）**：由 IANA 分配，如 FTP(21)、TELNET(23)、SMTP(25)、DNS(53)、TFTP(69)、HTTP(80)、SNMP(161)。
	- **登记端口（1024~49151）**：需在 IANA 登记以避免冲突。
	- **客户端端口（49152~65535）**：临时分配，通信结束后回收，又称短暂端口号。
	- 端口号仅具有本地意义，不同主机的相同端口号无关联；UDP 和 TCP 端口号相互独立。

- **套接字（Socket）**：IP 地址 + 端口号，唯一标识网络中某台主机上的一个应用进程。一条 TCP 连接由通信双方的两个套接字唯一确定。

- **无连接 vs 面向连接服务**：

| 特性 | UDP | TCP |
| --- | --- | --- |
| 连接建立 | 不需要 | 需要（三次握手） |
| 可靠交付 | 不可靠 | 可靠（无差错、不丢失、不重复、按序） |
| 通信方式 | 一对一、一对多、多对多 | 仅一对一 |
| 首部开销 | 8B | 最小 20B |
| 流量控制 | 无 | 有（滑动窗口） |
| 拥塞控制 | 无 | 有 |
| 适用场景 | 实时应用、DNS、DHCP | FTP、HTTP、SMTP |

#### UDP

- **特点**：① 无连接（无建立时延）；② 面向报文（保留报文边界，一次发一个完整报文）；③ 首部仅 8B；④ 支持一对多、多对多通信；⑤ 无拥塞控制。
	- 应用需自行处理报文大小：太长则 IP 分片，太短则首部开销占比大。

- **UDP 首部格式（8B = 4 字段 × 2B）**：
	- 源端口、目的端口、长度（最小值 8）、检验和。
	- 目的端口不存在时，丢弃报文并由 ICMP 发送"端口不可达"差错报文。

- **UDP 检验和**：
	- 计算时在 UDP 数据报前增加 12B **伪首部**（含源 IP、目的 IP、协议字段 17、UDP 长度），伪首部不发送也不接收。
	- 计算过程：① 检验和字段置 0；② 将伪首部与 UDP 数据报视为 16 位字序列；③ 若数据长度为奇数字节则补 0；④ 按二进制反码求和；⑤ 结果取反码填入检验和。
	- 接收方同样组合伪首部+数据报计算，结果为全 1 则无差错。
	- **二进制反码求和规则**：从低位逐列相加（0+0=0, 0+1=1, 1+1=0 进位 1），最高位进位回卷至最低位。
	- 伪首部可检测 IP 首部中的源/目的地址是否在传输中被改变。

#### TCP 特点与报文段

- **TCP 特点**：面向连接、仅一对一、可靠交付、全双工、面向字节流（不保留报文边界，根据窗口和拥塞程度动态决定报文段长度）。

- **TCP 首部格式（最小 20B）**：
	- **源端口/目的端口**：各 2B。
	- **序号（4B）**：本报文段发送数据的第一个字节的序号，范围 $0\sim2^{32}-1$，模 $2^{32}$ 运算。
	- **确认序号（4B）**：期望收到对方下一个报文段的第一个数据字节的序号，表示到该值减 1 为止的数据已正确接收。
	- **数据偏移（4 位）**：TCP 首部长度，单位 4B，最小 5（20B），最大 15（60B）。
	- **标志位（各 1 位）**：
		- **URG**：紧急指针字段有效。
		- **ACK**：确认序号有效（连接建立后所有报文段均置 1）。
		- **PSH**：接收方应尽快交付给应用进程。
		- **RST**：连接严重差错，必须释放重连。
		- **SYN**：连接请求（SYN=1,ACK=0）或连接接受（SYN=1,ACK=1）。
		- **FIN**：释放连接。
	- **窗口（2B）**：接收方当前还能接收的最大数据量（流量控制）。
	- **检验和（2B）**：检验首部+数据，计算前加 12B 伪首部（协议字段为 6）。
	- **紧急指针（2B）**：URG=1 时有效，指出紧急数据字节数。
	- **选项（最长 40B）**：如 MSS、窗口扩大、时间戳等。
	- **填充**：确保首部为 4B 整数倍。

#### TCP 连接管理

- **三次握手（建立连接）**：
	1. **客户→服务器**：SYN=1, seq=x（初始序号）。客户进入 SYN-SENT。**不携带数据，消耗一个序号**。
	2. **服务器→客户**：SYN=1, ACK=1, seq=y, ack=x+1。服务器进入 SYN-RCVD。**不携带数据，消耗一个序号**。
	3. **客户→服务器**：ACK=1, seq=x+1, ack=y+1。可携带数据（若不携带则不消耗序号）。客户进入 ESTABLISHED，服务器收到后也进入 ESTABLISHED。

- **四次挥手（释放连接）**：
	1. **客户→服务器**：FIN=1, seq=u（主动关闭）。客户进入 FIN-WAIT-1。**消耗一个序号**。
	2. **服务器→客户**：ACK=1, seq=v, ack=u+1。服务器进入 CLOSE-WAIT。客户收到后进入 FIN-WAIT-2。此时连接**半关闭**——客户→服务器方向已关闭，服务器仍可发送数据。
	3. **服务器→客户**：FIN=1, ACK=1, seq=w, ack=u+1。服务器进入 LAST-ACK。
	4. **客户→服务器**：ACK=1, seq=u+1, ack=w+1。客户进入 TIME-WAIT（等待 2MSL），服务器收到后进入 CLOSED。客户等待 2MSL 后进入 CLOSED。
	- **2MSL 目的**：确保最后一个 ACK 到达对方；使本连接中所有滞留报文段从网络中消失。
	- **保活计时器**：服务器每收到数据重置；超时则每 75s 发探测报文段，10 次无响应则关闭连接。

#### TCP 可靠传输

- **序号**：对字节流中的每个字节依次编号（而非对报文段编号），序号字段值指本报文段第一个数据字节的序号。

- **确认（累积确认）**：确认序号为第一个未收到字节的序号（即期望收到的下一个序号）。可捎带确认。

- **超时重传**：每发送一个报文段设置超时计时器，到期未收到确认则重传。RTO 根据自适应算法基于加权平均 RTT 动态调整。

- **冗余 ACK 与快速重传**：接收方收到失序报文段时立即发送对最后一个按序到达报文段的重复确认。发送方**连续收到 3 个冗余 ACK** 则判定报文段丢失并立即重传（无须等待超时）。

#### TCP 流量控制

- **滑动窗口机制**：接收方将接收窗口 rwnd 写入 TCP 首部"窗口"字段，通知发送方其可用缓存大小。发送方的发送窗口不能超过 rwnd。
	- **发送窗口上限 = min[rwnd, cwnd]**
- **零窗口死锁**：接收方发送零窗口通知后，若后续非零窗口通知丢失，双方将相互等待。解决方案：持续计时器——发送方收到零窗口通知后启动，超时则发送零窗口探测报文段，对方确认中携带当前窗口值。

#### TCP 拥塞控制

- **四种算法**：慢开始、拥塞避免、快重传、快恢复。
	- 发送窗口上限 = min[rwnd, cwnd]

- **慢开始**：初始 cwnd=1MSS，每收到一个对新报文段的确认将 cwnd+1，每经过一个 RTT 翻倍（指数增长）。当 cwnd >= ssthresh 时转为拥塞避免。

- **拥塞避免**：每经过一个 RTT 将 cwnd+1（线性增长，加法增大）。

- **网络拥塞处理（超时）**：
	- ssthresh = max(cwnd/2, 2)
	- cwnd = 1
	- 重新执行慢开始

- **快重传**：发送方连续收到 3 个冗余 ACK 时立即重传丢失报文段。

- **快恢复**：收到 3 个冗余 ACK 时：
	- ssthresh = cwnd/2
	- cwnd = ssthresh
	- 直接进入拥塞避免阶段（不重置为 1）

- **拥塞控制流程图**：
	- **超时** → 慢开始（ssthresh=cwnd/2, cwnd=1）
	- **3 冗余 ACK** → 快恢复（ssthresh=cwnd/2, cwnd=ssthresh → 拥塞避免）
