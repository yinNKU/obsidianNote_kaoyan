## 一句话定位
操作系统的运行环境由内核态与用户态的双重模式、中断/异常机制以及系统调用共同构成，确保系统安全、高效地运行。
可参考 [[异常和中断]]

## 它解决什么问题？
隔离用户程序与核心系统资源，通过受控入口（中断/异常/系统调用）实现用户态到内核态的安全切换，防止非法操作破坏系统。

## 主要概念
内核、用户态、内核态、特权指令、中断、异常、系统调用、陷入指令

> **缩写对照**
> - **PCB**：Process Control Block，进程控制块
> - **PC**：Program Counter，程序计数器
> - **PSW**：Program Status Word，程序状态字

## 概念解析

#### 操作系统内核
- **定义**：将与硬件紧密相关、运行频率较高的模块集中置于紧靠硬件的层次并常驻内存，这部分核心组件称为内核。
- **支撑功能**：
	- **时钟管理**：计时、产生定时中断，用于时间片轮转、实时任务调度、作业运行进度衡量。
	- **中断机制**：允许 CPU 在 I/O 期间执行其他指令，保存现场、转移控制权、恢复现场。
	- **原语**：若干条指令组成的原子操作，执行不可中断（通过关中断实现），如进程切换、资源分配。
- **资源管理功能**：进程管理（PCB 等）、存储器管理（分配/回收/地址映射）、设备管理（分配/缓冲/驱动）。

#### 处理机双重工作模式
- **用户态（目态）**：用户程序运行的模式，访问受限，只能执行非特权指令。
- **内核态（管态/系统态）**：操作系统内核运行的模式，可访问全部地址空间，执行特权指令。
- **模式切换**：
	- 系统引导时硬件从内核态开始，加载 OS 后切至用户态。
	- 发生中断/异常时硬件自动从用户态切至内核态（模式位置 0）。
	- 返回用户态前由内核切换回用户态（模式位置 1）。
- **特权指令**：仅在内核态执行，如启动外设、设置系统时钟、关中断、修改模式位。用户程序试图执行特权指令将触发异常，OS 终止该程序。
- **非特权指令**：可在任意模式执行，一般计算和数据处理，内存访问限于用户地址空间。

#### 中断和异常
- **中断（外中断，Interrupt）**：来自 CPU 外部的事件，如 I/O 完成中断、时钟中断。
	- **可屏蔽中断**：通过 INTR 线发出，可通过屏蔽字实现多重中断。
	- **不可屏蔽中断**：通过 NMI 线发出，紧急硬件故障如电源掉电。
- **异常（内中断，Exception）**：来自 CPU 内部的事件，一旦发生必须立即处理，不可屏蔽。
	- **故障（Fault）**：指令执行引起，如非法操作码、缺页、除零。处理完成后返回第 i 条指令重新执行。
	- **自陷（Trap/陷入）**：事先安排的异常，用于用户态调用内核程序，如系统调用指令。处理完成后返回第 $i+1$ 条指令。
	- **终止（Abort）**：硬件故障使 CPU 无法继续，如控制器出错、存储器校验错。
- **处理过程**：CPU 检测到中断/异常 → 打断当前程序 → 转入处理程序 → 若可恢复则返回原程序，否则终止。
- **中断 vs 子程序调用**：
	- 中断与被中断程序相互独立；子程序与主程序属同一程序。
	- 中断随机产生；子程序调用由 CALL 显式触发、事先安排。
	- 中断需硬件电路支持；子程序调用纯软件实现。
	- 中断入口地址由中断向量表提供；子程序入口由 CALL 地址码指定。
	- 中断需对同时到达的多个请求进行优先级裁决；子程序调用无此操作。

#### 系统调用
- **定义**：操作系统提供给应用程序的接口，是用户态进入内核态的合法途径。凡涉及共享资源的操作（存储分配、I/O、文件管理等）必须通过系统调用。
- **分类**：
	- 设备管理（请求/释放/启动设备）
	- 文件管理（读/写/创建/删除文件）
	- 进程控制（创建/撤销/阻塞/唤醒）
	- 进程通信（消息/信号传递）
	- 内存管理（分配/回收/获取地址空间）
- **与普通过程调用的区别**：
	- 运行状态：系统调用调用者在用户态、被调用者在内核态；普通过程调用在同一特权级。
	- 状态转换：系统调用需陷入指令触发状态切换；普通过程调用直接跳转。
	- 返回机制：系统调用执行后内核可能切换进程；普通过程调用直接返回原调用点。
	- 嵌套限制：系统调用受内核栈空间限制；普通过程调用受用户栈大小限制。
- **处理过程（4 阶段）**：
	1. 传递系统调用号及参数（堆栈或寄存器）。
	2. 执行陷入指令，CPU 从用户态切换至内核态，保存 PC、PSW 及通用寄存器。
	3. 内核根据系统调用号查询系统调用表，定位并执行处理程序。
	4. 恢复现场，切回用户态，从断点继续执行。
- **用户态转内核态的 4 种情形**：
	1. 用户程序请求 OS 服务（系统调用）。
	2. 发生外中断（I/O 完成、时钟信号）。
	3. 执行过程中产生异常（除零、缺页）。
	4. 试图执行特权指令（触发异常）。
