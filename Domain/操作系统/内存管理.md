## 一句话定位

内存管理是操作系统对内存空间的分配、回收、地址转换、扩充和保护等一系列操作的统称，旨在高效利用有限的物理内存，并为多道程序提供安全、独立的运行环境。

## 它解决什么问题？

多道程序环境下多个进程共享主存，若缺乏有效管理，地址空间可能重叠导致数据破坏。内存管理实现：① 为进程分配与回收内存；② 将逻辑地址动态转换为物理地址；③ 通过虚拟存储技术扩充逻辑空间；④ 实现内存共享与保护；⑤ 解决连续分配产生的外部碎片问题。

## 概念解析

#### 内存管理的基本原理

- **逻辑地址 vs 物理地址**：
	- **逻辑地址（虚拟地址）**：编译后各目标模块从 0 开始编址，链接后形成统一的从 0 开始的逻辑地址空间。进程运行时使用的均为逻辑地址，不同进程可有相同逻辑地址（映射到不同物理位置）。
	- **物理地址**：主存中所有物理存储单元的集合。现代系统由 MMU 依据页表在运行时自动完成地址转换，用户程序完全透明。

- **程序的链接**（三种方式）：
	- **静态链接**：运行前将各目标模块及库函数链接成完整装入模块（可执行文件）。需完成地址调整和外部符号解析。缺点：任一模块修改需重新链接整个程序。
	- **装入时动态链接**：装入内存时边装入边链接，遇到外部模块调用时立即查找并装入。优点：便于修改更新，便于实现模块共享。
	- **运行时动态链接**：执行过程中仅当需要调用某未装入模块时才动态加载链接。未使用的模块既不装入也不链接。优点：加快装入过程，节省内存。

- **程序的装入**（三种方式）：
	- 都是连续地址空间，程序物理地址不能分开
	- **绝对装入**：编译时已知程序驻留位置，生成绝对地址的目标代码。仅适用于单道程序环境。
	- **可重定位装入（静态重定位）**：装入时根据内存空闲情况分配连续区域，一次性将所有逻辑地址转换为物理地址。缺点：装入后不能移动，不能动态申请内存。
	- **动态运行时装入（动态重定位）**：装入时不转换地址，推迟到指令执行时由硬件借助重定位寄存器动态计算物理地址。优点：支持程序在内存中移动，便于紧凑消除碎片。
		- 是操作系统为了紧凑碎片，移动程序在内存中的位置，从而获得大区域空闲块，并修改这个程序的重定位寄存器的上下文，便于在切换到这个进程时重定位寄存器的值是新值。

- **内存保护**：
	- **方法一**：上、下限寄存器，CPU 访问地址时与寄存器的值比较判断越界。
	- **方法二**：重定位寄存器（基地址，用于"+"）和界地址寄存器（限长，用于"比"）。逻辑地址先与界地址比较，未越界则加重定位寄存器的值得物理地址。
	- 寄存器的加载必须通过特权指令，仅内核可修改。

- **内存共享**：只有只读区域（可重入代码/纯代码）可共享。每个进程需配备独立私有数据区存放可修改数据。

#### 连续分配管理方式

- **单一连续分配**：内存分为系统区和用户区，用户区仅一道程序独占。优点：简单无外部碎片。缺点：仅单用户单任务，存在内部碎片。
- **固定分区分配**：用户空间划分为若干大小固定分区，每个分区容纳一道作业。
	- 分区可等大或不等大，系统维护分区使用表。
	- **缺点**：产生内部碎片（作业小于分区时空间浪费）；无法支持多进程共享同一区域。
- **动态分区分配（可变分区）**：按进程实际需求动态分配大小恰好匹配的连续空间。
	- **外部碎片**：频繁装入释放后积累大量分散小空闲块。可通过**紧凑**（移动进程合并空闲块）缓解，需支持动态重定位。
	- **回收合并四种情形**：① 回收区与前空闲相邻 → 合并；② 与后空闲相邻 → 合并；③ 与前后均相邻 → 三者合并；④ 不与任何空闲相邻 → 新建表项。

- **动态分区分配算法（顺序搜索）**：

| 算法 | 排序方式 | 核心特点 | 评价 |
| --- | --- | --- | --- |
| 首次适应（First Fit） | 地址递增 | 从链首顺序找第一个满足的分区 | 优先利用低地址，保留高地址大空闲；低地址易积累小碎片 |
| 邻近适应（Next Fit） | 地址递增（循环） | 从上一次查找结束处开始搜索 | 减少低地址重复扫描，但大空闲分布不均 |
| 最佳适应（Best Fit） | 容量递增 | 选择最小的可用分区 | 保留大分区，但产生大量无用小碎片 |
| 最坏适应（Worst Fit） | 容量递减 | 选择最大的可用分区 | 避免小碎片，但大分区被快速消耗 |

- **动态分区分配算法（索引搜索）**：
	- **快速适应（Quick Fit）**：按常用大小分类，索引表管理各链。查找快、无碎片，但回收合并复杂。
	- **伙伴系统（Buddy System）**：所有分区大小为 $2^k$。分配时不断二分至所需大小，回收时若伙伴空闲则合并。伙伴定义：大小相同、地址相邻的两个分区。
	- **哈希算法**：以分区大小为关键字建立哈希函数，快速定位对应空闲链。

#### 基本分页存储管理

- **核心思想**：物理内存划分为固定大小的**页框**（页帧/物理块），进程逻辑地址空间划分为与页框大小相同的**页面**（页）。以页为单位分配内存，消除外部碎片。
	- **页内碎片**：进程最后一页未填满时产生内部碎片，平均约半页。
	- **页面大小**：通常取 2 的整数次幂。过小则页表过长，过大则页内碎片增多。

- **逻辑地址结构**：由页号 P 和页内偏移量 W 组成（一维线性地址）。例如 32 位地址、4KB 页面 → 高 20 位页号，低 12 位偏移。

- **页表**：每个进程一张，按页号顺序排列，每个页表项记录物理块号及状态信息。作用：实现页号到页框号的映射。

- **基本地址变换机构**（由 MMU 硬件自动完成）：
	1. 计算页号 $P = \lfloor A/L \rfloor$、页内偏移 $W = A \% L$。
	2. 判断页号是否越界（$P \geq$ 页表长度 M）。
	3. 查找页表：页表项地址 = 页表始址 $F + P \times$ 页表项长度，取出物理块号 $b$。
	4. 物理地址 $E = b \times L + W$。
	- 无快表时每次访存需 **两次访存**（先查页表，再访问目标）。

- **具有快表（TLB）的地址变换**：
	- **快表**：具有并行查找能力的高速缓冲存储器，缓存当前活跃的页表项。
	- **命中**：直接从快表取物理块号，一次访存即可。
	- **未命中**：访问内存页表取物理块号（两次访存），并将该表项装入快表（满则置换）。
	- 基于局部性原理，TLB 命中率通常 >90%，性能开销控制在 10% 以内。

- **两级页表**（解决单级页表过大的问题）：
	- 问题：32 位系统、4KB 页面、4B 页表项 → 页表有 $2^{20}$ 项，占 4MB 内存且需连续存放。
	- 思路：将页表分页离散存放，再建立外层页表（页目录）索引各页表页。
	- 逻辑地址结构：页目录号（10 位）+ 页号（10 位）+ 页内偏移（12 位）。
	- 地址变换：① 页目录号索引外层页表 → 内层页表地址；② 页号索引内层页表 → 物理块号；③ 拼接偏移。无快表需 **三次访存**。
	- 本质：按需分配页表页，避免为未使用的地址空间预留无用表项。
	- 64 位系统可扩展为三级或四级页表。

#### 基本分段存储管理

- **核心思想**：按程序的逻辑结构（主程序、子程序、栈、数据等）划分为若干大小不等的段，每个段内连续编址，段间不连续。
	- 逻辑地址 = 段号 S + 段内偏移 W（**二维地址**，用户/编译器需显式指定段号）。
	- 动机：支持方便编程、信息保护与共享、动态增长、动态链接。

- **段表**：每个进程一张，每个段表项记录该段的基址和段长。段号作为隐含索引。

- **地址变换**：
	1. 分离段号 S 和段内偏移 W。
	2. 判断段号越界（$S \geq$ 段表长度 M）。
	3. 查段表得该段段长 C，判断段内越界（$W \geq C$）。
	4. 物理地址 $E = b + W$（基址 + 偏移）。

- **分页 vs 分段对比**：

| 对比项 | 分页 | 分段 |
| --- | --- | --- |
| 单位性质 | 物理单位，系统管理 | 逻辑单位，用户/程序视角 |
| 大小 | 固定，由系统决定 | 不固定，取决于逻辑结构 |
| 地址空间 | 一维（线性地址） | 二维（段号 + 偏移） |
| 透明性 | 对用户透明 | 对用户可见 |
| 共享 | 需多个页表项指向共享页框 | 只需一个段表项指向共享段 |
| 目的 | 提高内存利用率 | 满足编程/共享/保护需求 |

- **段的共享与保护**：同一共享段在不同进程可有不同段号。系统维护共享段表（含 count 计数），仅当 count=0 时回收。保护方式：地址越界保护 + 存取控制保护。

#### 段页式存储管理

- **核心思想**：分段 + 分页结合。先按逻辑结构分段，每段再划分为固定大小的页。内存分配以页为单位。
	- 逻辑地址 = 段号 S + 页号 P + 页内偏移 W（**二维地址**）。
	- 每个进程一张段表，每个段对应一张页表。
	- 无快表时每次访存需 **三次访存**（段表 → 页表 → 目标）。
	- 段页式地址空间对用户是二维的（段可见，页透明）。

#### 虚拟内存的基本概念

- **传统存储管理的缺陷**：
	- **一次性**：作业必须全部装入内存后才能运行，大作业无法运行，并发度下降。
	- **驻留性**：作业装入后一直驻留至结束，即使被阻塞也占据内存。

- **局部性原理**（虚拟内存的理论基础）：
	- **时间局部性**：某条指令/数据被访问后不久很可能再次被访问（循环、重复操作）。
	- **空间局部性**：访问某存储单元后，附近单元也很可能被访问（顺序执行、数组连续存储）。

- **虚拟存储器定义**：基于局部性原理，仅将当前运行所需的少数页面装入内存即可启动程序。执行中若访问的信息不在内存，由 OS 自动从外存调入；内存不足时将暂时不用的页面换出到外存。使用户获得逻辑上远大于物理内存的地址空间。
	- **三个特征**：多次性（分次调入）、对换性（换入换出）、虚拟性（逻辑扩充）。

- **三种实现方式**：请求分页、请求分段、请求段页式。需要硬件支持：足够的内存和外存、页表/段表机制、缺页中断机构、地址变换机构。

#### 请求分页管理方式

- **页表新增字段**（在基本页表基础上）：
	- **状态位 P**：标记该页是否已调入内存，决定是否触发缺页中断。
	- **访问字段 A**：记录访问次数或时间间隔，供置换算法参考。
	- **修改位 M（脏位）**：标记调入后是否被修改过，决定换出时是否需写回外存。
	- **外存地址**：指示该页在外存中的存放位置。

- **缺页中断**：当访问的页面不在内存时触发。
	- **特点**：在指令执行期间触发（非执行完毕后）；一条指令可能引发多次缺页中断（如 copy A to B 最多 6 次）。
	- **处理流程**：保护 CPU 现场 → 分析中断原因 → 分配页框/置换页面 → 从外存调入页面 → 更新页表和快表 → 恢复现场，重新执行指令。

- **请求分页地址变换流程**：
	1. 检索快表（TLB）→ 若命中则取物理块号，置访问位，写操作置修改位。
	2. 快表未命中 → 访问页表。若页面在内存（状态位=1）→ 取物理块号，装入快表。
	3. 页面不在内存 → 触发缺页中断，从外存调入（必要时先置换），更新页表和快表。
	4. 拼接物理地址访存。

#### 页框分配与置换策略

- **最小页框数**：保证进程正常运行所需的最少页框数，与硬件结构有关。简单机器至少 2 页（指令+数据），功能较强的机器可能需 6 页。

- **驻留集**：进程启动时分配给它的页框集合。太小则缺页率高，太大则浪费内存、降低并发。

- **三种分配/置换策略**：

| 策略 | 分配方式 | 置换范围 | 特点 |
| --- | --- | --- | --- |
| 固定分配局部置换 | 固定数量 | 自身页框 | 数量恒定，过少则频繁缺页，过多浪费 |
| 可变分配全局置换 | 动态调整 | 全局页框 | 灵活但活跃进程可能膨胀抢占 |
| 可变分配局部置换 | 动态调整 | 自身页框 | 根据缺页率调整，兼顾并发与缺页率 |

- **调入时机**：
	- **预调页**：一次调入若干相邻页面，用于进程首次调入。
	- **请求调页**：缺页时每次调入一页（当前主流，实现简单）。

- **调入来源**：对换区（连续分配，I/O 快）vs 文件区（离散分配）。未修改页面从文件区调入无需写回；修改页面换出时写回对换区。

#### 页面置换算法

- **OPT（最佳置换算法）**：淘汰以后永不使用或最长时间内不再被访问的页面。理论最低缺页率，无法实现，用于评价其他算法。

- **FIFO（先进先出置换算法）**：淘汰最早进入内存的页面。实现简单但性能较差，可能产生 **Belady 异常**——分配的物理块增多缺页次数反而上升。

- **LRU（最近最久未使用置换算法）**：淘汰最近最长时间未使用的页面。性能接近 OPT，需硬件支持记录访问时间，开销较大。

- **简单 CLOCK 算法（NRU）**：为每页设访问位。页面组织成循环队列，替换指针循环扫描：访问位为 0 则淘汰，为 1 则置 0 并继续扫描。近似 LRU 但开销小。

- **改进型 CLOCK 算法**：结合访问位 A 和修改位 M，将页面分四类：
	- 1 类 (A=0, M=0)：最佳淘汰页
	- 2 类 (A=0, M=1)：次佳淘汰页
	- 3 类 (A=1, M=0)：可能再次访问
	- 4 类 (A=1, M=1)：可能再次访问
	- 置换过程：第一轮找 1 类 → 第二轮找 2 类（同时清 A）→ 若均失败则复位指针、清所有 A，重复第一轮。优先淘汰未修改页面，降低磁盘 I/O。

| 算法 | 核心策略 | 是否有 Belady 异常 | 实现开销 |
| --- | --- | --- | --- |
| OPT | 淘汰未来最久不用的 | 否 | 无法实现 |
| FIFO | 淘汰最早进入的 | 是 | 低 |
| LRU | 淘汰最久未使用的 | 否 | 高 |
| 简单 CLOCK | 扫描循环队列淘汰 A=0 的 | 否 | 中 |
| 改进型 CLOCK | 优先淘汰 A=0,M=0 的 | 否 | 较高 |

#### 抖动和工作集（不考）

- **抖动（颠簸）**：刚换出的页面马上又要换入，刚换入的又立即换出，导致磁盘 I/O 频率急剧上升，CPU 利用率趋近于零。根本原因是分配给进程的物理块过少。
- **工作集**：在某时间间隔内进程实际访问过的页面集合。驻留集不应小于工作集，否则进程将频繁缺页。

#### 页框回收

- **页面缓冲算法**：在原置换算法基础上增设两个链表：
	- **空闲页面链表**：换出未修改页面时不写回磁盘，直接挂在链表末尾。若后续再次访问相同页面可直接复用，避免磁盘读入。
	- **修改页面链表**：换出已修改页面时暂不写回磁盘，积累足够数量后批量写回，减少磁盘 I/O 频率。
- **守护进程 kswapd**：定期检查内存使用，空闲页框低于阈值时主动回收。不可回收页框：内核栈、内核代码/数据段等。可回收页框：进程代码/数据段、文件映射页、共享内存页等。

#### 内存映射文件

- **定义**：将磁盘文件与进程的虚拟地址空间建立直接映射，进程可像访问内存一样读写文件。映射时不立即加载文件内容，首次访问时才按需调入页面。
- **共享内存实现**：将同一文件映射到多个进程的虚拟地址空间，页表将这些虚拟页映射到相同物理页，一个进程写入后另一进程可立即看到更新结果，无须额外复制或同步。
- **优点**：编程简单（直接按内存方式读写）；便于多进程共享同一磁盘文件。

#### 虚拟存储器性能影响因素

- **页面大小**：过大则页内碎片增多，过小则页表过长、缺页率上升。
- **物理块数**：超过阈值后继续增加对缺页率改善甚微。
- **页面置换算法**：好的算法（LRU、CLOCK）可降低缺页率。
- **修改页面写回频率**：批量写回优于每页即写即回。
- **程序局部化程度**：局部性越好，缺页率越低（如数组按行存储、按行访问）。
