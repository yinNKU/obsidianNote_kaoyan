## 一句话定位

文件管理是操作系统对文件（有名称的信息集合）进行组织、存储、共享和保护的一系列机制的统称，通过目录结构、物理分配、存储空间管理和虚拟文件系统为用户和进程提供透明高效的文件访问接口。

## 它解决什么问题？

用户需要长期保存、共享和按名存取大量信息，而磁盘等存储设备的物理细节（扇区、柱面）对用户过于复杂。文件管理解决：① 将用户按逻辑结构组织的信息映射到物理存储设备；② 提供目录结构支持按名存取与高效检索；③ 实现文件共享与保护；④ 管理磁盘空闲空间，提高存储利用率；⑤ 通过 VFS 屏蔽不同文件系统的差异。

## 概念解析

#### 文件与文件系统基础

- **文件**：具有文件名的一组相关信息的集合。在操作系统中，文件是信息存储的基本单位，也是进程间共享信息的载体。
- **文件属性**：名称、标识符（系统内唯一）、类型、位置（存储设备中的路径和指针）、大小、保护信息、时间戳（创建/修改/访问时间）。
- **文件分类**：
	- **按用途**：系统文件、用户文件、库文件。
	- **按数据形式**：源文件、目标文件、可执行文件。
	- **按存取控制**：只读、读写、可执行、不保护。
	- **按组织形式**：普通文件、目录文件、设备文件（Unix 风格将设备视为文件）。

- **文件系统层次结构**（从底层到上层）：
	1. **I/O 控制层**：设备驱动程序，直接与硬件交互，处理中断。
	2. **基本文件系统（物理 I/O 层）**：处理内存与磁盘间的数据块交换，以物理块为单位。
	3. **文件组织模块**：将逻辑记录地址转换为物理块号，管理逻辑块到物理块的映射。
	4. **逻辑文件系统**：管理文件元数据（FCB、目录结构、文件保护），维护文件系统数据结构。

- **文件逻辑结构**：
	- **顺序文件**：记录按顺序存放，存取速度快，但插入/删除记录需移动大量数据。可变长记录无法随机存取。适合批量处理。
	- **索引文件**：为每个文件建立索引表（键-指针），支持直接存取和动态增删，但增加索引开销。
	- **索引顺序文件**：记录按顺序组织，再为记录组建立索引。结合顺序和索引的优点，既支持顺序存取也支持随机存取。
	- **直接文件（散列文件）**：通过哈希函数将记录键映射到物理地址。存取快但可能产生冲突。
	- **记录定长 vs 变长**：定长记录易于计算位置，变长记录需要额外管理。

#### FCB 与 inode

- **FCB（文件控制块）**：文件系统为每个文件维护的数据结构，集中存放文件的全部属性信息。典型 FCB 包含：文件名、文件类型、物理位置（分配方式及盘块号）、逻辑结构、保护信息、时间戳、文件长度等。
	- FCB 存放在目录中，叫文件目录项，目录本身也是一个文件（目录文件）。

- **inode（索引节点）**：Unix/Linux 系统中用于描述文件元数据的数据结构，与文件名分离存放。
	- **磁盘 inode**：存储在磁盘上的 inode 区域，文件创建时分配，文件删除时回收。包含文件主标识、文件类型、存取权限、物理地址、文件长度、链接计数等。
	- **内存 inode**：文件被打开时从磁盘 inode 加载到内存，增加内存专用字段（如 inode 编号、引用计数、所属文件系统等）。
	- **优势**：将文件名与文件元数据分离，支持硬链接（多个文件名指向同一 inode），目录项更小，检索效率高。

#### 目录结构

- **目录**：由若干目录项组成的文件，每个目录项对应一个文件。目录项通常包含文件名和指向 FCB/inode 的指针。
- **单级目录**：所有文件在同一目录下。结构简单，但不允许重名，不支持文件分组。
- **两级目录**：每个用户一个独立目录（UFD），系统维护主文件目录（MFD）。不同用户可重名，搜索效率提高，但用户内无法再分组。
- **树形目录**：用户可自由创建子目录，文件路径分隔层次。支持绝对路径（从根开始）和相对路径（从当前目录开始），检索高效，用户可灵活组织。现代操作系统普遍采用。
	- **当前目录（工作目录）**：进程当前所在的目录，通过相对路径减少路径字符串长度。
- **无环图目录**：在树形目录基础上允许不同目录指向同一文件（共享）。实质是指针/链接而非复制，可缓解"别名"问题。

#### 文件物理结构

- **连续分配**：每个文件在磁盘上占用一组连续的物理块。实现简单，支持顺序和随机存取。**缺点**：产生外部碎片；文件创建时需预知大小，动态增长困难。
- **链接分配**：每个文件对应一组离散的物理块，通过指针链接，都不支持对文件的随机存取。
	- **隐式链接**：每个盘块携带指向下一块的指针，只能顺序存取，可靠性差（指针损坏则后续块丢失）。
	- **显式链接（FAT）**：所有链接指针集中存放在一张文件分配表（FAT）中，每个表项存放下一个盘块号。
		- FAT 在系统启动时读入内存，检索快，支持直接访问某个块，但不支持对文件的随机存取
		- 缺点：FAT 随磁盘容量增长急剧膨胀。

- **索引分配**：每个文件建立一个索引数据块（索引块），记录所有物理块号。
	- **单级索引**：一个索引块管理所有数据块。支持直接存取，但小文件浪费索引块空间。
	- **多级索引**：索引块本身也建立索引，逐级指向下级索引块。适合大文件，访问次数随级数增加。
	- **混合索引（UNIX 13 地址项）**：inode 中设置 13 个地址项，兼顾小文件和大文件：
		- 前 10 个为**直接地址项**：直接指向数据块（小文件零索引开销）。
		- 第 11 个为**一次间接地址项**：指向一个索引块（管理更多块）。
		- 第 12 个为**二次间接地址项**：指向两级索引。
		- 第 13 个为**三次间接地址项**：指向三级索引（处理超大文件）。
		- 设每个盘块大小为 4KB，每个盘块号占 4B → 每个索引块可存放 1024 个盘块号：
			- 直接：10 × 4KB = 40KB
			- 一次间接：1024 × 4KB = 4MB
			- 二次间接：1024 × 1024 × 4KB = 4GB
			- 三次间接：1024 × 1024 × 1024 × 4KB = 4TB


| 分配方式      | 顺序存取 | 随机存取 | 碎片   | 动态增长 | 典型应用       |
| --------- | ---- | ---- | ---- | ---- | ---------- |
| 连续分配      | 优    | 可    | 外部碎片 | 困难   | 早期 OS      |
| 隐式链接      | 优    | 不可   | 无    | 容易   | 已淘汰        |
| 显式链接（FAT） | 优    | 不可   | 无    | 容易   | FAT32      |
| 单级索引      | 优    | 可    | 无    | 容易   | 部分 Unix    |
| 混合索引      | 优    | 不可   | 略    | 灵活   | Unix/Linux |

#### 文件操作与打开文件表

- **创建文件**：① 校验文件名合法性及目录写权限；② 分配空闲 inode/FCB，初始化元数据（类型、权限、时间戳等）；③ 分配磁盘块，地址记录到 inode；④ 在目录中新建目录项 <文件名, inode 号>；⑤ 更新空闲 inode 表、空闲块结构等元数据；⑥ 可选：创建后立即打开并返回文件描述符。

- **删除文件**：① 路径解析定位目录项，验证目录写权限；② 检查硬链接计数——若 count>1 则仅删除目录项、计数减 1 即完成（不回收 inode 与磁盘块）；若 count=1 才执行完整删除；③ 移除目录项（逻辑删除）；④ 释放 inode 回空闲池；⑤ 释放所有数据块和索引块；⑥ 释放缓冲区、文件对象等内存资源；⑦ 同步更新元数据。

- **读文件**：路径解析获取 inode → 根据读指针位置从外存数据块读取 → 更新读指针。

- **写文件**：路径解析获取 inode → 根据写指针位置写入数据块 → 更新写指针；若超出当前分配空间则动态分配新磁盘块并更新 inode 块指针。（这个才有写文件数据信息的情况，不考虑延迟写）

- **打开文件**：避免重复目录检索。过程：路径逐级遍历 → 提取 inode 号 → 查系统打开文件表（不存在则从磁盘读入创建新项，打开计数=1；存在则计数+1）→ 在进程打开文件表中分配新项指向系统表项 → 返回文件描述符。后续所有操作（read/write/lseek/close）均通过文件描述符完成，不再使用文件名。

- **关闭文件**：从进程打开文件表删除对应项 → 系统表项打开计数减 1 → 计数为 0 时删除系统表项并释放资源，将文件控制信息写回磁盘

- **两级打开文件表**：
	- **系统级（全局一张）**：存储与进程无关的文件属性（磁盘位置、大小、访问时间等），每项含打开计数器。
	- **进程级（每进程一张）**：存储进程私有状态（读/写指针、访问模式、权限），每项指向系统表项。多进程打开同一文件时，各自进程表项指向同一系统表项，实现资源共享与独立控制统一。
	- **每个打开文件关联的关键信息**：文件指针（进程私有，存进程表）、打开计数（系统表）、磁盘位置（缓存于内存）、访问权限（进程表）。

- **文件名 vs 文件描述符**：文件名仅用于 open 前的路径检索；一旦 open 成功返回文件描述符，后续所有操作均通过文件描述符索引进程打开文件表完成，不再使用文件名。

#### 文件共享与保护

- **硬链接**：多个目录项指向同一个 inode。inode 设链接计数 count，每增加一个硬链接 count+1，删除一个目录项 count-1，仅当 count=0 时回收文件。优点：共享文件不增加数据副本。缺点：不能跨文件系统，不能链接目录。
- **软链接（符号链接）**：创建一个特殊类型文件（链接文件），内容为指向目标文件的路径。系统访问时通过该路径重定向到目标文件。优点：可跨文件系统，可链接目录。缺点：存在"悬空链接"风险（目标被删除后链接失效）。
- **硬链接 vs 软链接对比**：

| 对比项 | 硬链接 | 软链接 |
| --- | --- | --- |
| 删除原文件 | 仍可通过链接访问 | 链接失效（悬空） |
| 跨文件系统 | 否 | 是 |
| 链接目录 | 否 | 是 |
| 实现方式 | 共享 inode | 存储路径字符串 |
| 空间开销 | 几乎为零 | 需额外 inode 和数据块 |

- **文件保护方法**：
	- **访问控制列表（ACL）**：为每个文件设 owner/group/other 三类用户的读/写/执行权限（如 Unix 的 rwx 位）。
	- **口令保护**：用户创建文件时设置口令，访问时需验证。简单但安全性较低。
	- **加密保护**：文件以密文形式存储，访问时需解密密钥。安全性高但加解密有性能开销。

#### 磁盘与内存布局

- **磁盘物理布局**（典型 Unix 文件系统）：
	- **MBR（主引导记录）**：磁盘 0 号扇区，包含引导代码和分区表。
	- **引导块**：每个分区的第一个块，包含该分区操作系统的引导程序。
	- **超级块**：记录整个文件系统的管理信息（磁盘块大小、总块数、空闲块数、inode 总数、空闲 inode 数等）。
	- **空闲块信息**：管理未分配磁盘块的数据结构（位示图或空闲链表等）。
	- **inode 区**：存放所有文件的 inode。
	- **根目录**：文件系统根目录的目录文件。

- **内存布局**（与文件系统相关的内核数据结构）：
	- **内存挂载表**：记录每个已挂载文件系统的信息（挂载点、超级块指针等）。
	- **内存 inode 缓冲区**：缓存最近访问的磁盘 inode。
	- **系统级打开文件表**：进程已打开文件的全局表。
	- **目录项缓存（dcache）**：缓存最近访问的目录项，加速路径解析。

#### 存储空间管理

- **空闲表法**：系统维护一张空闲盘块表，每个表项记录一个连续空闲区的起始块号和块数。分配采用首次适应/最佳适应/最坏适应等算法。回收时合并相邻空闲区。适用于连续分配方式。

- **空闲链表法**：
	- **空闲盘块链**：以盘块为单位组成链表，每次分配取头部若干块，释放时将回收块依次挂回。适合离散分配，但分配/释放操作频繁，链表较长。
	- **空闲盘区链**：以连续空闲区为单位组成链表（记录起始块号和长度）。分配和回收类似动态分区分配。链表节点少但管理较复杂。

- **位示图法**：用二进制位表示磁盘块的使用状态（0 空闲 / 1 已分配），位图连续存放在磁盘特定区域。分配时顺序查找为 0 的位并将位置 1；回收时将对应位置 0。适合各种分配方式。**优点**：占用空间小，可常驻内存，查找效率高。是 Linux ext 系列文件系统的默认方式。

- **成组链接法**（Unix 系统采用）：
	- 将空闲块分组管理，每组的空闲块号集中存放在前一组的最后一个空闲块中（形成链式结构），系统维护一个栈保存当前可用空闲块。
	- **分配**：从栈顶取出空闲块，若当前组分配完则从下一组继续。
	- **回收**：将回收块压入栈顶，栈满则新开一组。
	- **优势**：综合了空闲表法和空闲链表法的优点，分配回收速度快，内存消耗少。

#### VFS（虚拟文件系统）

- **定义**：为上层应用程序提供统一文件操作接口的抽象层，屏蔽底层不同文件系统（ext4、NTFS、FAT32 等）的实现差异。用户程序只需调用标准的系统调用（open、read、write），VFS 负责分发到具体文件系统的实现。

- **VFS 的四种核心对象**：
	1. **超级块对象**：代表一个已挂载的文件系统，包含该文件系统的控制信息（类型、大小、状态等）。
	2. **inode 对象**：代表一个具体文件，包含文件的元数据信息（权限、大小、操作函数指针等）。VFS inode 与磁盘 inode 可能不完全对应，需在 VFS 和具体文件系统之间转换。
	3. **目录项对象**：代表路径中的一个组成部分（目录或文件名）。用于加速路径解析，缓存目录与文件的对应关系。
	4. **文件对象**：代表一个已打开的文件。包含文件偏移、访问模式、指向目录项和 inode 的指针。文件对象与进程一一对应，通过文件描述符索引。

#### 文件系统挂载

- **挂载（mount）**：将一个文件系统连接到当前已存在的目录树中某个目录节点上，使该目录成为访问新文件系统的入口点（挂载点）。挂载后，对挂载点目录的访问将透明地映射到新文件系统的根目录。
- **挂载流程**：① 检查磁盘分区的文件系统有效性（如超级块）；② 在内存挂载表中找到空表项，记录文件系统信息；③ 将新文件系统的根目录与挂载点目录关联；④ 设置挂载标志，使后续路径跨越该挂载点时可跳转到新文件系统。
- **卸载（umount）**：断开挂载点与文件系统的关联，将内存中的脏数据写回磁盘。



## 相关概念问题

- 为什么 Unix/Linux 的 inode 将文件名与元数据分开？——支持硬链接，减小目录项大小，提高路径检索效率。
- 硬链接和软链接的本质区别是什么？——硬链接共享同一 inode，删除原文件不影响；软链接存储路径，删原文件后链接失效。
- 为什么 UNIX 13 地址项中前 10 个是直接地址？——大多数文件是小文件，直接地址可避免索引块开销，零次或一次间接即可覆盖绝大多数场景。
- 打开文件表为什么设计为两级？——实现进程级文件描述符与系统级打开文件的分离，支持多个进程共享同一个已打开文件，独立维护文件读写位置。
- 成组链接法相比位示图的优势？——成组链接法不要求连续的磁盘空间存放位图信息，适合大容量磁盘，分配和回收主要依赖内存栈操作，速度更快。
