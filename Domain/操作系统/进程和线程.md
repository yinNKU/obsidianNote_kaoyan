## 一句话定位

进程是资源分配和调度的基本单位，是程序的一次动态执行过程；线程是 CPU 调度和执行的基本单位，是进程内的轻量级执行流，用于进一步提升并发性能。

## 它解决什么问题？

引入进程解决多道程序并发执行带来的三大问题：失去封闭性（地址空间隔离恢复程序独立执行环境）、执行间断性（PCB 保存上下文实现中断后准确恢复）、结果不可再现性（隔离机制与调度策略保障执行可控性）。引入线程则降低并发执行的时空开销，使同一进程内可运行多个执行流，充分发挥多核处理器并行优势。

## 概念解析

#### 进程的概念

- **定义**：进程是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位。
	- 进程实体（进程映像）= 程序段 + 数据段 + PCB。创建进程的本质是创建 PCB，撤销进程即释放 PCB 及相关资源。
	- 核心内涵：进程必须是动态的、具有生命周期的过程性实体，而非静态的程序。
	- 典型定义：进程是正在执行的程序实例；是程序及其数据从外存加载到内存后在 CPU 上运行的过程；是具有独立功能的程序在一个特定数据集合上的执行活动。

#### 进程的特征

- **动态性**：进程是程序的一次执行实例，有明确生命周期（创建 $\rightarrow$ 就绪 $\rightarrow$ 运行 $\rightarrow$ 阻塞 $\rightarrow$ 终止）。动态性是最根本的特征。
- **并发性**：多个进程可同时驻留内存，在一段时间内交替或并行执行。引入进程的根本目的正是支持程序并发执行。
- **独立性**：进程是独立运行、独立获取系统资源、作为调度基本单位参与 CPU 竞争的实体。无 PCB 的程序不能被调度执行。
- **异步性**：进程相互制约，以不可预知的速度推进，可能导致执行结果不可再现，需要操作系统协调确保正确性。

#### 进程的组成（PCB）

- **PCB（进程控制块）**：进程存在的唯一标志，常驻内存，系统唯有通过它才能感知并管理进程。
	- **进程标识信息**：PID（唯一编号）、PPID（父进程标识符）、UID（所属用户），为资源共享与安全保护提供依据。
	- **进程调度信息**：当前状态、优先级、CPU 占用时间、等待时间、进入内存时间、阻塞原因，用于调度决策与状态管理。
	- **资源和内存信息**：代码段/数据段/堆栈段指针、文件描述符列表、I/O 资源清单，记录进程占用资源。
	- **处理机状态信息（CPU 上下文）**：通用寄存器值、程序计数器、栈指针（SP）、程序状态字（PSW），进程切换时保存到 PCB，恢复时重新载入 CPU。
	- **PCB 组织方式**：链接方式（相同状态 PCB 链成队列，如就绪队列、阻塞队列）；索引方式（为每种状态建立索引表，表项指向对应 PCB）。
- **程序段**：CPU 执行的代码部分，可被多个进程共享（如多个用户运行同一个编辑器，内存只保留一份代码副本）。
- **数据段**：进程运行所需的数据，每个进程数据段私有，保障进程间独立性与安全性。

#### 进程的内存映像

- **定义**：程序加载运行时操作系统建立的虚拟地址空间逻辑布局，反映进程运行时代码、数据、堆、栈等区域的组织方式。
	- **代码段**：存放编译后的机器指令，只读可共享。含 .init（初始化代码）、.text（主程序指令）、.rodata（只读数据如字符串常量）。
	- **数据段**：存放全局变量和静态变量。.data 存已初始化的全局/静态变量；.bss 存未初始化的全局/静态变量。
	- **PCB**：不属于进程虚拟地址空间，由内核维护存放在系统内核区，对用户进程不可见。
	- **堆**：运行时动态申请内存的区域（如 malloc/free），从低地址向高地址增长，大小不固定。
	- **栈**：支持函数调用（存局部变量、函数参数、返回地址），后进先出（LIFO），从高地址向低地址扩展，由系统自动管理。
	- **共享库存储映射区**：运行时动态映射的公共函数代码（如 printf），只读可多进程共享。
	- 代码段和数据段大小在加载时确定，堆和栈可在运行时动态扩展和收缩。

#### 进程的状态与转换

- **五种状态**：
	- **运行态**：进程正在 CPU 上执行。单 CPU 中任一时刻最多一个进程处于运行态。
	- **就绪态**：进程已获得除 CPU 外的所有必要资源，一旦获得 CPU 即可立即运行。多个就绪进程组织成就绪队列。
	- **阻塞态（等待态）**：进程因等待某一事件（资源可用、I/O 完成等）而暂停运行。即使 CPU 空闲也无法执行。据阻塞原因可分为多个子队列。
	- **创建态**：进程正在创建过程中，尚未进入就绪态。分配 PCB $\rightarrow$ 分配资源 $\rightarrow$ 转入就绪态。
	- **终止态**：进程已完成执行，正在等待系统回收资源。

- **状态转换**：
	- 就绪态 $\rightarrow$ 运行态：调度程序选中，获得 CPU 使用权。
	- 运行态 $\rightarrow$ 就绪态：时间片用完主动让出 CPU；或可剥夺调度中更高优先级进程就绪。
	- 运行态 $\rightarrow$ 阻塞态：进程发起的系统调用请求无法立即满足（如 I/O 操作），**主动**行为。
	- 阻塞态 $\rightarrow$ 就绪态：等待的事件发生（如 I/O 完成），中断处理程序将其修改为就绪态，**被动**行为。

- **就绪态 vs 阻塞态**：就绪态仅缺 CPU，获得即可运行；阻塞态缺其他资源或等待事件。就绪态切换频繁（时间片轮转），阻塞态频率远低。

#### 进程控制

- **进程的创建**：
	- 父子进程关系：父进程创建子进程，子进程复制父进程当前状态（程序代码、数据段、堆栈、文件描述符等），但拥有各自的 PCB 和虚拟地址空间，相互独立。
	- 触发创建的操作：用户登录、作业调度启动批处理、系统提供服务、用户程序发起应用请求。
	- 创建步骤：① 分配唯一标识并申请 PCB；② 分配运行所需资源；③ 初始化 PCB（标识信息、处理机状态、调度控制信息、内存资源信息）；④ 插入就绪队列。
- **进程的终止**：
	- 终止原因：正常结束、异常结束（越界/非法指令/特权违规/运算错误/I/O 故障/超时）、外界干预（操作员/OS/父进程请求）。
	- 终止步骤：① 检索 PCB 读取状态；② 若运行态则剥夺 CPU 并调度；③ 释放所有资源；④ 若支持级联终止则递归终止子孙进程；⑤ 移出队列并清理。
	- Linux 特性：父进程终止时子进程由 init 进程（PID=1）收养，继续正常运行。
- **进程的阻塞和唤醒**：
	- **阻塞原语（Block）**：运行态进程因等待事件主动调用，使自己进入阻塞态。
	- 阻塞步骤：① 保存 CPU 现场到 PCB；② 修改为阻塞态，插入等待队列；③ 调用调度程序选择新进程运行。
	- **唤醒原语（Wakeup）**：等待事件发生时由中断处理程序或合作进程调用，将阻塞进程重新激活。
	- 唤醒步骤：① 在等待队列中找到目标 PCB；② 移出等待队列，置为就绪态；③ 插入就绪队列。
	- Block 与 Wakeup 成对使用，缺一不可，否则进程永久阻塞。

#### 进程通信（IPC）

- **共享存储**：创建独立内存区域映射到多个进程的虚拟地址空间，进程直接读/写该区域交换信息。
	- 操作系统仅负责分配共享内存区并完成地址映射；同步互斥（如 P/V 操作）须由用户程序自行实现。
- **消息传递**：以格式化消息（Message）为单位，通过发送/接收原语进行通信。通信底层细节封装在内核中，对用户透明。
	- **直接通信**：发送原语指定接收进程，内核将消息从发送方复制到接收方的内核缓冲队列。
	- **间接通信**：通过中间实体（信箱）进行，发送方投递到信箱，接收方从信箱取出。
	- 微内核中内核与服务器的交互即基于消息传递；支持多处理器系统和分布式网络。
- **管道通信**：基于 FIFO 的 IPC 机制，常用于有亲缘关系的进程（如父子进程）以生产者-消费者模式交换数据。
	- 管道是内核维护的固定大小内存缓冲区（非磁盘文件），支持 read()/write() 操作。
	- 三方面协调：① 互斥（任一时刻只允许一个进程读或写，但是一个管道可以由多个进程操作）；② 同步（满则写阻塞，空则读阻塞）；③ 写端关闭检测（写端关闭后 read() 返回 0）。
	- Linux 管道特点：固定缓冲区大小（如 64KB）；自动阻塞与唤醒；一次性读操作（数据读出即释放）；单向通信（双向需两个管道）。
- **信号（Signal）**：用于通知进程某个事件已发生的机制，每类事件对应一个信号序号（Linux 约 30 种，编号 1~30）。
	- PCB 中用 n 位向量记录待处理信号（置 1 表示待处理）和阻塞信号（置 1 表示暂不处理）。
	- 发送方式：内核发送（检测到系统事件，如非法指令发 SIGILL）；进程发送（调用 kill() 函数向指定进程发信号）。
	- 处理时机：操作系统从内核态返回用户态时检查并处理待处理信号。
	- 处理方式：执行默认处理程序（如 SIGILL 默认终止进程）；执行自定义处理程序（进程可定义自己的信号处理函数）。

#### 线程的基本概念

- **定义**：线程是"轻量级进程"，是程序执行流的最小单元，也是 CPU 调度和执行的独立单位。
	- 线程不拥有独立系统资源（地址空间、打开的文件等），但拥有私有数据：线程 ID、程序计数器、寄存器集合和栈。
	- 同一进程内的所有线程共享该进程的代码段、数据段、堆、文件描述符等资源，线程间通信高效。
	- 引入线程后：进程是除 CPU 外的系统资源分配单位；线程是 CPU 调度和执行的基本单位。
	- 生命周期：创建 $\rightarrow$ 就绪 $\rightarrow$ 运行 $\rightarrow$ 阻塞 $\rightarrow$ 终止。三种基本状态：运行态、就绪态、阻塞态。
	- 线程切换（同一进程内）开销远小于进程切换（无须切换地址空间等资源）。

#### 线程与进程的比较

- **调度**：进程是资源拥有者，线程是独立调度基本单位。同一进程内线程切换不触发进程切换；不同进程线程切换仍触发进程切换。
- **并发性**：引入线程后，不仅进程间可并发，同一进程内多线程也可并发，多层次并发提升资源利用率。
- **拥有资源**：进程是资源分配基本单位；线程不拥有独立系统资源，仅拥有运行必需的私有数据结构。
- **独立性**：进程地址空间完全独立，其他进程无法直接访问；同一进程内线程共享地址空间紧密协作。
- **系统开销**：创建/撤销进程开销大（需分配 PCB、地址空间、I/O 资源）；创建/撤销线程仅分配栈和少量内核对象；进程切换涉及整个地址空间切换，线程切换仅保存/恢复寄存器状态。
- **多处理器支持**：单线程进程任一时刻只能在一个 CPU 执行；多线程进程的多个线程可同时调度到多个 CPU 并行执行。

#### 线程的控制与状态

- **TCB（线程控制块）**：系统为每个线程维护 TCB，记录管理信息。
	- 内容：线程标识符、寄存器集合（程序计数器、状态寄存器、通用寄存器）、当前状态、调度优先级、线程局部存储区、堆栈指针。
	- 同一进程所有线程共享地址空间和全局变量；每个线程有独立私有栈（位于进程地址空间内）。
- **生命周期**：初始线程创建其他线程 $\rightarrow$ 调度器决定哪个线程获得 CPU $\rightarrow$ 执行期间进行同步/互斥 $\rightarrow$ 终止。
	- 终止原因：正常执行完主函数、未处理异常、主动调用终止函数、被其他线程强制取消。
	- 终止后不立即释放资源，直至其他线程执行分离操作后方可回收。

#### 线程的实现方式

- **用户级线程（ULT）**：所有线程管理（创建/切换/撤销）在用户空间完成，无须操作系统介入，内核完全感知不到这些线程。
	- **优点**：线程切换在用户空间完成，无须切换到内核态；调度策略可由应用程序定制；与 OS 无关，可移植性好。
	- **缺点**：某线程执行阻塞型系统调用时整个进程被内核挂起；无法发挥多处理器并行优势（内核仅将该进程调度到一个 CPU）。
	- 调度仍以进程为单位，每个进程分得一个时间片，进程内多个用户级线程分享该时间片。
- **内核级线程（KLT）**：线程管理完全由操作系统内核负责，内核为每个线程维护 TCB 并感知其存在。
	- **优点**：能发挥多处理器并行优势（同一进程多线程可同时调度到不同 CPU）；阻塞处理灵活（某线程阻塞时内核可调度同一进程其他线程）；内核自身可采用多线程技术提升系统效率。
	- **缺点**：线程切换需从用户态陷入内核态，涉及模式转换和上下文保存/恢复，系统开销较大。
- **组合方式**：内核支持多个内核级线程的创建与调度，同时允许用户程序在用户空间管理多个用户级线程。结合两者优点：多 CPU 并行、单线程阻塞不挂起进程、用户级线程快速切换。

#### 多线程模型

- **多对一模型**：多个用户级线程映射到一个内核级线程。
	- 优点：线程管理在用户空间进行，切换效率高。缺点：任一用户线程执行阻塞系统调用时整个进程挂起；无法在多 CPU 上并行。
- **一对一模型**：每个用户级线程映射到一个独立的内核级线程。
	- 优点：某线程阻塞时内核可调度同一进程其他线程；支持真正并发，可在多 CPU 上并行。缺点：每创建一个用户线程就对应创建一个内核线程，系统开销大，限制最大线程数。
- **多对多模型**：n 个用户级线程映射到 m 个内核级线程（$n \ge m$）。
	- 用户级线程在用户空间调度，内核级线程由内核调度到多个 CPU 执行。兼具两者优点：用户级线程切换高效，支持多核并行与阻塞隔离。
- **线程库实现**：纯用户空间实现（对应 ULT，库调用仅触发本地过程调用）；内核支持实现（对应 KLT，库 API 触发系统调用）。
	- 主流线程库：POSIX Pthreads（可基于用户级或内核级）、Windows 线程 API（内核级）、Java 线程 API（通过调用宿主系统线程库实现）。
