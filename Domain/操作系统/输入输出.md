## 一句话定位

I/O 管理是操作系统对外部设备进行控制、调度和数据传输的机制集合，通过层次化的 I/O 软件、缓冲技术、设备分配策略和磁盘调度算法，屏蔽硬件差异，实现高效可靠的数据交换。

## 它解决什么问题？

外部设备种类繁多、速度差异大、操作方式各异，若缺乏统一管理，应用程序将难以直接使用设备。I/O 管理解决：① 屏蔽设备物理差异，提供统一编程接口；② 协调 CPU 与设备的速度不匹配（缓冲、SPOOLing）；③ 在多进程环境下合理分配与共享设备；④ 通过调度算法优化磁盘等设备的存取性能；⑤ 处理设备中断与错误，保证 I/O 操作的可靠性。

## 概念解析

#### I/O 设备分类

- **按信息交换单位**：
	- **块设备**：以数据块为单位，可寻址、支持随机访问，如磁盘。传输速率高，常用 DMA 方式。
	- **字符设备**：以字符为单位，不可寻址、顺序存取，如键盘、打印机。传输速率低，常用中断方式。
- **按传输速率**：低速（键盘/鼠标，B 级）、中速（激光打印机，KB 级）、高速（磁盘，MB 级）。
- **按共享属性**：
	- **独占设备**：一次仅一个进程使用（打印机）。
	- **共享设备**：多进程分时并发访问（磁盘），即一段时间允许多个进程同时访问。
		- 必须可寻址可随机访问
	- **虚拟设备**：通过 SPOOLing 将独占设备改造为多台逻辑设备。

#### I/O 接口（设备控制器）

- **组成**：① CPU 与控制器接口（数据/地址/控制线）；② 控制器与设备接口（数据/控制/状态）；③ I/O 逻辑（命令译码、设备识别）。
- **功能**：接收识别命令、数据交换、状态报告、地址识别、数据缓冲、差错控制。
- **I/O 端口编址**：
	- **独立编址**：I/O 端口与主存地址空间分离，用专用 I/O 指令（x86 的 IN/OUT）。优点：地址线少、译码快、指令清晰。缺点：指令功能有限、控制逻辑复杂。
	- **统一编址（内存映射）**：I/O 端口占用部分主存地址空间，用普通访存指令访问。优点：编程灵活、保护机制统一。缺点：占用主存地址空间、译码复杂。
- **设备绝对号**：系统为每个设备确定一个唯一编号

#### I/O 控制方式

- **程序直接控制（轮询）**：CPU 循环测试设备状态，直到数据就绪。CPU 与设备串行，利用率极低。
- **中断驱动**：设备完成操作后主动发送中断信号，CPU 响应中断处理数据。CPU 与设备可并行工作，但仍以字/节为单位经 CPU 寄存器传输，块设备效率低。
- **DMA 方式**：在设备与内存间建立直接数据通路。传送单位为块，数据不经 CPU，仅开始和结束时需 CPU 干预。DMA 控制器含四类寄存器：命令/状态寄存器 CR、内存地址寄存器 MAR、数据寄存器 DR、数据计数器 DC。
	- 分为预处理阶段和后处理阶段
	- 预处理阶段：是这个请求IO的进程在内核态执行相关操作，然后阻塞自身
	- 后处理阶段：是中断服务例程在执行，不是一个进程。
- **通道控制方式**：通道是专用处理机，一种特殊的硬件机制，执行存放在主存中的通道程序。CPU 仅发一条 I/O 指令，通道自主完成全部 I/O 操作。一个通道可管理多台设备，比 DMA 更灵活。


| 对比维度 | DMA 方式 | 通道控制方式 |
| --- | --- | --- |
| **本质** | **硬件控制器**（专用电路） | **专用处理机**（有指令集、可执行程序） |
| **参数设定** | CPU 预设：数据块大小、内存始址、方向等所有参数 | CPU 仅给一条指令 + 通道程序入口地址，参数由通道程序动态决定 |
| **灵活性** | 固定流程，无法处理复杂逻辑 | 可执行完整的通道程序，自主决策 |
| **可管理设备数** | 一个 DMA 控制器通常只服务**一台**设备 | 一个通道可同时管理**多台**设备 |
| **I/O 阶段处理** | 仅单一数据块传输 | 可处理多设备、多阶段的复杂 I/O 任务 |
| **与 CPU 并行度** | 传输期间 CPU 不可用总线（DMA 窃取周期） | 通道独立运行，CPU 几乎完全解放 |

#### I/O 软件层次结构（四层）

1. **用户层软件**：调用 I/O 库函数（如 printf/scanf），通过系统调用进入内核。
	- 通过逻辑设备名访问设备
	- 完成整数转ASCII的任务
2. **设备独立性软件**：执行公共操作——设备分配与回收、逻辑→物理设备名映射、缓冲管理、差错控制、提供统一逻辑块。实现设备无关性。
3. **设备驱动程序**：将抽象 I/O 请求转换为设备控制器能识别的具体指令，校验请求合法性、检查设备状态、传递参数、启动设备。
	- 每类设备需专用驱动程序，每类一个即可
4. **中断处理程序**：设备完成后发中断 → CPU 保护现场 → 识别中断源 → 处理中断（读数据/错误处理） → 恢复现场返回。
- **write 系统调用流程**：用户程序 printf → 陷阱指令陷入内核 → system_call 分派 → sys_write 公共操作 → 设备驱动程序发送命令 → 设备控制器执行 → 中断通知完成 → 唤醒进程 → 返回用户态。

#### I/O 操作举例（scanf 示例）

以 `scanf("%c", &d)` 从键盘输入字符存入变量 d 为例：

- **两个缓冲区概念**：内核缓冲区（内核空间，所有进程共享）与用户缓冲区（用户空间，C 标准库为 scanf 关联）。数据必须先复制到内核缓冲区，系统调用返回前再复制到用户缓冲区。
- **调用链**：用户进程 P 调用 scanf() → scanf() 调用系统调用封装函数 read() → 陷阱指令陷入内核 → 内核调出 sys_read() 系统调用服务例程 → 设备无关层处理 → 设备驱动层处理。
- **完整流程**：
	1. 检查 scanf 关联的用户缓冲区 buf，有数据则直接读取，为空则触发 read 系统调用；
	2. 执行 read 前传入三个参数——fd（标准输入文件描述符）、buf（用户缓冲区地址）、count（最大字节数）。
	3. 设备驱动程序对本次 I/O 进行初始化操作（设置参数等）。
	4. 驱动程序调用进程调度程序 scheduler()，**阻塞进程 P** 并调度其他进程执行。
	5. 用户通过键盘输入字符，送入键盘 I/O 接口的数据端口。
	6. 键盘 I/O 接口向 CPU 发出中断请求。
	7. CPU 响应中断，启动键盘中断处理程序，对 I/O 中断进行通用处理后，唤醒具体的键盘驱动程序。
	8. 驱动程序将字符从键盘控制器读入内核缓冲区（系统缓冲区）。
	9. 数据传输完成后，唤醒进程 P 并将其插入就绪队列。
	10. 中断返回，进程 P 再次获得 CPU 后从系统调用返回，scanf() 解析缓冲区字符，存入变量 d。
- **数据流向**：键盘 I/O 端口 → 内核缓冲区（设备驱动层完成）→ 用户缓冲区（设备无关层完成）。

#### 应用程序 I/O 接口

- **字符设备接口**：get/put 操作、in-control 指令。
- **块设备接口**：read/write/seek 命令，将二维物理地址映射为线性地址空间。
- **网络设备接口**：Socket（套接字）接口。
- **阻塞 I/O**：进程发起 I/O 后阻塞等待，直到操作完成。实现简单，CPU 利用率低。
- **非阻塞 I/O**：系统调用立即返回；进程轮询检查数据是否就绪。适合高并发，但轮询浪费 CPU。

#### 高速缓存与缓冲区

- **磁盘高速缓存**：用内存空间暂存磁盘数据的副本，减少重复读盘。两种形式：固定专用缓存区、动态缓冲池（与虚拟内存共享）。
- **缓冲区目的**：① 缓和 CPU 与 I/O 设备速度不匹配；② 减少中断频率；③ 解决数据粒度不匹配；④ 提高并行性。
- **单缓冲**：处理一块数据时间 = Max(T, C) + M。T=设备输入时间，M=传送至工作区时间，C=CPU 处理时间。
- **双缓冲**：处理一块数据时间 = Max(T, C + M)。可实现全双工通信（A 机发送缓冲区 ↔ B 机接收缓冲区）。
- **循环缓冲**：多个缓冲区组成循环队列，in/out 指针推进。in 追上 out = 计算限制（输入快），out 追上 in = I/O 限制（处理快）。
- **缓冲池**：系统管理的共享缓冲区集合，组织为空缓冲队列、输入队列、输出队列。四种工作方式：收容输入、提取输入、收容输出、提取输出。
- **高速缓存 vs 缓冲区**：缓存存放已存在于慢速设备上的数据副本（可长期驻留），缓冲区存放传输中的临时数据（传输完即释放）。

#### 设备分配与回收

- **数据结构**：
	- **DCT（设备控制表）**：每设备一张，含设备类型/标识符/状态/控制器指针/设备等待队列。
	- **COCT（控制器控制表）**：每控制器一张，含控制器状态/所辖设备/通道指针。
	- **CHCT（通道控制表）**：每通道一张，对应控制器信息。
	- **SDT（系统设备表）**：全局一张，索引所有设备。
- **分配步骤**：分配设备（DCT）→ 分配控制器（COCT）→ 分配通道（CHCT）。三者均成功才完成分配。
- **分配因素**：设备固有属性（独占/共享/虚拟）、分配算法（FCFS/优先级）、安全性（安全分配=I/O 后阻塞 vs 不安全分配=可继续请求）。
- **逻辑设备名→物理设备名映射**：通过 LUT（逻辑设备表）建立映射。可系统一张（单用户）或每用户一张（多用户）。

#### SPOOLing（假脱机技术）

- **思想**：用磁盘作为缓冲，以多道程序模拟脱机 I/O，将独占设备改造为共享虚拟设备。
- **组成**：① 输入井/输出井（磁盘区域）；② 输入缓冲/输出缓冲（内存区域）；③ 输入进程/输出进程；④ 井管理程序。
- **打印机 SPOOLing 示例**：用户进程将打印数据写入磁盘输出井 → 进程即认为完成 → 后台假脱机打印进程按队列顺序将数据送物理打印机。每个进程以为自己独占打印机。
- **特点**：提高 I/O 速度（将低速 I/O 转化为内存与磁盘的快速交换）；独占→共享；实现虚拟设备；以空间换时间。
#### 磁盘（Disk）

- **物理结构**：盘片表面涂有磁性物质，数据存储在同心圆磁道上，磁道划分为扇区（最小寻址单位，固定大小如1KB），相邻磁道/扇区间有间隙。
- **地址结构**：磁盘地址 = 柱面号 · 盘面号 · 扇区号。所有盘片上半径相同的磁道构成一个柱面；同一柱面内的磁头同步径向移动。
	- 由于寻道时间长，因此同一文件连续存放的优先级是：扇区->盘面->柱面
- **ZBR技术（区域记录）**：将盘面划分为若干环带，外层环带磁道扇区数多于内层，提高存储容量并充分利用外层磁道。
- **磁盘类型**：
	 - 固定头磁盘：每磁道一个固定磁头（位置固定）
	 - 活动头磁盘：磁头可径向移动（通过磁头臂定位）
	 - 固定盘磁盘：盘片永久密封不可拆卸
     - 可换盘磁盘：盘片可拆卸更换
	 - 温彻斯特磁盘（温盘）：活动磁头+固定盘片，现代机械硬盘雏形
- **读/写过程**：① 磁头臂移动至目标柱面；② 激活对应盘面磁头；③ 等待目标扇区旋转至磁头下方，执行读/写。

#### 磁盘的管理

**1. 磁盘初始化**
- **低级格式化（物理格式化）**：将空白盘划分为扇区，每个扇区包含头部（磁道号/磁头号/扇区号）、数据区域、尾部（CRC校验）。出厂时通常已完成。
- **分区**：将磁盘划分为逻辑区域（如C/D盘），起始位置和大小记录在MBR分区表中。
- **逻辑格式化（高级格式化）**：在分区上建立文件系统，初始化根目录，创建空闲/已分配空间的管理数据结构。
- **簇（块）**：多个连续扇区组合，是文件系统分配的最小单位。文件占用空间为簇的整数倍，即使文件为0字节也占用一整簇。
- 硬盘制造是按照物理格式化、分区、逻辑格式化的顺序制造的

**2. 引导块**
- **自举程序**：初始化CPU、寄存器、设备控制器和内存，加载并启动操作系统。
- **引导流程**：ROM中存放小型自举装入程序 → 读取磁盘固定位置的引导块 → 引导块加载操作系统内核并启动。
- **Windows示例**：MBR（第0号扇区）包含引导代码+分区表+标志位 → 读取活动分区的引导扇区 → 加载系统服务与驱动程序。

**3. 坏块**
- **简单磁盘（如IDE）**：操作系统在逻辑格式化时检测，在FAT表中标记坏扇区为不可用。
- **现代复杂磁盘**：控制器维护坏块列表，出厂时初始化并动态更新，通过备用扇区自动重映射（扇区备用），对操作系统透明。


#### 磁盘调度算法

**1. 磁盘存取时间组成**

| 时间成分          | 含义                      | 公式                                         |
| ------------- | ----------------------- | ------------------------------------------ |
| **寻道时间 Ts**   | 磁头移动到目标磁道的时间（对读写时间影响最大） | Ts = m·n + s（m：跨越每条磁道时间；n：跨越磁道数；s：磁头臂启动时间） |
| **旋转延迟时间 Tr** | 目标扇区旋转至磁头下方的平均等待时间      | Tr = 1/(2r)（r：磁盘每秒转数）                      |
| **数据传输时间 Tt** | 读/写 b 字节数据的时间           | Tt = b/(r·N)（N：每条磁道存储字节数）                  |
**总平均存取时间**：Ta = Ts + 1/(2r) + b/(r·N)

**2. 算法内容**
- **FCFS**：按请求顺序服务。公平，但平均寻道距离大。
- **SSTF**：每次选距离最近的请求。性能优于 FCFS，但可能饥饿。
- **SCAN（电梯调度）**：单向移动至端点后掉头，中途服务请求。
- **C-SCAN**：仅单向服务，回扫时快速移回起点不服务。
- **LOOK / C-LOOK**：SCAN/C-SCAN 的改进版，移动到最远请求即折返，不一定要到物理端点。现代实际系统通常指这两种。
- **NStepSCAN**：将请求队列划分为 N 个子队列，子队列内 SCAN，子队列间 FCFS。防止磁臂黏着。
- **FSCAN**：NStepSCAN 简化版，仅分两个队列（当前 SCAN + 新请求延后）。
- 磁臂黏着现象：SSTF、SCAN、C-SCAN有（不是很理解为啥）

| 算法 | 优点 | 缺点 |
| --- | --- | --- |
| FCFS | 公平简单 | 平均寻道距离大 |
| SSTF | 性能优于 FCFS | 可能饥饿 |
| SCAN | 性能好，无饥饿 | 两端请求响应慢 |
| C-SCAN | 消除两端不公平 | — |

#### 减少延迟时间的优化

- **交替编号**：同一盘面扇区不连续编号，留出间隔确保处理完当前扇区后下一目标扇区刚好到达，避免错过造成整圈等待。
- **错位命名**：不同盘面的扇区起始位置错开，确保处理完一盘面后下一盘面的目标扇区恰好到达磁头位置。
- **提高磁盘 I/O 速度的方法**：磁盘高速缓存、调度算法、提前读、延迟写（类似返回写）、优化物理块分布、虚拟盘（RAM 盘）、RAID。

#### 固态硬盘（SSD）

- **结构**：闪存芯片 + 闪存翻译层。读/写以页为单位，擦除以块为单位（擦除后整块才能重写）。
- **随机写入慢的原因**：① 擦除操作比页访问慢一个数量级；② 修改已有数据的页需先复制块中所有有效页到新块再写入。
- **磨损均衡**：动态磨损均衡（写入时选擦写次数少的空闲块）；静态磨损均衡（定期迁移数据使负载均衡）。显著延长 SSD 寿命。
- **机械磁盘 vs SSD**：SSD 无机械部件，随机访问延迟极低，无噪声/无振动/低功耗/抗震性强，但有擦写寿命限制。

## 相关概念问题

#### 设备驱动程序和中断服务例程

- **关系**：中断服务例程（ISR）包含在设备驱动程序之中。
- **注册机制**：ISR 不是被操作系统"扫描"到的，而是驱动程序**主动注册**的。驱动加载时，在 init/probe 函数中调用 `request_irq()`（Linux）或 `IoConnectInterrupt()`（Windows）向内核注册 ISR 函数地址。
- **操作系统角色**：只提供中断向量表这张"空白签到表"，负责在中断发生时查表跳转。
	1. **加载驱动**：OS 检测到硬件 → 匹配并加载驱动 → 调用驱动的 init/probe。
	2. **注册 ISR**：驱动执行 `request_irq()`，将中断号与 ISR 函数地址告知内核。
	3. **填写表项**：OS 检查中断号合法性后，将 ISR 地址填入中断向量表对应表项。
	4. **中断响应**：硬件触发中断 → CPU 查中断向量表 → 直接跳转至注册的 ISR 执行。
- **为什么不是"扫描"**：① 中断号是动态分配的（APIC 动态分配，非硬件固化）；② 支持共享中断（多个设备共享同一中断号时，由驱动注册时建立的链表依次调用各 ISR）。
