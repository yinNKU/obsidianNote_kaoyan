## 一句话定位

同步与互斥是协调并发进程中资源访问与执行次序的机制，确保多个进程在共享资源时正确、有序地推进，避免数据不一致与死锁。

## 它解决什么问题？

多道程序环境下进程并发执行，存在相互制约关系：同步解决协作进程间的执行次序问题（如加法必须在乘法之后），互斥解决多个进程竞争同一临界资源的独占访问问题，防止条件竞争和数据不一致。

## 主要概念

临界资源、临界区、同步、互斥、Peterson算法、TestAndSet、Swap、互斥锁、自旋锁、信号量、P操作、V操作、整型信号量、记录型信号量、生产者-消费者、读者-写者、哲学家进餐、管程、条件变量

> **缩写对照**
> - **PCB**：Process Control Block，进程控制块
> - **TS**：TestAndSet，测试并设置指令
> - **mutex**：Mutual Exclusion，互斥（信号量）
> - **P**：Proberen，荷兰语"尝试"，申请资源操作
> - **V**：Verhogen，荷兰语"增加"，释放资源操作

## 概念解析

#### 同步与互斥的基本概念

- **临界资源**：同一时刻仅允许一个进程访问的资源（如打印机、共享变量、数据结构等）。对临界资源的访问必须以互斥方式进行。
- **临界区**：进程中访问临界资源的那段代码。访问过程划分为四部分：
	- **进入区**：检查是否允许进入，设置"正在访问"标志。
	- **临界区**：实际访问临界资源的代码段，也称临界段。
	- **退出区**：清除"正在访问"标志，释放资源。
	- **剩余区**：其余代码。
- **同步（直接制约关系）**：两个或多个进程为协调运行次序而产生的等待或传递信息的制约关系，源于进程间的相互合作。
	- 例如：输入进程 A 通过单缓冲向进程 B 提供数据——缓冲区空时 B 阻塞，满时 A 阻塞。
- **互斥（间接制约关系）**：一个进程在临界区使用临界资源时，其他试图访问该资源的进程必须等待；只有当前进程退出后才允许进入。
- **同步机制准则**：
	- **空闲让进**：临界区空闲时，应允许一个请求进入的进程立即进入。
	- **忙则等待**：已有进程在临界区内时，其他进程必须等待。
	- **有限等待**：任何请求进程应在有限时间内进入临界区，避免无限等待。
	- **让权等待**：进程无法进入临界区时应主动放弃 CPU 转为阻塞态，避免忙等待（原则上应遵循，但非必须）。

#### 实现临界区互斥的基本方法

- **软件实现方法**：在进入区设置并检查标志，表明是否有进程在临界区中。

	- **单标志法**：设置公用整型变量 turn，指示允许进入的进程编号。进程退出时将 turn 转让给对方。
		- 缺点：必须交替进入，违背"空闲让进"——若某进程不再请求，另一进程也无法再进入。

	- **双标志先检查法**：设置布尔数组 `flag[]`。先检查对方标志，若对方不想进入则设置自己标志并进入。
		- 缺点：检查和设置非原子操作，可能同时进入（违背"忙则等待"）。如 P0 检查 `flag[1]=false`，切换至 P1 检查` flag[0]=false`，双方同时设标志并进入。

	- **双标志后检查法**：先设置自己标志，再检查对方标志。若对方也想进入则等待。
		- 缺点：双方同时设置后彼此等待，无法进入（违背"空闲让进""有限等待"），导致饥饿。

	- **Peterson 算法**：结合 `flag[] 和 turn`。先设 `flag[i]=true`，再设 `turn=j`（谦让），然后 `while(flag[j] && turn==j) `等待。
		```
		flag[i] = true;
		turn = j;
		while (flag[j] && turn == j);
		critical section;
		flag[i] = false;
		```
		- 满足"空闲让进""忙则等待""有限等待"三条准则，但采用忙等待未遵循"让权等待"。
		- 纯软件互斥算法中，满足前三准则最完善的方案。

软件算法对比：

| 算法 | 核心思想 | 违背准则 |
| --- | --- | --- |
| 单标志法 | turn 变量交替进入 | 空闲让进 |
| 双标志先检查 | 先检查对方 flag，后设自己 flag | 忙则等待 |
| 双标志后检查 | 先设自己 flag，后检查对方 flag | 空闲让进、有限等待 |
| Peterson | flag[] + turn 谦让 | 让权等待（忙等待） |

- **硬件实现方法**：通过原子操作检测和修改共享标志（视为"锁"）。

	- **中断屏蔽方法**：临界区前关中断，临界区后开中断。关中断期间不会被抢占。
		- 缺点：① 降低并发效率；② 用户进程关中断可能引发系统风险；③ 不适用于多处理器系统。

	- **TestAndSet（TS）指令**：原子操作——读取标志旧值并置为 true，返回旧值。
		```
		boolean TestAndSet(boolean *lock) {
		    boolean old = *lock;
		    *lock = true;
		    return old;
		}
		```
		- 使用：while(TestAndSet(&lock)); 忙等待获取锁；lock=false 释放锁。
		- 由硬件保证"检查锁"与"加锁"的原子性。适用于多处理器。缺点：忙等待，可能饥饿。

	- **Swap 指令**：原子交换两个变量的值。
		```
		void Swap(boolean *a, boolean *b) {
		    boolean temp = *a;
		    *a = *b;
		    *b = temp;
		}
		```
		- 使用：局部变量 key=true，循环 Swap(&lock, &key) 直到 key 变为 false。
		- 本质与 TS 相同。优缺点一致。

硬件方法对比：

| 方法 | 原子操作 | 适用多处理器 | 主要缺点 |
| --- | --- | --- | --- |
| 中断屏蔽 | 关/开中断 | 否 | 降低并发，系统风险，不适用多核 |
| TestAndSet | 读-改-写 | 是 | 忙等待，可能饥饿 |
| Swap | 交换 | 是 | 忙等待，可能饥饿 |

#### 互斥锁

- **定义**：解决临界区问题的最简单工具。包含布尔变量 available，通过 acquire() 和 release() 操作。
	- acquire()：若锁可用则获取并置为不可用；若不可用则忙等待。
	- release()：将锁置为可用。
	- acquire() 和 release() 必须是原子操作，通常由硬件机制实现。
- **自旋锁**：上述互斥锁即自旋锁，进程等待时连续循环（忙等待）。
	- 优点：适用于多处理器系统，等待期间无上下文切换；若持有锁时间短则代价较低。
	- 缺点：单 CPU 下浪费 CPU 周期。

#### 信号量

- **定义**：功能强大的同步机制，能解决互斥和同步问题。仅能通过两个标准原语访问：wait（P 操作）和 signal（V 操作）。原语不可中断。

- **整型信号量**：用一个整型变量 S 表示资源可用数量。
	```c
	wait(S) { while (S <= 0); S--; }
	signal(S) { S++; }
	```
	- 缺点：忙等待，未遵循"让权等待"准则。

- **记录型信号量**：包含整型 value（可用资源数）和进程链表 L（等待队列），通过 block/wakeup 实现"让权等待"。
	```c
	typedef struct {
	    int value;
	    struct process *L;
	} semaphore;

	void wait(semaphore S) {
	    S.value--;
	    if (S.value < 0) {
	        add this process to S.L;
	        block(S.L);
	    }
	}

	void signal(semaphore S) {
	    S.value++;
	    if (S.value <= 0) {
	        remove a process P from S.L;
	        wakeup(P);
	    }
	}
	```

- **利用信号量实现互斥**：设互斥信号量 S=1，临界区置于 P(S) 与 V(S) 之间。
	- S=1 表示均未进入；S=0 表示一个在临界区；S=-1 表示一个在临界区且一个在等待。
	- 不同临界资源应配置独立互斥信号量。P 与 V 必须成对出现。

- **利用信号量实现同步**：设同步信号量 S=0。前驱执行 V(S) 通知，后继执行 P(S) 等待。
	- 用法总结：提供资源的行为之后 V 该资源，使用资源的行为之前 P 该资源。互斥问题中 P、V 须紧夹临界区。

- **利用信号量实现前驱关系**：每条前驱边设置一个同步信号量（初值 0）。前驱段执行后 V 通知所有直接后继，后继段执行前 P 等待所有直接前驱完成。

- **分析步骤**：
	1. **关系分析**：识别并发进程及其关系（互斥/同步/前驱）。
	2. **思路梳理**：确定关键同步点，规划 P、V 操作位置。
	3. **信号量设置**：定义信号量，明确语义与初值，嵌入 P、V 操作，避免死锁与饥饿。

#### 经典同步问题

- **生产者-消费者问题**：一组生产者与一组消费者共享容量 n 的缓冲区。
	- 信号量：mutex=1（互斥缓冲区），empty=n（空缓冲区数），full=0（满缓冲区数）。
	```
	producer() {                           consumer() {
	    while(1) {                             while(1) {
	        生产一个产品                            P(full);
	        P(empty);                            P(mutex);
	        P(mutex);                            从缓冲区取出产品
	        放入缓冲区                             V(mutex);
	        V(mutex);                            V(empty);
	        V(full);                             消费产品
	    }                                    }
	}                                    }
	```
	- **关键**：P(empty/full) 必须在 P(mutex) 之前，否则可能导致死锁——若生产者先持 mutex 再等空位，消费者无法进入取产品，双方互相阻塞。

	- **复杂版本（爸爸-妈妈-儿子-女儿）**：盘容量 1，爸爸放苹果，妈妈放橘子，女儿吃苹果，儿子吃橘子。
		- 信号量：plate=1（互斥盘子），apple=0（盘中有苹果），orange=0（盘中有橘子）。
		- 爸爸：P(plate) → 放苹果 → V(apple)
		- 妈妈：P(plate) → 放橘子 → V(orange)
		- 女儿：P(apple) → 取苹果 → V(plate)
		- 儿子：P(orange) → 取橘子 → V(plate)

- **读者-写者问题**：多读者可并发读文件，写者需独占文件。允许多个读者同时读，但写者与其他所有进程互斥。
	- 信号量：rw=1（读写互斥），mutex=1（互斥 count），count 记录当前读者数。
	- **读者优先**：
		```
		writer() {                           reader() {
		    while(1) {                           while(1) {
		        P(rw);                              P(mutex);
		        写文件                                 if (count == 0) P(rw);
		        V(rw);                              count++;
		    }                                       V(mutex);
		}                                           读文件
		                                            P(mutex);
		                                            count--;
		                                            if (count == 0) V(rw);
		                                            V(mutex);
		                                        }
		                                    }
		```
		- 缺点：写者可能饥饿——读者持续到达时写者无限等待。
	- **写者优先**：引入信号量 w=1 阻止新读者在写者等待时进入。
		- 写者：P(w) → P(rw) → 写 → V(rw) → V(w)
		- 读者：P(w) → P(mutex) → 操作 count → V(mutex) → V(w) → 读
		- 本质是防止写者饥饿的有限优先，而非绝对写者优先。

- **哲学家进餐问题**：5 名哲学家围坐圆桌，5 根筷子各置于相邻哲学家之间。需同时持有左右两根筷子才能进餐。
	- 信号量：chopstick[5] = {1,1,1,1,1}，每人先拿左筷再拿右筷。
	- **死锁风险**：5 人同时拿左筷，全部等待右筷，形成循环等待死锁。
	- **解决方案**：
		1. 限制最多 4 人同时进餐。
		2. 奇数号先左后右，偶数号先右后左，打破循环等待条件。
		3. 引入互斥信号量 mutex=1，仅当左右筷均空闲时同时拿起。
		```
//方案1
void philosopher(int i) {
    while(1) {
        think();
        sem_wait(&max_diners);   // 申请入场名额，最多 n-1 人同时进入
        sem_wait(&forks[i]);     // 拿左边
        sem_wait(&forks[(i+1)%n]); // 拿右边
        eat();
        sem_post(&forks[i]);
        sem_post(&forks[(i+1)%n]);
        sem_post(&max_diners);   // 释放名额
    }
}
//方案3
		Pi() {
		    do {
		        P(mutex);
		        P(chopstick[i]);
		        P(chopstick[(i+1)%5]);
		        V(mutex);
		        进餐;
		        V(chopstick[i]);
		        V(chopstick[(i+1)%5]);
		        思考;
		    } while(1);
		}
		```

#### 管程

- **定义**：将共享数据结构及其操作封装在一起的管理程序，自动保证互斥访问，通过条件变量实现同步。由四部分组成：
	1. 管程名称。
	2. 局部于管程内部的共享数据结构说明。
	3. 对该数据结构进行操作的一组过程（函数）。
	4. 对共享数据进行初始化的语句。
- **特点**：
	- **封装性**：共享数据仅能被管程内部过程访问，外部进程必须通过调用过程才能访问资源。
	- **互斥性**：任一时刻仅一个进程执行管程内过程，自动保证互斥。
	- 管程是语法范畴，无法被创建和撤销
- **管程 vs 进程**：进程拥有私有数据结构（PCB），管程管理公共数据（缓冲区等）；进程是主动执行实体，管程是被动调用模块；多个进程可并发但同一管程调用互斥；进程有动态生命周期，管程是静态资源管理模块。
- **条件变量**：进程进入管程后因条件不满足而等待时释放管程。每个条件变量维护一个等待队列。
	- **x.wait()**：当前进程加入 x 的等待队列，释放管程，允许其他进程进入。[^1]
	- **x.signal()**：唤醒一个因等待条件 x 而阻塞的进程。（与V操作不同）
- **条件变量 vs 信号量**：条件变量不维护数值，仅用于排队和通知；资源数量由共享变量显式记录。条件变量的 wait/signal 与信号量的 P/V 在阻塞/唤醒功能上相似，但语义不同。

#### PV 操作解题方法（四步法）

- **万能四步法（解题骨架）**：

	- **第 1 步：找"谁"和"什么"**
		- **找进程**：题目里有几个主动的实体？（理发师、顾客、生产者、消费者……）
		- **找资源**：有哪些被争抢的东西？（椅子、缓冲区、打印机、理发椅……）

	- **第 2 步：分"互斥"和"同步"**
		- **互斥**：哪些资源同一时刻只能被一个人用？（理发椅、打印机）→ 互斥信号量，初值 1。
		- **同步**：哪些进程必须等另一个先做完才能做？（顾客等理发师、理发师等顾客）→ 同步信号量，初值 0。

	- **第 3 步：定信号量（名字 + 初值 + 含义）**
		- 对每个资源和每个约束定义一个信号量，想清楚：
			- 该信号量 > 0 代表什么？（有资源/有事件发生）
			- 该信号量 = 0 代表什么？（无资源/等待中）
			- 谁对它做 P（申请/等待）？谁对它做 V（释放/通知）？

	- **第 4 步：画流程 + 填 P/V**
		- 先画出每个进程的**自然流程**，再在关键节点插入：
			- **P(同步信号量)**：我要等某件事发生。
			- **V(同步信号量)**：我做完某件事，通知别人。
			- **P(互斥信号量)**：我要进临界区。
			- **V(互斥信号量)**：我出临界区。
		- 流程图可以是类似拓扑排序的图，每个节点表示一个事件，每条边表示信号量。

- **核心口诀**：
	> **互斥资源上锁（初值 1），同步等待用零（初值 0），缓冲计数用 N（初值 n），谁等谁 P 谁做 V。**

- **新题快速上手**：
	1. **读题圈关键词**："最多容纳 N 个"、"满了就走"、"必须等"、"唯一" → 信号量线索。
	2. **画简图**：进程 + 资源池，箭头表示谁等谁。
	3. **列信号量表**：填好初值和谁 P 谁 V。
	4. **先写伪代码骨架**，再填 P/V，最后检查死锁。

## 相关概念问题
#### 可重入
- 即**一段代码可以被多个“执行者”（比如多个任务、线程或中断程序）同时调用，而每个调用都能独立、正确地完成，不会互相干扰或破坏数据。**

[^1]: 一般会对于一个共享变量有判断之后决定是否wait
