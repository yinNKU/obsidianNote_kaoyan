## 一句话定位

操作系统结构设计决定了系统的模块化程度、性能、安全性和可维护性，核心架构包括分层法、模块化、宏内核、微内核和外核。

## 它解决什么问题？

在操作系统功能日益复杂、代码规模持续增长的背景下，合理的内核结构设计可降低系统复杂度、提升可靠性、安全性与可移植性，并决定系统在性能与模块化之间的权衡。

## 主要概念

分层法、模块化、内聚性、耦合度、宏内核、微内核、外核、库操作系统、虚拟机管理程序

> **缩写对照**
> - **BIOS**：Basic Input/Output System，基本输入/输出系统
> - **MBR**：Master Boot Record，主引导记录
> - **PBR**：Partition Boot Record，分区引导记录
> - **PCB**：Process Control Block，进程控制块
> - **POST**：Power-On Self-Test，通电自检
> - **GRUB**：GRand Unified Bootloader，多系统启动管理器
> - **XNU**：X is Not Unix，macOS/iOS 使用的混合内核

## 概念解析

#### 分层法

- **定义**：将 OS 划分为若干层次，最底层（层 0）为硬件，顶层（层 N）为用户接口，每层仅可调用紧邻下层功能（单向依赖）。
	- **优点**：便于调试与验证（自底向上逐层开发，某层错误可定位在该层内部，因所有依赖的下层已验证）；易于扩充与维护（层间接口不变可独立修改/替换/新增单层）。
	- **缺点**：层次划分困难（合理界定各层功能边界复杂，依赖关系固化后架构缺乏灵活性）；运行效率较低（高层功能需穿越多个中间层，参数传递与控制转移引入额外开销）。

#### 模块化

- **定义**：将 OS 按功能划分为若干独立模块，每个模块有明确定义的接口，可进一步细分子模块（模块-接口法）。
	- **内聚性**：模块内部各组成部分联系的紧密程度。内聚性越高，模块独立性越好。
	- **耦合度**：模块间相互依赖和影响的程度。耦合度越低，模块独立性越好。
	- 模块粒度：过小则单个模块简单但交互频繁增加整体复杂度；过大则内部结构复杂难维护。须在粒度大小间取得平衡。
	- **优点**：提高正确性/可理解性/可维护性；增强可适应性便于功能扩展；支持并行开发加速研制进程。
	- **缺点**：接口规定难满足实际需求；各模块齐头并进，无法建立在上一个已验证的正确决定基础上，无法找到可靠的决定顺序。

#### 宏内核

- **定义**：将系统主要功能模块集成在一个紧密耦合的整体中，全部运行于内核态，共享地址空间，可直接调用彼此函数。
	- **优点**：性能高（减少上下文切换和消息传递开销）。
	- **缺点**：代码规模膨胀后维护困难、可靠性下降，面临"软件危机"。
	- **发展现状**：主流 OS（Linux、Windows、Android）主要采用宏内核或混合内核架构，同时吸收微内核部分设计理念。
	- **混合内核示例**：macOS 和 iOS 的 XNU 内核融合了 Mach 微内核与 BSD 宏内核的特性。谷歌 Fuchsia 和华为 HarmonyOS NEXT 则采用微内核架构。
	- 宏内核与微内核并非对立，而是相互借鉴、融合发展。

#### 微内核

- **定义**：将操作系统中最基本的功能保留在内核态，其余非核心功能（文件系统、设备驱动等）移至用户态作为独立服务进程运行。
	- 系统分为两部分：**微内核**（极小程序，仅含核心机制，运行于内核态）+ **多个服务器**（在用户态实现具体功能）。
	- 交互方式：客户进程与服务器之间通过微内核提供的消息传递机制通信（客户/服务器模式）。
	- 可靠性提升：用户态服务器崩溃不影响整个系统（可重启恢复），而宏内核中内核态模块崩溃直接导致系统宕机。

- **基本功能**：遵循"机制与策略分离"设计原则。
	- **进程（线程）管理**：微内核提供创建/切换/调度队列管理等机制；进程分类、优先级分配等策略由用户态进程管理服务器实现。
	- **低级存储器管理**：微内核仅含地址转换机制（页表管理、逻辑地址到物理地址映射）；页面置换算法、内存分配策略由用户态存储器管理服务器实现。
	- **中断和陷入处理**：微内核捕获硬件中断和陷入，识别类型后分发给用户态服务器处理。

- **特点**（2023 考点）：
	- **优点**：扩展性和灵活性（新增/修改功能只需调整相应服务器，不动内核）；可靠性和安全性（用户态服务崩溃不导致系统崩溃，攻击面更小）；可移植性（仅微内核含硬件相关代码，其余服务器与平台无关）；分布式计算友好（消息传递通信易于扩展至网络环境）。
	- **缺点**：性能问题（每次服务请求需多次穿越内核态与用户态，系统调用延迟增加）。混合内核将高频服务移入内核以缓解此问题，但会使微内核容量明显增大。
	- **应用领域**：实时 OS、工业控制、航空航天、军事等高可靠性关键任务领域。

#### 外核

- **定义**：将物理资源直接暴露给用户级系统，自身仅负责资源的安全分配与隔离，是运行于内核态的极小程序。
	- 外核将硬件资源（磁盘块、内存页、网络缓冲区）划分为互不重叠的子集分配给不同用户级系统，通过权限检查防止越权。
	- 用户空间构建 **库操作系统（library OS）**，自主实现文件系统、进程调度、虚拟内存等传统 OS 功能，直接操作物理资源。
	- **优点**：减少抽象开销（避免不必要的数据拷贝/地址转换/上下文切换，无须经过传统内核强制性抽象层）；提升灵活性与性能（数据库可直接管理磁盘块，充分发挥硬件潜力）；清晰分离保护与实现（外核仅负责资源保护，功能实现完全置于用户空间，结构简洁易验证）。

#### 操作系统引导

- **定义**：计算机通过执行一系列引导程序，依次定位启动设备、确定可引导分区、加载操作系统内核，最终完成系统启动的链式过程（2021、2022 考点）。
- **7 个步骤**（2013 考点）：
	1. **CPU 激活与 BIOS 初始化**：通电后 CPU 从 ROM 读取并执行 BIOS，初始化基本硬件，建立中断向量表。
	2. **硬件自检与启动设备选择**：BIOS 执行 POST（通电自检），检测 CPU/内存/外设，依据 CMOS 设置选择首个有效启动设备。
	3. **加载主引导记录（MBR）**：BIOS 将启动设备首扇区（MBR，含引导代码 + 硬盘分区表）加载到内存。
	4. **定位活动分区并加载分区引导记录（PBR）**：MBR 引导代码解析分区表，识别标记为"活动"的分区，将其首扇区（PBR）加载到内存。
	5. **加载启动管理器**：PBR 代码加载活动分区内的启动管理器（如 Linux 的 GRUB、Windows 的 Bootmgr），提供多操作系统/内核版本选择界面。
	6. **加载操作系统内核**：启动管理器将选定的内核映像加载到内存并跳转执行，内核接管系统控制权，重建中断处理机制，不再依赖 BIOS。
	7. **内核初始化与用户环境启动**：内核初始化核心子系统（内存管理构建页表和地址空间框架；进程调度初始化 PCB 链表、就绪/阻塞队列；设备驱动建立设备控制块和 I/O 缓冲区），启动首个用户态进程（如 init），构建完整用户操作环境。

#### 虚拟机

- **定义**：通过虚拟化技术将一台物理计算机抽象为多台逻辑上独立的计算环境，每台虚拟机都是完整硬件系统的精确复制品（2025 考点）。
- **第一类虚拟机管理程序（裸金属架构）**：直接运行在物理硬件之上，是唯一处于最高特权级的软件。管理硬件资源和并发调度多台虚拟机，客户 OS 彼此完全隔离。
	- 客户 OS 运行于**虚拟内核态**，用户进程运行于真实的用户态。客户 OS 执行敏感指令时触发异常陷入管理程序。
	- 硬件虚拟化支持：支持时管理程序根据执行上下文判断指令来源（客户 OS 则代为完成，用户程序则模拟异常响应）；不支持时所有敏感指令被透明重定向到管理程序，由软件模拟实现。
- **第二类虚拟机管理程序（寄居架构）**：以应用程序形式运行在宿主 OS 之上，依赖宿主系统分配资源，本质是用户态进程（如 VMware Workstation）。向客户 OS 伪装成完整硬件平台。
	- 首次启动时模拟新计算机行为，客户 OS 安装到虚拟磁盘（宿主 OS 中的普通文件）中。
- **应用**：Web 主机领域——单台物理服务器同时运行多个虚拟机，每台用户可自定义 OS 和软件，成本显著低于独占托管。这是主流云服务器服务的基础。
