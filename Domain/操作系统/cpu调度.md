## 一句话定位

CPU 调度是按照一定算法从就绪队列中选择进程并分配 CPU 的机制，是多道程序系统的基础与核心设计问题。

## 它解决什么问题？

进程数量远超 CPU 个数，若等待当前进程执行完毕才切换，CPU 会因等待慢速 I/O 而大量空闲。CPU 调度在进程阻塞时及时切换给其他就绪进程，显著提高 CPU 利用率、系统吞吐量和响应速度。

## 主要概念

调度层次、进程调度、调度程序、上下文切换、调度算法、FCFS、SJF、HRRN、优先级调度、时间片轮转、多级队列、多级反馈队列、亲和性、负载平衡

> **缩写对照**
> - **FCFS**：First Come First Serve，先来先服务
> - **SJF**：Shortest Job First，短作业优先
> - **SPF**：Shortest Process First，短进程优先
> - **HRRN**：Highest Response Ratio Next，高响应比优先
> - **RR**：Round Robin，时间片轮转
> - **AMP**：Asymmetric MultiProcessing，非对称多处理机
> - **SMP**：Symmetric MultiProcessing，对称多处理机

## 概念解析

#### 调度的概念

- **定义**：按照一定算法从就绪队列中选择一个进程，将 CPU 分配给它运行，实现多个进程的并发执行。
- **高级调度（作业调度）**：从外存后备队列挑选作业，分配内存等资源并创建进程，插入就绪队列，使其获得参与 CPU 竞争的资格。每个作业仅被调入一次、调出一次。多道批处理系统配备，分时/实时系统一般不设。
- **中级调度（内存调度）**：内存紧张时将暂时无法运行的进程换出到外存（挂起态），条件满足时再换入内存恢复为就绪态。实质是存储器管理中的对换功能，用于提高内存利用率和系统吞吐量。
- **低级调度（进程调度）**：从就绪队列选择进程分配 CPU，最基础、最频繁，所有操作系统都必须存在。频率通常每几十毫秒执行一次。
- **三级调度关系**：作业调度为进程活动做准备（频率最低），中级调度动态调节内存活跃进程数（频率中等），进程调度驱动实际执行（频率最高）。

#### 进程调度的任务

- **任务三方面**：
	- 保存 CPU 现场：将当前进程的 CPU 状态（程序计数器、通用寄存器等）完整保存至其 PCB。
	- 选取待运行进程：依据算法从就绪队列选取进程，将其状态由就绪态改为运行态。
	- 完成 CPU 分配：由分派程序将新进程 PCB 中的 CPU 现场加载到处理器寄存器，移交控制权。
- **调度程序的组成**：
	- **排队器**：将所有就绪进程按策略组织成一个或多个就绪队列。
	- **分派器**：执行实际的 CPU 分配——移出目标进程、触发上下文切换、转交 CPU 控制权。
	- **上下文切换器**：执行两对切换——保存当前进程上下文 $\rightarrow$ 装入分派程序上下文；移出分派程序上下文 $\rightarrow$ 装入新进程 CPU 现场。

#### 调度的时机与方式

- **可调度的事件**：创建新进程后（父子进程选择运行）；进程正常/异常终止后；进程因 I/O 或信号量阻塞时；I/O 完成后就绪进程与当前进程抉择时；抢占系统中更高优先级进程就绪或时间片用完时。
- **不可调度的情况**：处理中断的过程中（逻辑复杂且不隶属于任何用户进程）；执行原子操作的过程中（如加锁/解锁、中断现场保护与恢复）。
- **非抢占调度方式**：当前进程让出 CPU 后才调度（运行完成或主动阻塞）。实现简单、系统开销小，适用于早期批处理系统，但无法满足分时/实时系统的响应要求。
- **抢占调度方式**：更高优先级进程就绪时立即剥夺当前进程 CPU。提高系统吞吐率和响应效率，需遵循优先级、短进程优先、时间片等原则。
- **闲逛进程（Idle Process）**：PID=0，优先级最低，仅在无其他就绪进程时运行，一旦有新进程就绪立即让出 CPU。
- **两种线程调度**：用户级线程调度以进程为单位，内核感知不到线程，线程切换开销极小但单线程阻塞会挂起整个进程；内核级线程调度以线程为单位，每个线程有独立内核上下文，可单独分配时间片，但切换开销高（涉及完整上下文切换、地址空间更新、TLB 刷新）。

#### 调度的目标

- **CPU 利用率**：CPU 有效工作时间 /（有效工作时间 + 空闲等待时间）。应尽可能保持 CPU"忙碌"。
- **系统吞吐量**：单位时间内完成的作业数量。短作业有助于提升吞吐量。
- **周转时间**：作业提交到完成的总时间。周转时间 = 作业完成时间 - 作业提交时间。平均周转时间 = 各作业周转时间之和 / n。带权周转时间 = 周转时间 / 实际运行时间。
- **等待时间**：进程在就绪队列中等待 CPU 的总时间。调度算法仅影响等待时间，不影响实际执行或 I/O 时间。
- **响应时间**：用户提交请求到系统首次产生响应的时间。交互式系统中比周转时间更具实际意义。
- 不存在一种调度算法能同时满足所有需求，需在场景要求与系统效率之间权衡。

#### 上下文切换与模式切换

- **上下文切换**：将 CPU 切换到另一个进程时，保存当前进程状态并恢复另一个进程状态。
	- 流程：挂起当前进程，将其 CPU 上下文保存到 PCB $\rightarrow$ PCB 移入相应队列 $\rightarrow$ 选择新进程并更新 PCB $\rightarrow$ 恢复新进程 CPU 上下文 $\rightarrow$ 跳转执行。
	- 消耗：需要大量 load/store 指令保存寄存器状态，高负载下累积消耗可观。部分处理器用多组寄存器切换指针来减少开销。
- **模式切换**：用户态和内核态之间的切换，发生在同一进程内部（如系统调用或中断），不涉及上下文切换。
- **调度 vs 切换**：调度是决策行为（决定将 CPU 分配给谁），切换是执行行为（实际完成 CPU 控制权转移）。

#### 先来先服务（FCFS）调度算法

- **定义**：按照作业/进程到达就绪队列的先后顺序进行调度，选择最早进入队列的进程运行，直到完成或阻塞才交出 CPU。
	- 非抢占式，实现最简单。
	- 对长作业有利，对短作业不利。长作业先到达时后续短作业需长时间等待。
	- 有利于 CPU 繁忙型作业，不利于 I/O 繁忙型作业（即使频繁让出 CPU 也无法及时获得）。
	- 常与其他策略结合使用（如同优先级进程间按 FCFS 调度）。


#### 短作业优先（SJF）调度算法

- **定义**：按照作业或进程的预计运行时间进行调度，选择估计运行时间最短的作业/进程优先执行。
	- 可用作非抢占式（默认）或抢占式（最短剩余时间优先，新进程估计运行时间比当前进程剩余时间更短时抢占）。
	- 所有作业同时到达且运行时间已知时，SJF 的**平均等待时间和平均周转时间是最优的**。
	- **缺点**：对长作业不利，可能产生饥饿现象（不断有短作业到达时长作业无限期等待）；未考虑作业紧迫程度；作业"长短"依赖用户估计值，可能被操纵。

#### 高响应比优先（HRRN）调度算法

- **定义**：综合平衡 FCFS 和 SJF，每次调度时计算每个作业的响应比，选择响应比最高的作业调入内存执行。
	- 响应比 = (等待时间 + 估计运行时间) / 估计运行时间。
	- 等待时间相同时有利于短作业（类似 SJF）；估计运行时间相同时由等待时间决定（体现 FCFS 公平性）；长作业等待时间足够长后响应比会提高，避免饥饿现象。
	- 主要用于作业调度，非抢占式。

#### 优先级调度算法

- **定义**：为每个作业或进程分配优先级，每次选择优先级最高的作业/进程进行调度。
	- **非抢占式**：当前进程运行完成或主动阻塞时才调度更高优先级进程。
	- **抢占式**：更高优先级进程就绪时立即剥夺当前进程 CPU。
	- **静态优先级**：创建时确定、运行期间不变。实现简单但不够灵活，低优先级进程可能饥饿。
	- **动态优先级**：随进程推进或等待时间增加而动态调整。如等待时间增长则提高优先级，使低优先级进程最终也能获得调度。
	- **优先级设置原则**：系统进程 > 用户进程；交互型进程 > 非交互型进程（前台 > 后台）；I/O 型进程 > 计算型进程（让 I/O 设备尽早开始工作，提高系统吞吐量）。

#### 时间片轮转（RR）调度算法

- **定义**：就绪进程按 FCFS 排成队列，每隔固定时间片产生时钟中断，将 CPU 分配给队首进程执行一个时间片，未完成则放回队尾等待下次调度。
	- 主要适用于分时系统，最大特点是公平性。
	- **时间片过大**：退化为 FCFS，无法满足短作业和交互式用户对快速响应的需求。
	- **时间片过小**：频繁进程调度和上下文切换，系统开销剧增，用户程序实际执行时间减少。
	- 时间片设置需综合考虑响应时间、就绪队列进程数量、系统处理能力。合理大小应略长于一次典型交互所需时间。

#### 多级队列调度算法

- **定义**：将就绪进程划分为多个独立队列，每个队列对应一类相似特性的进程，各队列可独立采用适合的调度算法。
	- 各队列具有不同优先级，调度时优先调度高优先级队列中的进程。
	- 如交互型队列用 RR 算法保证响应性，批处理队列用 FCFS 或 SJF 提高吞吐量。

#### 多级反馈队列调度算法

- **定义**：融合时间片轮转与优先级调度，通过动态调整进程所处的队列（优先级）和对应的时间片大小，兼顾多种系统目标。
	- 设置多个就绪队列，优先级从高到低依次降低；优先级越高的队列时间片越小（如第 $i+1$ 级是第 $i$ 级的 2 倍）。
	- 每个队列内部采用 RR 调度。新进程先放入第 1 级队列末尾；时间片内未完成则移至下一级队列末尾。最低优先级队列时间片较长，行为接近 FCFS。
	- 按队列优先级调度：仅当所有更高优先级队列为空时才调度低优先级队列。低优先级队列执行中有新进程进入时立即抢占。
	- **优势**：交互型进程（短且频繁 I/O）在高优先级队列快速完成；短批处理作业周转时间短；长批处理作业虽降至低优先级但不会饥饿。

#### 基于公平原则的调度算法

- **保证调度算法**：为每个进程提供可量化的 CPU 时间分配保证（如 n 个进程各得 1/n 的 CPU 时间）。调度器跟踪各进程实际 CPU 使用情况，选当前公平比率最小的进程运行。
- **公平分享调度算法**：保证每个用户获得相同的 CPU 时间，不论用户启动多少进程。按用户权重分配调度机会，实现用户层面的公平性。

常见调度算法对比：

| | 先来先服务 | 短作业优先 | 高响应比优先 | 时间片轮转 | 多级反馈队列 |
| --- | --- | --- | --- | --- | --- |
| 是否可抢占 | 否 | 可以 | 否 | 可以 | 队列内算法不一定 |
| 优点 | 公平，实现简单 | 平均等待/周转时间最优 | 兼顾长短作业 | 兼顾长短作业 | 兼顾长短作业，响应好，可行性强 |
| 缺点 | 不利于短作业 | 长作业饥饿，估计时间难确定 | 计算响应比开销大 | 平均等待时间长，上下文切换浪费 | 最复杂 |
| 适用于 | — | 批处理系统 | — | 分时系统 | 相当通用 |

#### 多处理机调度

- **处理器亲和性**：进程应尽量保持在同一个 CPU 上运行，避免因迁移导致缓存失效和重新填充的代价。
	- **软亲和**：调度程序尽量将进程保持在某个 CPU 上，但可迁移。
	- **硬亲和**：用户进程通过系统调用主动绑定到固定 CPU。
- **负载平衡**：尽量将负载平均分配到所有 CPU 上，避免部分 CPU 空闲而其他 CPU 高负载。但负载平衡通常与处理器亲和性冲突。
- **公共就绪队列**：所有 CPU 共享一个就绪队列。负载平衡好，但亲和性差（进程可能频繁在不同 CPU 间切换）。
- **私有就绪队列**：每个 CPU 有独立就绪队列。亲和性好，但需要负载平衡机制。
	- **推迁移**：特定系统程序周期检查各 CPU 负载，从超载 CPU 队列推出部分进程迁移到空闲 CPU。
	- **拉迁移**：低负载 CPU 主动从超载 CPU 队列拉取进程。
